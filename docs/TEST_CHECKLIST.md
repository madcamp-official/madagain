# 테스트 체크리스트

SPEC 5(안정성/예외) 및 6(일정)의 검증 항목을 실기기 기준으로 정리.

## 네트워크 전제 (매 테스트 전 확인) — SPEC 5.3

- [ ] 두 폰이 **동일 로컬망** 또는 **S24+ 모바일 핫스팟**에 연결됨 (S24+가 서버)
- [ ] AP의 client isolation(단말 간 통신 차단)이 꺼져 있음
- [ ] 두 앱의 포트 설정이 `NetworkConstants`와 일치
- [ ] 헤드셋 HUD에 **자신의 리슨 IP**가 표시됨 / 컨트롤러가 그 IP를 **자동 취득**(디스커버리→게이트웨이) 또는 수동 입력

## 1일차 — 최우선 마감 🔴

- [ ] **UDP Ping-Pong**: S10e → S24+ 패킷이 수신되고 시퀀스가 단조 증가
- [ ] Magic 불일치 패킷이 폐기됨
- [ ] Cardboard 스테레오 분할 렌더링이 실기기에서 정상

## 통신 안정성/예외 (SPEC 5)

**5.1 연결 끊김 감지 + 재연결**
- [ ] UDP **1초+ 미수신** 시 S24+ HUD 상단에 **빨간 경고 배너** 표시 (`WebSocketServerHost.LinkWarning`)
- [ ] 끊김 시 서버가 스테일 세션을 끊음 → 컨트롤러가 **WebSocket 재연결(지수 백오프)** 후 재페어링
- [ ] 재연결 시 스트리밍/RTT 자동 재개, HUD 경고 해제

**5.2 패킷 순서 역전/중복 폐기**
- [ ] 시퀀스 역전/중복 패킷 폐기(`SequenceValidator`) — 헤드셋 HUD의 "폐기" 카운트 증가로 확인
- [ ] 지터 버퍼가 타임스탬프 기준으로 정렬·보간

**5.4 지연시간 목표**
- [ ] **RTT 50ms 이내** (로컬 Wi-Fi/핫스팟) — 컨트롤러 HUD `RTT … (OK)` (`RttProbe.MeetsTarget`)

**연결 수립 (SPEC 2.3)**
- [ ] 컨트롤러가 헤드셋 IP **자동 취득**(게이트웨이/디스커버리)으로 페어링
- [ ] 자동 실패 시 컨트롤러 **IP 직접 입력** 폴백으로 연결 (SPEC 2.3-3)
- [ ] S24+ 핫스팟 환경에서 코드 변경 없이 동일 동작 (SPEC 2.3-4)

## 입력/보간

- [ ] **지터 버퍼**: 재생 지연만큼 뒤처진 시점에서 위치 Lerp / 회전 Slerp 보간 → 지터·유실에도 부드러움
- [ ] 지연/지터가 헤드셋 HUD에 표시(`지터버퍼: 지연 … ms, 지터 … ms`)
- [ ] 왼쪽 **플로팅 조이스틱** 이동값이 UDP로 전달되어 헤드셋 `move` 값 반영
- [ ] 오른쪽 **2x2 스와이프 패턴**이 완성 시 WebSocket으로 전달 → 판정 결과 수신
- [ ] **역할 분리**: 헤드트래킹은 S24+ 자체 센서, S10e 6DoF는 컨트롤러 입력 전용 (SPEC 5.5)

## 성능

- [ ] 패킷 유실 상황에서도 시각적 끊김이 허용 범위(지터 버퍼 지연 조정으로 튜닝)
