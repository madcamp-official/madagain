### 1.3 복원된 작업 흐름

```
씬에서 자세 잡기
  → PoseJsonTool        pose_<이름>.json 저장          (Tools/뷰모델/포즈 JSON)
  → anim_<이름>.json    몇 프레임에 어떤 이징으로 (손으로 작성)
  → ClipBuildTool       .anim 클립으로 굽기            (Tools/뷰모델/클립 빌드)
  → F3 / F4             Play 중 타이밍 조절
```

`anim_*.json` 형식:
```json
{ "clip": "Assets/.../Shell_Idle.anim", "frameRate": 60,
  "keys": [ {"frame":0, "pose":"shell_idle", "ease":"auto"},
            {"frame":8, "pose":"reach",      "ease":"flat"} ] }
```
이징: `auto`(부드럽게) / `flat`(정점에서 멈춤) / `linear`(급가속) / `step`(즉시).

### 1.4 등반 손 — `MantleRig` 전면 재작성

**핵심 결정: 뷰모델 루트를 건드리지 않는다.**

루트를 내려 숨기는 방식은 기각했다 — 어깨까지 내려가 등반 중 팔이 이상해지고, 루트는
`ViewmodelMotion`이 소유한다. 대신 `HandIK.weight`만 쓴다. HandIK가 이미
`Slerp(원래자세, IK해, weight)`로 블렌드하므로, 타깃을 **park**(화면 아래 대기점)에 두면:

- **0 → 1** = 손이 기본 자세에서 **아래로 내려가 사라짐**
- **1 → 0** = 손이 아래에서 **기본 자세로 올라옴**

6단계: `Idle → Lowering → Reaching → Holding → Releasing → Raising → Idle`.
진입 `내려감→올라옴`, 이탈 `내려감→올라옴`으로 대칭이고, **손이 안 보이는 바닥에서 시스템이 교대**하므로
팝이 원리적으로 없다.

**`AutoTraversal.StartFlight()`에 `_rig.Prepare()` 한 줄 추가**(사용자 승인). 이유:
`BeginPull()`에서 Show를 받으면 이미 몸이 올라가는 시점이라 손이 늦는다. 도약 경로는 비행
0.18~0.9초를 손 내리기에 쓴다. 벽 앞 바로 잡기는 여유가 구조적으로 0이라 `fastEntryTime`(0.12초)로 압축한다.

### 1.6 3인칭 전신 idle — `View/Body/BodyIdleMotion.cs`

`ViewmodelMotion` 방식(루트를 통째로 흔듦)은 **못 쓴다** — 전신에 적용하면 **발이 미끄러진다.**
`FingerPoser`처럼 **뼈 단위 additive**로 간다. 호흡(Spine02·목) / 체중 이동(Waist·Pelvis) /
팔 늘어짐. **발·다리는 안 건드린다.**

오른팔 진폭이 따로 있는 이유: §2.6에 셸 자세가 **"하늘색 생명줄을 손으로 꽉 쥔 자세"**로
규정돼 있어 오른손이 흔들리면 안 된다.

### 1.7 펫 거미 — `View/Body/SpiderRig.cs` + `SpiderLegs.cs`

**본에 붙이지 않는다.** 거미는 장식이 아니라 빙의 시 대상으로 날아가고 릴레이로 옮겨 다니며
줄이 그 엉덩이에서 나간다(§2.2·§2.6). 본 자식으로 묶으면 떨어져 나갈 수 없다.
→ **소프트 추종 제약**. 상태: `Perched / Launching / Attached / Returning`.

**다리 4개 IK는 방향이 반대다.** 손 IK는 몸이 고정이고 손끝이 목표를 좇지만, 여기서는
**발끝이 팔에 고정**이고 몸통이 움직인다. 몸통이 들썩이면 다리가 알아서 굽었다 펴진다.
`HandIK`를 재사용하지 않았다 — 인체 관절 제한(팔꿈치 과신전 금지, 어깨 원뿔, 손목 클램프)이
거미 다리엔 방해만 된다.

**엉덩이 조준**: 실이 나갈 때 `Shell` 마디**만** 돌려 방적돌기가 대상을 향하게 한다.
몸통 전체를 돌리면 다리에 붙들려 있어 뒤틀린다.

**점프·착지 웅크림은 사용자 지시로 제외**했다(구현했다가 뺐다).

`ControlTether`에 읽기 전용 속성 3개 추가(`Active`/`StartPoint`/`EndPoint`) + `originOverride` 필드.
**null이면 기존 동작 그대로**라 위험이 낮다. `HackDriver`는 건드리지 않았다.

## 2. 다음 세션이 할 일

### 2.1 지금 바로 — 1인칭 기본 자세 잡기 (사용자가 직접)

준비는 끝났다. 사용자가 손으로 잡겠다고 했다. **대신 잡아주지 말 것.**

손볼 곳:
```
Viewmodel          → Position / Rotation / Scale   (구도와 크기)
R_Clavicle → R_Upperarm → R_Forearm → R_Hand       (Rotation만!)
R_Hand의 FingerPoser                                (손가락 슬라이더)
[SpiderPerch]      → Position                       (거미 앉는 자리)
```

- **뼈에 Position을 쓰면 안 된다** — 뼈 길이가 바뀌어 팔이 늘어난다.
- 손가락 뼈를 직접 돌렸다면 `FingerPoser` 우클릭 → **`본 다시 찾기 + 기준 포즈 캡처`**.
  안 누르면 런타임에 슬라이더가 옛 기준으로 되돌린다.
- 다 잡으면 `Tools/뷰모델/포즈 JSON` → 이름 `fp_idle` → 저장.
- **작업 후 Main Camera near를 0.3으로 되돌릴 것.**

**사용자가 직접 해야 할 남은 준비 1건**: Game View 해상도 `1560×1440` 추가
(Game View 드롭다운 → `+` → Fixed Resolution). 내부 API가 막혀 코드로 못 넣었다.

### 2.1b ★ 자세는 FK 말고 **IK로** 잡는 게 맞다 — 앞선 안내를 정정한다

세션 중 사용자가 이 문제를 제기했다:

> "Local 선택으로 해서 손목 각도 돌릴 때, 왜 그 기준점이 자꾸 손목이 되는 거지"

**손목 뼈가 손목에서 도는 건 정상이다.** 관절은 자기 자신이 회전 중심이라 다른 점 기준으로 돌 수 없다.
문제는 그게 아니라 **"손을 화면의 저 위치로 옮기고 싶다"** 를 손목으로 하려던 것이다.
손목을 돌리면 손이 제자리에서 방향만 바뀐다. 옮기려면 위팔·아래팔을 돌려야 하고, 그러면
각도를 세 번씩 시행착오하게 된다.

참고로 Scene View 토글이 두 개이고 자주 혼동된다:

| 토글 | 정하는 것 |
|---|---|
| **Pivot / Center** | 기즈모가 **어디에** 놓이나 ← 기준점은 이쪽이다 |
| **Local / Global** | 기즈모 **축 방향** |

뼈 작업은 **`Pivot` + `Local`** 이 정답이다. Local은 축 방향만 바꾸지 기준점을 안 바꾼다.

**정정**: 이 세션 초반에 "HandIK weight는 0으로 두라"고 안내했는데 **과했다.**
그 조언은 등반 중 덮어쓰기를 걱정한 것이었으나, `MantleRig`는 `CaptureBaseWeights()`로 진입 전
weight를 기억했다가 `RestoreWeights()`로 되돌리도록 만들어져 있다.
**평상시 weight가 1이어도 등반과 충돌하지 않는다.**

권장 작업 방식:

1. `R_Hand`의 `HandIK` → **weight = 1**
2. `HandTarget_R`을 **이동**시켜 손 위치 결정 → 팔 전체가 따라온다
3. `HandTarget_R`을 **회전**시켜 손 방향 결정 (`matchRotation`이 켜져 있어 손목이 따라온다)
4. 팔꿈치가 이상하게 꺾이면 `ElbowPole_R`을 옮긴다 — 팔꿈치가 그쪽을 향한다
5. 왼손 동일

만질 게 **타깃 2개 + 폴 2개**로 줄어든다. 뼈를 직접 돌릴 일이 거의 없어진다.

손가락엔 IK가 없으므로 `FingerPoser` 슬라이더 + 필요시 손가락 뼈 직접 회전(이건 관절이 곧
기준점인 게 맞는 상황이다).

**저장은 그대로 된다.** `PoseJsonTool`의 `FullTrsNames`에 `HandTarget_R/L`·`ElbowPole_R/L`이
들어 있어 뼈 회전과 타깃 위치를 **둘 다** 저장한다. IK로 잡든 FK로 잡든 복원된다.

> 주의: `PoseJsonTool`의 **불러오기**는 IK를 자동으로 끈다(원본 Precog가 FK 전제였다).
> 저장된 뼈 회전이 IK가 풀어놓은 결과라 시각적으로는 같은 자세가 나오지만,
> 이어서 또 IK로 조정하려면 weight를 다시 1로 올려야 한다.

### 2.2 자세가 나온 뒤

1. `MantleRig.parkLocalR/L` — 손이 내려가 **화면 밖으로 나가는** 위치. 잡은 구도 기준으로 맞춘다.
2. `MantleRig.handEulerR/L` — 리그 손 뼈 축 보정. 등반 실행하며 기즈모 보고.

5. 3인칭 셸 포즈 — §2.6의 "생명줄 쥔 자세"를 잡아 `pose_shell_idle.json`으로 저장.

노란 구 = park, 청록 = 모서리 앵커, 초록/빨강 = 손 기저 축, 연두 = 다리 앵커.

## 4. 함정 — 다음 세션이 반드시 알아야 할 것

### 4.1 ★ Unity가 새 .cs를 **에러 없이** 컴파일에서 누락한다

이번에 두 번 겪었다(`PoseJsonTool.cs`, `SpiderLegs.cs`). 증상:

- 다른 파일에서 `CS0103: The name 'X' does not exist in the current context`
- 정작 그 파일 자체는 **에러가 하나도 없다**
- 파일·`.meta`·내용 전부 정상, `AssetDatabase.LoadAssetAtPath<MonoScript>()`가 **null**

`ImportAsset(ForceUpdate)`도, `.meta` 삭제도 안 먹혔다(같은 GUID를 재사용한다).

**해결 순서** — 이대로 하면 낫는다:
```
1. 파일 내용 백업
2. .cs 와 .cs.meta 둘 다 삭제
3. refresh_unity (force / all)
4. 파일 재생성
5. refresh_unity (force / all)
```

새 스크립트를 만든 뒤 `CS0103`이 뜨면 **문법을 의심하지 말고 이걸 먼저 하라.** 시간을 크게 아낀다.

### 4.2 `execute_code`는 C# 6 (CodeDom)

- **로컬 함수 불가** (C# 7). 배열+루프로 풀어 쓸 것.
- 메서드 본문이라 `using` 지시문 불가. `UnityEditor.SceneManagement.EditorSceneManager` 식으로 전체 경로.
- 튜플 리터럴 불가.
- `using System;`을 쓰면 `Object`가 모호해진다 → `UnityEngine.Object`로 명시.

### 4.3 병렬 세션과 Unity 인스턴스를 공유한다

씬을 열기 **전에 반드시** 확인할 것:
```csharp
var sc = SceneManager.GetActiveScene();
return new { sc.path, sc.isDirty, Application.isPlaying };
```
- `isPlaying`이면 씬을 바꾸지 말 것 — 그쪽 플레이가 끊긴다.
- `isDirty`면 저장 안 된 그쪽 작업이 날아간다.

실제로 이 세션에서 Protag GameObject가 저장 전에 사라진 적이 있다. **배치하면 즉시 저장하라.**

### 4.4 `PlayerBodyModeController`가 루트를 원점으로 리셋하던 버그 (고침)

1인칭 진입 시 `localPosition = Vector3.zero`로 덮고 있었다. 그대로 뒀으면 **자세를 잡아도 Play
누르는 순간 날아간다.** 지금은 `firstPersonLocalPos`/`firstPersonLocalEuler`에 씬 값을 기록해 쓴다.

⚠️ **한 번 채워지면 그게 정본이다.** 자세를 다시 잡으면 그 두 필드를 비우거나 새 값으로 갱신할 것.

### 4.5 거미는 `[SpiderPerch]`의 자식이다 — 일부러 그렇게 했다

`SpiderRig`는 월드 좌표 추종이라 부모가 필요 없지만, **`Viewmodel` 루트 스케일을 바꿀 때
거미와 다리 앵커가 같이 따라오게** 하려고 자식으로 붙였다. 런타임에는 어차피 매 프레임
월드 위치를 덮어쓰므로 무해하다.
