# OneBit — 계조 축소 · 디더 재질

> 대상: `Assets/_Project/Shaders/OneBit.shader` · `View/Art/OneBitControl.cs` · `Editor/OneBitSwapTool.cs`
> 상태: **1차 값 확정(손·거미).** 다른 대상에 재사용 가능.
> 관련: [흑백_아트_계획.md](흑백_아트_계획.md) · [기초_설계안.md](기초_설계안.md) §7(시각 언어)

---

## 1. 무엇인가

**명암을 몇 단계로 끊고, 계단 경계를 점 패턴(디더)으로 흩는 재질.**

화면 전체 흑백은 후처리(채도 −100)가 담당한다. 이 셰이더는 그 **위에서 특정 대상만** 불연속으로
만들어 배경과 분리한다. 처음엔 "손·거미를 1비트(순수 흑백 2치)로"가 목적이었으나, 실제로 써 보니
**계단 수를 늘리고 디더를 최대로 건 쪽**이 훨씬 좋았다(§4).

이름이 `OneBit`인 것은 최초 목적의 잔재다. **머티리얼 127개에 이미 물려 있어 이름을 바꾸지 않는다** —
바꾸면 전부 다시 교체해야 한다.

## 2. 파이프라인

```
albedo × (환경광 + 메인라이트 · ndl · 그림자)      ← 조명은 '형태'를 위한 것이지 색을 위한 게 아니다
      ↓ 휘도 (0.2126, 0.7152, 0.0722)
      ↓ 입력 범위 remap   t = saturate((lum − inBlack) / (inWhite − inBlack))
      ↓ 디더            t += (Bayer4x4 − 0.5) · dither / (levels−1)
      ↓ 계조 축소        q = round(t · (levels−1)) / (levels−1)
      ↓ 반전            q = invert ? 1−q : q
   출력 (q, q, q, 1)
```

**순서가 중요하다.** remap이 디더·양자화보다 **먼저**여야 한다. 어두운 재질은 휘도가 바닥에 몰려
있어서, 펼치기 전에 자르면 계단이 하나도 안 생긴다(§6-1).

**디더는 계단 하나 폭만큼만 흔든다**(`/ (levels−1)`). 그래서 톤이 뭉개지지 않고 경계만 섞인다.

**라이트 랩**: `ndl = saturate((dot(N,L) + wrap) / (1 + wrap))`. 어두운 면이 통째로 검게 죽는 것을
막아 형태를 살린다. 1이면 완전 랩(반구 전체가 밝기를 가짐).

## 3. 파라미터

| 이름 | 역할 | 감각 |
|---|---|---|
| `levels` | 계단 수 (2~8) | **2 = 순수 흑백 2치**, 클수록 부드럽다 |
| `inBlack` | 입력 검정점 | 올리면 어두운 쪽이 뭉쳐 검게 눌린다 |
| **`inWhite`** | 입력 흰색점 | ★ **어두운 재질에서 가장 중요.** 내릴수록 어두운 구간이 펼쳐진다 |
| `invert` | 흑백 뒤집기 | 대상에만 걸린다(배경은 후처리 흑백 그대로) |
| `dither` | 계단 경계 흩기 | 0 = 딱 떨어지는 밴딩, 1 = 점 패턴 |
| `lightWrap` | 형태 유지 | 조명이 약하거나 없으면 올린다 |

**값은 전역 셰이더 프로퍼티**(`_OneBit*`)로 구동한다. 머티리얼이 100개가 넘어 개별 조절이
불가능하기 때문. `OneBitControl` 하나가 전부를 움직인다. 개별 재질을 따로 쓰고 싶으면
그 머티리얼의 `_UseGlobal`을 0으로 두면 자기 값으로 돈다.

## 4. 확정값 — 손·거미 (ViewmodelStudio, 2026-07-29)

```
levels    = 8
inBlack   = 0
inWhite   = 0.5
invert    = false      ← 반전은 결국 안 쓰기로
dither    = 1          ← 최대
lightWrap = 1          ← 최대
```

**해석**: 계단을 최대로 잘게(8) 두고 디더를 최대로 걸면, 결과적으로 **하프톤 점묘**에 가까워진다.
"조금만 불연속"이라는 요구가 밴딩이 아니라 **점의 밀도 변화**로 실현된 셈이다.

> ⚠️ **이 값은 현재 조명 환경에 묶여 있다.** ViewmodelStudio는 `ambientMode = Flat`, ambient 0.212
> 무채색이고 **라이트가 하나도 없다.** 즉 `dot(N,L)` 성분이 사실상 죽어 있고, 형태는 **albedo
> 텍스처의 명암에서만** 나온다. `lightWrap 1`이 최적으로 나온 것도 그 때문이다.
> **조명이 있는 씬으로 옮기면 `inWhite`·`lightWrap`을 다시 잡아야 한다.**

## 5. 쓰는 법

### 적용
Project 창 또는 Hierarchy에서 대상을 선택 → **`Tools/흑백/1비트 — 선택 오브젝트에 적용`**
(GameObject를 선택하면 하위 렌더러의 머티리얼을 전부 훑는다. 꺼둔 파츠도 포함한다.)

### 복구
**`Tools/흑백/1비트 — 원래 셰이더로 복구`**
원래 셰이더 이름을 **프로젝트 루트 `onebit_restore.json`** 에 기록해 둔다. 텍스처·색 등 다른
프로퍼티는 건드리지 않으므로 셰이더만 되돌리면 원상복구다.

> 기록 파일을 **Assets 밖**에 두는 이유: 안에 두면 에셋으로 임포트돼 프로젝트 창을 어지럽힌다.

### 조절
씬에 `OneBitControl` 컴포넌트 하나(`[OneBit]`). **`[ExecuteAlways]`라 Play 없이 씬 뷰에서 바로**
반영된다. Play 중엔 씬에 없어도 자동 생성된다.

### 다른 대상에 재사용할 때 — 튜닝 순서
1. **`inWhite`를 먼저.** 계단이 안 보이면 십중팔구 이 값이다. 어두운 재질일수록 낮춘다.
2. `levels` — 딱딱하게 원하면 2~3, 점묘처럼 원하면 6~8.
3. `dither` — 밴딩이 거슬리면 올린다.
4. `lightWrap` — 한쪽 면이 통째로 죽으면 올린다.
5. `inBlack` — 검은 쪽을 더 눌러야 할 때만.

## 6. 함정 (겪은 것)

1. **처음에 팔 전체가 흰색이 됐다.** 팔 albedo가 거의 검정이라 휘도가 임계값 아래로 전부 몰렸고,
   2치라 중간이 없어 통째로 0 → 반전되어 전부 1. **어두운 재질은 자르기 전에 펼쳐야 한다**는 것을
   이 사고로 알았다. → `inWhite` 도입.
2. **전역 프로퍼티는 `CBUFFER_START(UnityPerMaterial)` 밖에 선언해야 한다.** 안에 넣으면
   SRP Batcher와 싸운다.
3. **fbx 내장 머티리얼은 못 바꾼다** — 읽기 전용이다. 교체 툴이 건너뛰고 이름을 알려준다.
   임포터에서 `Materials → Extract Materials` 후 다시 실행해야 한다.
4. **Undo로 되돌려도 복구 JSON은 안 지워진다.** 툴로 적용한 뒤 Ctrl+Z로 되돌리면 머티리얼은
   원래 셰이더인데 기록 파일은 남는다. 다시 적용할 때 현재 셰이더를 원본으로 덮어쓰지 않도록
   **적용 전에 현재 셰이더를 확인**하는 편이 안전하다.
5. **텍스처가 그대로 붙는 이유**는 `_BaseMap`/`_BaseColor` 이름을 URP Lit과 맞춰 뒀기 때문이다.
   이름을 바꾸면 교체 순간 전부 흰색이 된다.

## 7. 미검증 · 미결

| 항목 | 내용 |
|---|---|
| **VR 스테레오에서 디더** | 디더가 **화면 좌표** 기준이라 **양안이 서로 다른 점 패턴**을 본다. 깊이 인지에 충돌을 일으키거나 어른거릴 수 있다. 문제가 되면 **오브젝트/UV 공간 디더**로 바꿔야 한다 — 실기 확인 필요 |
| **머리 움직임 시 크롤링** | 화면 공간 디더는 카메라가 움직이면 패턴이 표면을 기어다닌다. 위와 같은 대책 |
| **모바일 성능** | 픽셀당 연산은 가볍다(fbm 없음). 다만 `UsePass`로 ShadowCaster·DepthOnly를 빌려 쓰므로 그림자 비용은 URP Lit과 동일 |
| **조명 있는 씬** | §4 값은 라이트 없는 스튜디오 기준. 실제 스테이지에서 재조정 필요 |
| **§7 시각 언어와의 관계** | 기초_설계안 §7은 `초록 = 해킹 / 빨강 = 위험` 2색을 규정한다. "전부 흑백" 방침이 이걸 폐기한 것인지 **아직 확답을 못 받았다.** 폐기라면 위험 표시를 **테두리 두께·글리치 속도·점 밀도** 같은 다른 채널로 옮겨야 한다 |

## 8. 재사용 후보

계조 축소는 대상을 배경에서 떼어내는 수단이라, **"이건 다른 층위의 것"** 을 알릴 곳에 쓸 수 있다.

- **해킹 대상 하이라이트** — 초록 대신(또는 함께) 계단 수를 줄여 이질감을 준다
- **빙의 중 남겨진 셸** — 내 몸이 아니라는 표시
- **보스 파괴 연출** — 파편만 계조를 낮춰 실루엣으로
- **UI·패턴 격자** — 이미 흑백이므로 디더만 얹어 톤을 맞춘다
