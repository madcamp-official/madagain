# MINDHEXER 기초 설계안 (KJH 초안)

> KJH 개인 문서. 상태: **초안**. shared 승격 전.
> 팀원(SYB) 통신 스캐폴드(`docs/SYB/SPEC.md` v3)와 정합이 필요한 항목은 §5·§9에 명시한다.
> 수치는 전부 **출발점**이며 실측·튜닝 대상이다.

## 0. 게임 정의와 컨셉

> 폰 2대(S24+ 카드보드 HMD + S10e 컨트롤러)로 하는 **VR 침투 해킹 퍼즐 게임.**
> **컨트롤러(폰)로 공장 안의 기계·지형지물을 해킹·조종해, 없던 길을 만들어 목표 지점에 도달하는 것이 게임의 본체다.**

### 0.1 무대와 목표

초거대 로봇을 연구·생산하는 공장. 주인공은 침투해 **공장을 무력화**한다.

### 0.2 흐름 — 4막 구조

- **1막 (잠입 퍼즐)**: 초거대 로봇 공장에 침투. 해킹으로 지형지물을 조종하고 경비병에 빙의하며 퍼즐을 풀어 **최종 제어실**에 도달한다. **메인은 3D 맵 공간 조작 퍼즐**.
- **2막 (각성 · 1차 추격)**: 제어실에서 무력화에 성공한 듯하나, 눈앞의 초거대 로봇(원본: 구형 머리·눈 들어감)이 **각성**해 관제실 유리를 부수고 추격한다. (제어실=전신, 추격 중=좁아서 상체만.) 왔던 길을 되돌아가 **초거대 유압프레스로 1차 압사** → 머리가 눌리고 눈알이 튀어나와 **넙죽이 형태**가 된다.
- **3막 (복귀 퍼즐)**: 무력화한 줄 알고 다시 퍼즐을 풀며 원래 지점(탈출구)으로 돌아간다.
- **4막 (반전 · 2차 추격 · 최후)**: 탈출 직전, **넙죽이가 되돌아가던 길의 옆벽을 부수며 등장**해 거대 구조물을 던진다. **컷신으로 자동 회피**, 구조물이 반대편 벽을 부숴 **새 길이 열리고** 그 길로 도주한다. 끝에서 **초초거대 유압프레스로 다시 찍어 완전히 찌부(사망)** → 공장을 나오며 엔딩.

> 보스의 단계적 파괴(눈알 고어 팝 → 넙죽이화 → 완전 찌부)가 핵심 볼거리 → §11. 2·4막 파괴 연출 → §12.

### 0.4 실제 진행 시나리오 (2026-07-31 확정)

§0.2가 서사 구조라면, 여기는 **플레이어가 실제로 하는 것의 순서**다. 구현은 이쪽을 따른다.

**전반부 — 프레스는 문이다**

| 순서 | 내용 |
| --- | --- |
| 1 | **1스테이지 입구가 내려온 유압프레스로 막혀 있다.** 이것을 **첫 해킹**으로 들어올려 입장한다 |
| 2 | 1스테이지 클리어 |
| 3 | 2스테이지 입구의 내려온 프레스를 들어올려 입장 → 클리어 |
| 4 | 3스테이지 입구의 내려온 프레스를 들어올려 입장 → 클리어 |

> **첫 해킹 = 1스테이지 입구 프레스.** 게임이 가르치는 첫 동작이 곧 첫 관문이다.

**전환점**

3스테이지 클리어 후 평상시처럼 걸어가 막고 있는 프레스를 해킹해 **들어올리는 순간**,
보스가 **틈 사이로 머리를 쾅 박고 입구를 막아 버린다.**
여기서 **처음으로 프레스를 내려찍어** 보스를 기절시키고 도망친다.

**후반부 — 프레스는 무기다 (역주행)**

- 계속 도망가다 **입구에 도착할 때마다 보스가 가로막고**, 막힐 때마다 **프레스로 내려찍으며** 도망친다.
- **마지막 1스테이지 입구**에서 마지막으로 막히고, 그때 내려찍어 **보스를 죽인다.**
- 3 → 2 → 1 **역순**이고, 끝나는 곳이 시작한 곳이다(수미상관).

> **같은 기믹을 두 번 쓴다** — 전반부엔 올려서 열고(문), 후반부엔 내려서 찍는다(무기).
> 방향과 목적만 뒤집힐 뿐 배울 것은 하나뿐이라, 후반부에 새 기믹 없이 긴장만 올라간다.

**보스 파괴 연출 — 축소 확정**

- **머리가 점점 찌그러지는 것은 구현하지 않는다.** 그냥 **"깡" 하고 부딪히는 느낌**으로 간다.
- 마지막 1스테이지 내려찍기도 **그냥 "깡" 내려찍고 보스가 뒤로 넘어가는 것**으로 끝낸다.

> ⚠️ **§11.1의 3상태(원본 → 넙죽이 → 완전 찌부) 모델 스왑과 충돌한다.** 위 축소가 그 표를 어디까지
> 대체하는지(모델을 1개만 쓸지, 넙죽이 상태는 남길지) 아직 정하지 않았다. §11.1을 읽을 때 이 항목을
> 같이 볼 것.

### 0.3 핵심

- **핵심 동사 = 해킹.** 해킹으로 기계(레일 캐리어·갠트리·피스톤·유압프레스·터렛)를 밖에서 **조종**하고, 경비병·로봇팔에 **시점 진입**해 이용한다(§6).
- **픽션상 실체 = 디지털이 아니라 물리 조작.** 무대가 **폐공장(비SF)** 이라 "디지털 해킹"이 겉돈다. 그래서 해킹의 정체는 **애완 거미의 실이 대상 내부의 기어·부품을 파고들어 강제로 맞물려 물리적으로 움직이는 것**이다. 점 패턴(§2.4)은 "암호 풀기"가 아니라 **내부를 실로 헤집어 맞물리는 행위**이며, 빙의도 거미가 대상 **내부로 파고들어 직접 구동**하는 것이다. (용어 "해킹"은 게임 내 축약어로 유지.)
- **은신·드론은 삭제.** 플레이어는 항상 노출되며 경비병은 **상시 위협**이다. 긴장은 "경비병을 처리·회피하며 필요한 기믹을 조종해 길을 뚫는" 데서 나온다.

## 2. 핵심 게임 루프 & 조작

> **공장 기계를 해킹·조종해 길을 만들고 경비병을 처리하며 목표로 전진한다.**

- 플레이어는 **항상 노출**된다(은신 없음).
- 경비병은 사거리·시야 안 플레이어를 조준 → n초 후 발사 → 사살하는 **상시 위협**이다(§2.3).
- 해킹은 **시간·주의를 점유**한다: 패턴 푸는 동안 정지, 조종 중엔 이동 가능.
- 따라서 판단은 "경비병 사거리 안에서 해킹을 감행할 것인가, 먼저 경비병을 (기믹으로) 치우고 안전하게 해킹할 것인가"이다.

### 2.1 조작 스킴

- **파지**: 폰을 **가로로 양손 파지**(브롤스타즈 등 일반 모바일 게임 자세).
- **왼손 엄지 — 이동**: **플로팅 조이스틱**(처음 터치한 지점이 중심).
- **오른손 엄지**:
  - 짧은 **탭 = 점프**
  - **드래그 = 해킹 패턴**
  - **오른쪽을 꾹(정지) = 빙의 해제·본체 복귀**
  - 구분: 탭=짧게 / 드래그=움직임 있음 / 복귀=오른쪽 영역을 움직임 없이 유지(오발동 방지 위해 살짝 길게). 실측 튜닝.
- **대상 지정** = HMD 머리 시선(head gaze) Raycast. 콜라이더는 모델보다 넉넉하게.

### 2.2 해킹 흐름 (펫 거미)

플레이어는 신적 존재가 아니라 **오른손 위 애완 거미(펫)** 로 해킹한다.

- **흐름**: 대상 바라봄 → 오른엄지 드래그 → 거미가 줄을 순식간에 뽑아 대상 **내부로 꽂아 넣음**(기어·부품 사이로 파고듦) **+ 점 패턴 즉시 등장(병렬)** → 패턴을 그으면 **실이 내부를 헤집어 맞물리며** 성공.
- **모든 해킹 = 점 패턴 통일**(조종·빙의·보스 스턴 §11.3 공통). 시도 즉시 패턴이 뜨므로 대기 시간이 없다.
- **사거리 = 초록 하이라이트로 즉시 판정**(§7). 사거리 밖 대상은 하이라이트되지 않아 시도 자체가 안 됨 → 거미 낙하·귀환 로직 불필요.
- **점 패턴 미니게임 = §2.4**(2×2 한붓그리기).
- **실의 외형(스티치/레이싱)**: 실은 내부로만 사라지지 않고 **표면 틈새·이음새를 들락날락 꿰매듯** 지나가 **외부에도 초록 실 마디가 얽혀 보인다**. 허공에 늘어진 한 가닥이 아니라 **표면을 따라 박음질된** 형태 → "이 기계는 거미줄에 꿰여 장악됐다"가 외형으로 읽힘. 해킹 중=초록 / 장악 후=파랑(§7)으로 실 색이 남아 **조종 중 표식**을 겸한다.

접속 성공 시 종류별 연출:

| 종류 | 연출 |
| --- | --- |
| **외부 조종형** (레일·갠트리·피스톤·프레스) | 줄 **퐉** 꽂음 → 반짝 → 패턴 → 조종(폰 6DoF) |
| **시점 진입형** (경비병·로봇팔) | 줄 **톡** 꽂음 → (경비병은 **스턴·찌직**) = 패턴 푸는 시간의 연출 → 성공 시 거미가 대상으로 날아가 붙음 → 화면 **초록 지직 + 암전** → **대상 시점 전환**(경비병은 1인칭, 그 몸도 손에 거미를 들고 줄이 꽂혀 빛남 = 조종 중 표시) |

- 조종 단계는 §6(PD 제어). ⚠️ 왼엄지 조이스틱 + 폰 모션 동시 파지의 부담은 실측 필요.

### 2.3 경비병 위협 모델

- 경비병은 **감지 범위 + 시야**를 가진다. 은신이 없으므로 범위·시야 안에 들면 **항상 감지**한다.
- 감지하면 → **멈춰서 조준 → n초 후 발사 → 명중 시 사살**(n = 튜닝값).
- 회피 = 사거리·시야 밖으로 **이동**, 엄폐, 또는 경비병 **제거**(로봇팔·터렛·유압프레스)·**빙의로 치우기**.
- 패턴 푸는 동안 정지하므로 사거리 안이면 그대로 맞는다 → 해킹은 경비병 없는 위치에서 하는 것이 원칙.
- (미정) 조준 후 시야 이탈 시 해제 여부, 발사 전 취소 가능 여부 → 실측.

### 2.4 점 패턴 (해킹 미니게임)

모든 해킹(조종·빙의·보스 스턴 공통, §2.2)은 같은 점 패턴을 푼다. 성공 후 결과만 3종으로 갈린다.

- **격자 = 항상 2×2(점 4개) 고정. 대각선 허용** → 변 = 테두리 4 + 대각선 2 = **6변**(4점 완전그래프 K4).
- 패턴 = 점을 잇는 **한붓그리기**(시작점부터 안 떼고 죽 긋는다). **같은 변 재사용(겹침) 허용**, 단 **한 변에 최대 3번**까지.
- **선(줄) 개수만 대상 종류별로 고정 = 난이도**, 실제 경로는 **매번 랜덤**:
  - **외부 조종**(빙의 불가) = **5선** (쉬움)
  - **시점 진입**(빙의 가능) = **7선** (어려움)
  - **보스** = **7선** (빙의급, §11.3)
- **시작점 = 좌상단(왼쪽 위) 점 고정.** 즉시 되돌아가기(A→B→A) **허용**(겹침·부채꼴이 핵심 재미).
- **생성 알고리즘**: 고전 한붓그리기(오일러 경로: 모든 변을 정확히 1회)와는 **다른 문제**다. 우리는 "K4 위에서 **길이 N(5/7)짜리 랜덤 워크**, 단 변별 사용 ≤3, 시작 = 좌상단"이면 되므로 → **제약 있는 랜덤 워크**(좌상단에서 캡 안 찬 인접 변을 N번 무작위 선택, 되돌아가기 포함)로 즉석 생성한다. 별도 라이브러리 불필요, 수십 줄. 판정도 **방향(변) 시퀀스 일치 비교**로 단순(시작점 고정이라 정렬 필요 없음).
- **성격**: 왼쪽에 뜬 패턴을 **보고 그대로 따라 긋는** 순발력·정확도 챌린지(암기 아님). 랜덤이라 손버릇으로 못 외운다. **픽션상 = 암호 풀기가 아니라 거미 실로 내부 기어를 헤집어 맞물리는 물리 조작**(§0.3).
- **입력**: 절대 위치가 아니라 **방향 스트로크**(다음 점 방향으로 톡톡 그어 이동). 폰=오른엄지 방향 드래그 / PC=**Space 홀드 + 마우스 방향 드래그**.
- **UI**: 패턴은 **화면 왼쪽**에 뜬다. 겹친 변은 실제로는 포개지지만 화면엔 **부채꼴로 살짝 펼쳐서** 그려 "몇 번 지나가는지"를 보이게 한다.
- **화면 구성(라이브 피드백, 확정)**: 폰 암호락처럼 "지금 어디까지 왔는지"를 확실히 보인다. 4겹으로:
  - **① 타겟 경로(템플릿)** — 풀 정답 패턴을 **흐린 유령선**으로 깔아 둠(따라 그릴 대상).
  - **② 라이브 트레이스** — 실제로 그은 선을 그 위에 **진하게** 덧그림. 완료 획은 파랑으로 잠김.
  - **③ 현재 위치 헤드** — 지금 있는 점에 **밝게 빛나는 실 끝(거미줄 tip)** → "여기서 다음 획을 뽑는다".
  - **④ 방향 러버밴드** — 현재 점에서 **입력 방향으로 늘어나는 실** 실시간 표시 → 커밋 전 "이 획이 어느 점으로 갈지" 미리 보임(폰 암호락의 손가락-따라-선을 6변으로 스냅).
- **기어 비주얼(내부 조작 표현)**: 패턴 UI 배경에 **기어·부품**을 그린다. 기어는 **생성된 경로 위에 절차적으로 배치**(방식 b) → 선을 그으면 **항상** 그 변의 기어가 돌아가며 반응이 난다. "암호 입력"이 아니라 "**내부를 물리적으로 맞물리는 중**"임을 매 획마다 손맛으로 전달. (고정 배치는 랜덤 경로가 기어를 안 지나 밋밋해질 수 있어 배제.)
- **사운드 타이밍(확정)**: 한 획(점→점)을 그을 때 시간축으로 ③ **실 쭈욱 당김**(획 진행 중, 텐션) → ① **기어 회전음**(변 중간 기어 지날 때) → ② **철컥**(다음 점 스냅·맞물림 잠김). 이식 `CombatAudio` 2D 오디오 허브 재활용(이식_환경 ⑦).
- **UI 레이어 구조 & 소멸 연출(확정)**: 패턴 UI는 **여러 레이어로 분리**한다 — (a) 배경 기어·부품 / (b) 타겟 템플릿(유령선) / (c) 라이브 트레이스(실) / (d) 현재 헤드·러버밴드. 성공·실패 시 **통짜 페이드가 아니라 레이어별 시차**로 빠진다(리치한 소멸감).
  - **실패**: 이어졌던 **실(c)이 순식간에 시작점(좌상단)으로 촤르륵 되감김** — 팽팽하다 끊겨 스프링처럼 튕겨 돌아가는 느낌 + 실 되감기 소리. 이어서 **헤드/러버밴드(d) → 기어 역회전·역철컥(a) → 템플릿(b)** 순으로 시차 페이드아웃.
  - **성공**: 마지막 획 잠김 → 큰 **콰쿵/철컥** → 대상 파랑 전환과 싱크. 레이어는 **트레이스(c) 잠깐 유지 → 기어(a) 정지 → 템플릿(b)·헤드(d)** 순으로 빠짐.
- **⟨제안·미정⟩ 세부 연출** — 아래는 방향만 적어 둔 제안, 실측 후 확정:
  - **기어 세부**: 변마다 기어 1개(획=기어 한 번). **겹침 = 래칫** — 같은 변 2·3회 = 그 기어 **딱딱딱 2·3클릭**(겹침·부채꼴에 물리적 이유 부여).
  - **완성 시**: 큰 **콰쿵/철컥** + 대상 깨어남(초록→파랑, 외부 스티치 실 팽팽 §2.2). UI는 잠깐 **잠김 연출 후 페이드** 유력.
  - **오답 획**: (a) **틀리면 이 해킹 실패**(방 리셋 아님, 재시도) 유력 / (b) 정답 방향으로만 스냅(순수 속도) — 실측 판단.
- 판정 결과는 SYB 통신의 `PatternResult`(WebSocket)와 정합 필요(§9).

### 2.5 VR ↔ PC 조작 대응 (PC 프로토타입)

PC 먼저 개발(§10)하므로 폰 조작을 PC로 옮긴다. **게임 로직은 그대로 두고 입력 소스만 바꾸는** 것이 원칙 — 폰 이식 때 바인딩만 교체한다.

**조직 원리**: **Space = 해킹** / 좌·우클릭 = 그 대상의 조작 / WASD = 이동 / 마우스 = 시점·조준 / Q = 복귀·해제.

**PC가 부족한 것 → 대체**
- **6DoF 깊이축**(밀고 당기기): 물리 입력 없음 → **스크롤**. (이 "깊이축"은 조종당하는 *물체의 앞뒤 이동 축*이며, 폰의 6DoF=컨트롤러 폰 위치추적(층 2)과는 별개. PC는 6DoF 없이도 3축 다 조종된다.)
- **머리·손 분리 안 됨**: 마우스 하나가 시점을 겸함 → 조종을 **버튼+스크롤로 빼서** 마우스를 시점으로 남긴다(→ 조종하며 도주 가능). 해킹 패턴 그릴 때만 마우스 점유로 시점 잠깐 정지.

**본체(평상시)**

| 액션 | VR (S24+ HMD + S10e) | PC |
|---|---|---|
| 이동 | 왼엄지 조이스틱 | WASD |
| 시점·대상 지정 | 머리 시선 + 중앙 레티클 | 마우스 + 중앙 레티클 |
| 점프 | 오른엄지 **탭** | Space **탭** |
| 해킹 시도 | 오른엄지 **드래그** | Space **홀드** + 마우스 드래그 |
| 복귀·해제 | 오른쪽 꾹 | Q |
| 방향 전환 | Snap Turn 45°(멀미완화) | 마우스 연속 회전(불필요) |

- **Space 탭=점프 / 홀드=해킹**(폰 탭/드래그와 동일 논리, 오발동 튜닝 필요).

**해킹 패턴 입력(공통)**: 방향 스트로크 → **Space 홀드 + 마우스 방향 드래그**(§2.4) / 취소 = 떼기·Esc.

**외부 조종 중** — 조종을 **좌·우클릭(+Shift)** 으로 하여 **마우스는 시점으로 자유**(도주 + 조종 동시). **최대 2축**(3축·스크롤 폐기). 물체가 쓰는 축을 우선순위 **좌우 > 앞뒤 > 상하** 로 최대 2개 골라 슬롯에 배정한다.

| 슬롯 | VR | PC |
|---|---|---|
| **1순위 축** | 폰 제스처(해당 축) | **좌클릭(−) / 우클릭(+)** |
| **2순위 축** | 폰 제스처(해당 축) | **Shift+좌클릭(−) / Shift+우클릭(+)** |
| 아날로그 vs 플릭 | 살살 vs 확(임펄스) | 홀드 = 아날로그 / **더블클릭 = 플릭** |
| 이동(본체·도주) | 왼엄지 조이스틱 | WASD(동시 가능) |
| 시점 | 머리로 봄 | **마우스 자유** |

- 예: 레일(1축)=좌/우클릭 · 갠트리(좌우+앞뒤)=좌우 클릭·앞뒤 Shift+클릭 · 프레스(상하 1축)=좌/우클릭 · **터렛(회전 1축)=좌/우클릭**.
- **PC는 스크롤 미사용.** VR(폰)은 변경 없음. 스냅 격자라 이산 입력이 오히려 맞다.
- ⚠️ 실측: **좌/우클릭을 가로 좌/우로 쓰는 조작감**, 그리고 **홀드(등속 크립)가 §6.2의 1:1 아날로그를 대신할 수 있는지**(특히 유압프레스 정밀 조종) 확인.

**시점 진입 중(빙의)**

| 대상 | 시점/조준 | 좌클릭(주 행동) | 이동 | 릴레이 해킹 | 복귀 |
|---|---|---|---|---|---|
| 경비병(1인칭) | 마우스 | — | WASD+Space | Space 홀드 | Q |
| 로봇팔(3인칭) | 마우스(손 방향 회전) | 쥐기 토글 | — | Space 홀드 | Q |

> 터렛은 **외부 조종**으로 옮겼다(§6.2) — 위 표가 아니라 슬롯 표(좌/우클릭)를 쓴다. CCTV는 보류(§6.1).

**보스 스턴**: 마우스 조준 + Space 홀드 → 패턴(§2.4). 결과만 n초 스턴.

**시점 처리 (마우스 1개 제약)**
- **해킹 중**: 마우스가 패턴에 점유 → 시점 잠깐 고정(~1초). 설계 의도(§2 해킹=주의 점유·정지)와 부합. 주변 감시 손해는 **방향 지시 HUD 경고**(위협 쪽 화살표/붉은 글로우)로 대체. VR은 머리로 둘러볼 수 있으나 그 차이는 수용.
- **외부 조종 중**: 조종을 버튼·스크롤로 빼서 **시점은 마우스로 계속 자유** → 추격 중 도주하며 조종 가능. §6.2 "보는 각도 바뀌면 조종 매핑 바뀜"은 대상을 바라보며 조종하면 자연 회피.
- VR 이식 시 머리-손 분리가 복원돼 제약 자연 해소.

### 2.6 펫 거미 모션 세트

펫 거미는 **오른손 위 상시 뷰모델**(FPS 무기 뷰모델 위치, 이식 `ViewmodelMotion`/`ViewmodelCamera`). 그 모션이 곧 게임필이자 **상시 HUD** — 텍스트 UI 없이 상태를 펫 자세로 읽힌다(VR·흑백에서 유용).

**성격·역할**
- **"능글맞고 든든한 파트너"** 톤. 무기 뷰모델처럼 **반응성 좋은 애니**가 핵심.
- 맵이 흑백이라 펫은 **실루엣 + 실 색(초록=가능 / 하늘색=장악)** 으로 감정·상태 전달.
- 펫 모션이 **조준 가능 대상·쿨다운·위협 방향**을 겸해 표시(어포던스, UI 절약).

**상황별 모션**

| 상황 | 펫 모션 | 겸하는 피드백 |
|---|---|---|
| **대기(idle)** | 다리 까딱, 두리번, 숨쉬기 | 살아있는 파트너감 |
| **이동** | sway·bob, 다리로 손 붙잡고 버팀 | — |
| **점프** | 웅크렸다 폄(다리 오므림) | — |
| **조준(사거리 안 대상)** | 그쪽으로 **앞다리 들어 겨냥 + 방적돌기 텐션** | "지금 해킹 가능 대상 있음" |
| **해킹 시도** | **방적돌기에서 실 발사** → 대상 내부에 꽂음(외부=퐉 / 시점=톡) | — |
| **해킹 중(패턴)** | 실 계속 뽑아 **앞다리로 바쁘게 조작** | "내부 헤집는 중" 동기화 |
| **성공(외부 조종)** | 실 문 채 자세 잡음(손↔대상 연결 유지), 실 하늘색 전환 | 마리오네트 시작(§6.2) |
| **성공(시점 진입)** | 실 타고 **대상으로 촥 날아감**(뷰모델서 사라짐) | 시점 전환 |
| **릴레이** | 현재 대상에서 **다음 대상으로 새 선 뻗어 옮겨감**(생명줄 연장) | 릴레이 체인(§6.3) |
| **실패** | 실이 좌상단 되감김에 **홱 당겨졌다 제자리**(움찔·짜증) | 실패 즉시 인지(§2.4) |
| **외부 조종 중** | 앞다리로 실 **밀당**, 이동 방향 맞춰 당김 | 텐션 사운드 싱크 |
| **빙의 복귀(Q)** | **생명줄 따라 손으로 촥 귀환** | 복귀 인지(§6.3) |
| **위협(본체 조준)** | 위협 방향으로 **곤두섬/경계 자세** | 방향 경고 보조(§2.5) |
| **보스 스턴** | 큰 대상이라 **여러 가닥·힘주며 버팀** | 스턴 각인(§11.3) |
| **쿨다운(재해킹 불가)** | 실 **재정비·다리 정돈**(준비 안 됨) | 쿨다운 표시 |
| **피격/본체 사망** | 움츠러들며 화면 가림과 함께 사라짐 | 죽음 연출(§16.2) |

> 빙의 중엔 펫이 대상(체인 끝)에 있어 뷰모델엔 없다. 본체는 **하늘색 생명줄을 손으로 꽉 쥔 자세**(§6.3).

## 3. 컨트롤러 입력 능력과 한계 (설계의 물리적 전제)

컨트롤러로 무엇을 잡을 수 있고 없는지가 조작 설계 전체를 규정한다. **DoF(자유도)** 로 정리한다.

| 입력 | 어떻게 잡나 | 됨? | 원리 |
|---|---|---|---|
| **회전** (기울임·도리질·갸웃) | 자이로 (3DoF) | ✅ | 적분 1번이라 안정. 카메라 불필요 |
| **터치 / 스와이프** | 터치스크린 | ✅ | 자명 |
| **임펄스** (휙 휘두른 세기) | 가속도계 | ✅ | 짧은 윈도우 1번 적분. ZUPT로 리셋 |
| **절대 위치** (앞으로 30cm 밀기) | **VIO(카메라+IMU) 필요** | 조건부 | 가속도 2번 적분은 몇 초면 붕괴. 카메라로 바깥을 봐야 앎 |

**핵심 사실**: 가속도만으로는 위치를 못 잡는다(두 번 적분 → 오차가 시간 제곱으로 폭발). 위치는 카메라로 실제 세상 특징점을 보고 자기 이동을 역산하는 VIO가 필요하다.

## 4. 6DoF 결정 — 채택 (위치 조작 필요)

**결정**: 컨트롤러의 **6DoF(위치 포함) 추적을 채택**한다. 위치는 ARCore VIO로 얻는다.

**근거**: "폰을 실제로 움직여 물체를 그만큼 이동"이 재미의 필수 요소. 회전만으로는 물체 조종의 공간감이 나오지 않는다.

### 4.1 SYB SPEC v3와의 차이

SYB 통신 명세는 "6DoF/VIO 폐기"로 적혀 있다. 이 설계안은 그것을 뒤집어 6DoF를 복원한다. 대립이 아니라 아직 확정 안 된 게임 디자인을 여기서 정하는 것이다. 다만 6DoF 복원은 통신·컨트롤러 앱 변경을 요구(§5)하므로 **SYB 합의가 전제**다. 상세는 [../decisions/0001-6dof-controller-tracking.md](../decisions/0001-6dof-controller-tracking.md).

### 4.2 6DoF의 대가

| 문제 | 대응 |
|---|---|
| **카메라 가림** (손가락이 후면 카메라 → 추적 끊김, SW 해결 불가) | **그립 형상 설계** |
| **환경 조건** (저조도·단색 흰 벽 실패) | 시연 공간을 밝고 무늬 있게 |
| **발열** (카메라+VIO 상시) | 통풍 + 세션 시간 제한 |
| **드리프트** (수 분 누적) | 수 분마다 재보정 |
| **좌표계 분리** (두 폰 원점 무관) | 수동 캘리브레이션 정렬 |
| **빠른 동작** (모션 블러) | 빠른 휘두르기를 핵심 조작으로 안 삼기 |

### 4.3 층 구조 — 3DoF 위에 6DoF를 얹는다

- **층 1 — 3DoF (회전 + 터치 + 임펄스)**: 항상 동작. 저발열·저지연·카메라 불필요.
- **층 2 — 6DoF (위치)**: VIO 필요.
- **Graceful degradation**: 층 2가 깨지면 층 1로 자동 강등("연결 품질 저하" 연출). 층 1만으로도 물체 조종이 성립하도록 먼저 만든다.

## 5. 프로토콜에 미치는 영향 (SYB 협의 필수)

6DoF를 쓰면 컨트롤러가 **위치(position)** 를 함께 보내야 한다. 현재 공유 `InputPacket`에 위치 필드가 없다.

- 현재 `InputPacket` = 60바이트. `Position(float×3)` **+12바이트 → 72바이트**.
- `shared/com.mindhexer.shared`에서만 변경(양쪽 자동 반영). `PacketSerializer`·`NETWORK_PROTOCOL.md`·`ProtocolVersion` 동시 갱신.
- 컨트롤러 앱: ARCore(VIO) 세션 구동 → 카메라 상시 동작. 현재 `TouchGyroCapture`에 없는 부하.

> 근본 비용은 몇 바이트가 아니라 **컨트롤러 앱에 VIO 파이프라인 전체가 얹히는 것**이다. SYB와 스코프 합의 선행.

## 6. 해킹 대상 & 조종

대상은 **두 부류**다.

- **외부 조종** (내 시점 유지, **연두** 하이라이트): 밖에서 조종. 아날로그 + 플릭(§6.2).
- **시점 진입** (대상 시점으로 들어감, **진한 청록** 하이라이트): 그 안에서 봄. 릴레이 가능(§6.3).

### 6.1 대상 로스터

**외부 조종 (연두)**

| 대상 | 용도 |
| --- | --- |
| **레일 캐리어** | 레일 위 1D 이동. 레일을 레벨마다 임의 방향 배치(벽 세로/바닥/천장/대각·꺾임) |
| **다축 갠트리** | 상자 공간 XYZ 자유 이동(2~3축) |
| **피스톤** (공압) | 밀치기·막기·발판 등 **타이밍 기믹** |
| **유압프레스** (유압) | **경비병 압사** + **2·4막 보스 압사**(단계적 파괴, §11) |

| **터렛** | 회전 조종 + **자동 사격**(무차별 — 나도 쏜다). 경비병 살해 (§6.2 터렛) |

**시점 진입 (진한 청록, 릴레이 가능)**

| 대상 | 용도 |
| --- | --- |
| **경비병(로봇)** | 1인칭. 플레이어와 완전 동일 조작 |
| **로봇팔** | 3인칭. 플레이어/경비병을 집어 옮김 |

**보류 — 이번 범위에서 제외 (시간·단순화)**

| 대상 | 사유 / 상태 |
| --- | --- |
| **CCTV** | 스포트라이트 위험 지대 + 벽 관통 정찰. **레벨에 배치하지 않는다.** 코드·프리팹·에셋은 남긴다(`Prefabs/Hackables/Deferred/`) |
| **회전 장치** (회전판) | 축 중심 각도 회전 발판. 구현체 `RotationPlatform`은 남기고 배치만 안 한다 — **터렛 조종이 이 조작 문법을 그대로 쓴다**(§6.2) |

> 보류는 **삭제가 아니다.** 되살릴 때 이 표가 근거다. 터렛이 회전 조작을 물려받으므로 `RotationPlatform`
> 코드는 계속 살아 있는 채로 검증된다.

### 6.2 외부 조종 — 축 정의 & 입력 모드

**축 정의**
- 이동 축은 **월드 좌표에 고정**(레일·기믹이 월드 X/Y/Z 중 어느 축을 따르는지는 레벨에 박힘, 플레이어 위치와 무관).
- **폰 제스처는 그 월드 축이 화면에 투영되는 방향에 맞춰 매핑**(가로면 좌우, 세로면 상하, 깊이면 앞뒤 밀기). 보는 각도가 바뀌면 대응 제스처도 바뀐다.
- **레일 캐리어 = 1축**, **다축 갠트리 = 2축**. **위치 최대 2축**(우선순위 좌우 > 앞뒤 > 상하). 3축·스크롤 깊이 폐기 → PC 매핑 §2.5.
- 구현: 월드 축 벡터를 HMD 카메라로 화면 투영 → 가로/세로/깊이 판별해 제스처 배정.

**입력 모드 — 아날로그 + 플릭**
- **살살 = 아날로그 1:1 추종**(미세 조종).
- **강하고 빠르게(확·탁) = 플릭.** 의미는 대상 종류에 따라 다르다:
  - **이송 기믹(레일·갠트리)**: 다음 스냅 포인트로 **한 칸**. 현재 위치 무관(1/5에서 오른쪽 확 → 1/4까지).
  - **타격·돌출(피스톤·프레스)**: **끝까지(풀 스트로크)**. 프레스=내리찍기, 피스톤=돌출.
- **스냅 격자 = 정답 위치에 맞춰 분할 수 N 지정**(정답 2/4 → 4분할, 3/5 → 5분할). 플릭만으로 정답에 안착.
- 플릭 판정 = 가속도 임펄스(§3, 층 1로도 됨).

**⏸ 레일 세트 — 값 확정 보류 (스테이지 로드 후 착수)**

컴포넌트(`RailSet`)는 동작하지만 **수치가 전부 미확정**이다. 맵이 아직 바닥·천장을 뚫는 세로 레일뿐이고,
곧 불러올 스테이지에 **레일 캐리어를 여러 개 이어붙인 것**이 있으니 그것을 보고 하드코딩하기로 했다.
지금 값을 정해도 칸 길이가 바뀌면 전부 다시 정해야 한다.

미해결 항목:

- **칸 길이·스케일 미정.** 실측: `Model_Rail` 한 개 = 8.92 × 1.63 × 1.54 m(스케일 11), 그레이박스는
  2.00 × 0.10 × 0.70 m. **모델이 칸 간격(2m)의 4.5배**라 그대로 갈아끼우면 다섯 칸이 겹쳐 뭉친다.
  → 레일 위 라이더(CCTV) 크기 대비 적절한 스케일을 눈으로 먼저 정하고, `cellLength`를 거기에 맞춘다.
- **두 줄 구성.** `Model_Rail`은 파츠 z가 한쪽에 몰린 **한 줄**이다(z −0.096~0.036). 두 줄은 이걸 Z로
  나란히 두 개 놓는 것 — 그레이박스의 `Bar_L`/`Bar_R`와 같은 구조.
- **플릭 거리·시간 하드코딩 예정.** 플릭 기본값은 "레일 하나 길이의 절반"으로 하기로 했다.
  현재 값(`flickTime` 0.28초 × 칸 2m ≈ 평균 7.1 m/s, 오버슈트로 순간 최고는 더 높음)은
  **사람 걷는 속도의 5배로 너무 빠르다.** 칸 길이가 정해질 때 같이 잡는다.
- **필요 총 길이 공식**: 레일이 고정 트랙이 아니라 세트 전체가 밀리므로, `+rangeMax`로 가면 반대쪽 끝도
  그만큼 딸려 와 시야에 들어온다.
  ```
  총 길이 T ≥ 보이는 구간 L + 2 × max(rangeMax, |rangeMin|)
  필요 칸 수 = ceil(T / cellLength)
  ```
  → **칸 수는 손으로 정하는 값이 아니라 범위에서 계산되는 결과다.** "엄청 길게"는 고민이 아니라
  범위를 넓힌 결과가 된다.
- **⚠️ `RailSetEditor` 경고식이 틀렸다.** `railTotal < (rangeMax − rangeMin)`만 검사하는데 실제 조건은
  위 공식이다 — **경고를 통과해도 레일 끝이 드러난다.** "보이는 구간 L" 입력을 추가해 고쳐야 한다.
- **⚠️ 드로우콜.** 레일 1개 = 렌더러 96개 · 정점 12,430(머티리얼은 1종). 두 줄 × 9칸이면 렌더러 1,728개,
  30칸이면 5,760개 — **모바일 VR 양안 렌더에서 죽는다.** 세트가 움직이므로 정적 배칭도 안 된다.
  → 머티리얼이 1종이라 **`Mesh.CombineMeshes`로 렌더러 1개로 결합**하면 손실 없이 해결된다
  (정점 22만이면 `IndexFormat.UInt32` 필요). 에디터 툴 버튼으로 구워 두는 방식.
- `RailSet.prefab`이 아직 없다 — 씬에 직접 배치돼 있어 재사용·팔레트 등록이 안 된다.

**대상별**
- **레일 캐리어**: 레일 방향으로 기울임/밀기(시점 기준). 1축.
- **다축 갠트리**: 좌우·상하(± 앞뒤 밀기 6DoF)로 월드 축 매핑. 2~3축.
- **피스톤(공압)**: 홀드로 살살 + 플릭으로 **끝↔끝 돌출**. (프레스와 조작을 통일했다 — 게임을 복잡하게 만들지 않기로.)
- **유압프레스(유압)**: **홀드 정밀(느림·묵직) + 플릭=끝까지 내리찍기.** 압사.
- **★ 플릭은 홀드보다 훨씬 빨라야 한다.** 예전엔 둘이 같은 시간(1초)을 써서 차이가 안 느껴졌다.
  `flickDuration`을 따로 두고 **프레스 0.12초('쾅') / 피스톤 0.2초('철컥')**, 홀드는 1초 유지.
- **객체별 최소·최대 길이.** `strokeMin`/`strokeMax`(월드 m)로 개체마다 행정을 다르게 준다.
  같은 프레스라도 A는 얕게, B는 깊게 내려오게 만들 수 있다.
- **미리 늘여 놓고 시작할 수 있다.** `startExtension`(0~1) 하나가 **에디터 씬 뷰 표시와 런타임 시작값을
  동시에** 담당한다 — 슬라이더를 움직이면 그 자리에서 늘어나고, Play를 누르면 **보이는 그 상태로 시작**한다.
  (홈 자세를 직렬화해 두므로 여러 번 늘였다 줄여도 원위치가 밀리지 않는다.)
- 구동 = PD 제어(`torque = Kp*error - Kd*angularVelocity`). 물체별 Kp/Kd로 무게(갠트리 무겁게 / 캐리어 경쾌). 힘·토크 계산 전부 S24+(SSOT = 헤드셋).
- **PC 조종 입력 매핑(3축: 좌·우클릭 / Shift+클릭 / 스크롤)은 §2.5** 참조.

**마일스톤(스테퍼) — 홀드 입력의 양자화**

경비병을 제외한 **모든 외부 조종 대상**에 적용된다(경비병은 빙의라 이 경로를 안 탄다).

VR 조종 입력은 휴대폰 6DoF 추적에서 오고, 그 신호에는 늘 **떨림**(가만히 들고 있어도 미세 진동)과
**아웃라이어**(추적이 한 프레임 튐)가 섞인다. 신호를 잘라내는 방식(데드존·저역통과)은 진짜 조작까지
뭉개지고 임계값 밖 스파이크는 그대로 통과한다. 그래서 **자르지 않고 양자화**한다.

- 요구량을 누적기에 쌓고, **누적이 스텝 이상 && 간격 경과** 시 **정확히 ±1스텝만** 내보낸다.
- **떨림** → 스텝보다 작은 변화는 출력 0. 좌우 진동은 누적이 상쇄돼 아예 안 움직인다.
- **아웃라이어** → 간격당 1스텝이라 튀어도 한 칸만. 남은 양은 누적기에 남아 **버려지지 않는다**
  (단 상한 2스텝 — 없으면 손을 뗀 뒤에도 밀린 딸깍이 줄줄이 나온다).
- 부수 효과로 **딸깍딸깍 톱니바퀴 손맛**. §6.2의 "기계식 인덱싱"과 같은 언어라 필터가 곧 연출이 된다.

> **★ 스텝과 간격은 따로 정할 수 없다: `스텝 ÷ 간격 = 최대 속도`**
> 5도 스텝에 간격 0.5초면 최대 10°/s로 답답해진다. 그래서 **간격을 딸깍 빈도로 고정하고
> (0.0833초 = 초당 12틱), 스텝은 그 부품의 기존 속도에서 유도**한다. 튜닝 손잡이가 "속도" 하나로
> 유지되고 딸깍 빈도가 부품마다 같아 손맛이 통일된다.

| 부품 | 기존 속도 | 유도된 스텝 |
|---|---|---|
| 터렛·회전판 | 60°/s | **5도** |
| 레일·갠트리 | 2 m/s | **0.17 m** |
| 피스톤·프레스 | 스트로크 비율 0.6/s | **0.05** (비율) |

**플릭에는 걸지 않는다.** 플릭은 격자로 가는 각본된 이동이고 자체 가감속 곡선이 있다 — 양자화를 또
걸면 딸깍이 이중으로 겹쳐 덜덜거린다. 노이즈가 들어오는 경로는 홀드뿐이므로 거기만 걸면 충분하다.

구현: `MilestoneStepper`(구조체) 하나를 `RailSet`·`RotationPlatform`·`ActuatorControl` 셋이 공유.
실측 검증 — 30·45·60·72fps 전부 12틱/60°s 유지, 떨림 ±1도 1초 → 0도, 200도 스파이크 → 즉시 5도.
(90fps에서만 11틱/55°s — 프레임 경계 양자화라 무해하다.)

**실 연결 조종 (마리오네트) — 빙의와의 시청각 구분**
- 외부 조종은 빙의(내부로 들어감)와 달리 **실이 손(펫 거미) → 대상에 연결된 채 유지**되며, 그 실로 **꼭두각시처럼** 조종한다. 조종하는 내내 연결선이 보인다(§2.2 스티치와 이어짐).
- **움직일 때마다 실이 팽팽하게 늘어지는(당겨지는) 소리** — 조종 입력에 반응하는 텐션 사운드(§2.4 "실 당김"과 같은 계열, 조종 지속판).
- **실 색 = 상태 표식**: 기본 **초록**(해킹 시도 중) → **성공/장악 후 밝은 파랑**(§7 색 언어: 초록=가능 / 파랑=장악과 일치). 조종 중엔 파란 실이 손과 대상을 잇는다.

**터렛 — 회전 조종 + 자동 사격**

- **조종 방식은 회전 장치와 완전히 동일하다.** 별도 문법을 만들지 않는다 — **1축(좌우 회전)**,
  홀드 = 연속 회전, 플릭 = 한 칸 각도 스냅. §2.5 슬롯 표를 그대로 쓴다.
- **각도 제한은 기본으로 없다**(±360). 터렛은 한 바퀴 도는 게 기본이고, 제한은 필요한 개체에만
  좁혀서 준다. 플릭 격자는 기본 **30도**(회전판의 45도와 다르게 잡았다 — 조준은 더 잘게).
- **발사는 자동이다.** 조준선에 들어온 대상을 스스로 쏜다. 플레이어가 쏘는 버튼은 없다 —
  플레이어가 하는 일은 **"어디를 겨누게 할 것인가"** 하나뿐이다. 퍼즐이 "조준 각도 맞추기"로
  깔끔하게 환원된다.
- **★ 무차별이다. 해킹 전후가 같다.** 조준선에 걸린 것이 **플레이어든 경비병이든 똑같이 죽인다.**
  편을 가르지 않는다. 벽에 가려지면 안 맞는다(엄폐는 통한다).

  > **그래서 해킹은 "터렛을 내 편으로 만드는 것"이 아니라 총구를 돌릴 권한을 얻는 것이다.**
  > 겨눠 놓고 그 앞으로 걸어가면 자기가 죽는다. 이 위험이 남아 있어야 **"겨눠 놓고 어떻게 지나갈
  > 것인가"** 가 퍼즐이 된다. 아군 판정을 넣으면 그 긴장이 통째로 사라지고, 터렛은 그냥
  > "켜면 이기는 버튼"이 된다.

  - **"해킹되면 무력화"는 없다.** 해킹 여부는 사격 판정에 **전혀 관여하지 않는다.**
  - 감지 범위 표시(빨강)도 해킹 후에 끄지 않는다 — 끄면 "이제 안전하다"는 거짓 신호가 된다.
  - **빙의 중인 경비병도 쏜다.** 몸이 부서지면 본체로 강제 복귀한다(몸을 잃는 대가는 그대로).
- 상하 조준은 없다(1축). 자동 발사라 높이는 알아서 맞춘다고 본다.

> **왜 빙의에서 외부 조종으로 옮겼나** — 터렛은 시점을 빌릴 이유가 약하다(정찰 가치가 CCTV보다
> 낮고, 이동도 없다). 조준·발사를 1인칭으로 넘기면 조작 규칙이 하나 더 늘어나는 데 비해 얻는 게
> 적다. 외부에서 각도만 돌리게 하면 **레일·프레스와 같은 문법 하나로 통일**되고, 패턴 난이도도
> 외부 조종 기준(5선)이 되어 흐름이 끊기지 않는다.

### 6.3 시점 진입 — 경비병·로봇팔

접속 성공 시 거미가 대상으로 옮겨가 꽂히고 시점이 전환된다. **본체는 그 자리에 남는다.** 두 대상 모두 그 시점에서 **재해킹(릴레이) 가능**하며, 유일한 제한은 **해킹 사거리**다(홉 제한 없음).

**빙의 1인칭 화면 프레임 연출**
- 빙의 1인칭 시점에선 **화면 테두리(프레임)에 파란 실**이 UI 오버레이로 보인다. 그 실이 **부들부들 떨며 화면 가장자리를 안쪽으로 당기는** 모습 → "거미 실에 꿰여 이 몸을 조종 중"이라는 **텐션·장악감**을 프레임으로 표현. 파랑 = 장악(§7).
- **상태 시각 구분 정리**: **외부 조종 = 손↔대상 연결 실**(마리오네트, §6.2) / **빙의 = 화면 테두리 실 텐션**(내가 그 안에 있음). 두 상태가 시각적으로 확실히 갈린다.

**본체 취약 (시점 진입 중)**
- 남겨진 본체는 **취약**하다 — 경비병에게 발각·사격당할 수 있다.
- **조준 경고**: 경비병이 본체를 조준하면 현재 시점 시야 가장자리에 **초록 경고** → 오른쪽 꾹으로 **복귀해 대처**(도망·엄폐) 가능.
- **본체 사망 → 방 단위 즉시 리셋**(§6.4, game over 아님).
- **생명줄 = 하늘색 장악선(§7)**: 빙의 = 해킹 성공이므로 **본체–빙의대상 연결선 색은 하늘색**. 거미는 현재 대상(체인 끝)에 있고, 선은 **본체 → 릴레이 경유 대상들 → 현재 대상**까지 한 줄로 이어진다(대상을 옮겨 다녀도 유지). 이 한 가닥이 **릴레이(홉마다 선이 뻗어나감)** 와 **Q 즉시 복귀(선을 따라 본체로 당겨 귀환)** 를 동시에 정당화한다.
- **본체 자세 = 선을 손으로 꽉 쥔 정지**: 본체엔 **거미가 없으므로**, 본체가 직접 손으로 **하늘색 생명줄을 꽉 붙잡아 앵커**한다 + 옅은 글리치(무방비 + 위치·복귀 표식). "실을 놓지 않고 버틴다 = 언제든 당겨 복귀"가 자세로 읽힘.
- → **몸을 안전한 곳에 두거나 근처 경비병을 치운 뒤 빙의**하는 것이 전략이 된다(은신 삭제 자리의 긴장).

- **경비병(로봇, 1인칭)**: 플레이어와 **완전 동일 조작**(이동·점프·절벽 이동·해킹 다 됨). **왼패널 = 이동**(조이스틱). 용도: 발판 밟기, 못 닿는 버튼 누르기, 정찰, 위치 정리.
- **로봇팔(3인칭 예외)**: 팔꿈치에서 손등을 보는 각도. 팔·손은 **3D 글리치 초록 애니로만**(메쉬 안 보임, 2D 아님). **팔꿈치를 pivot으로 손 방향 회전만**(앞뒤 뻗기 없음). 기본 편 손. **왼패널 = 쥐기 토글**. 손바닥 위치의 플레이어/경비병을 집어 원하는 곳에 놓기.

> **왼패널(원래 조이스틱 자리)은 대상마다 기능이 다르다** — 경비병=이동 / 로봇팔=쥐기. 맥락별 재배치.

**복귀**: 오른엄지로 **오른쪽 꾹 → 본체로 즉시 복귀**(연쇄일 때도 본체로 한 번에).

### 6.4 소프트락 방지

- **원칙: 레벨 디자인으로 예방.**
- **위치 이탈**(경비병을 옮겨둠): 기존 **길찾기(점프 가능)로 원위치 자동 복귀**.
- **사망**(터렛 등에 죽어 필요한 유닛 상실): 진짜 필요한 개체는 **몰래 원위치 리스폰**(안전망).
- **본체 사망**(시점 진입 중 노출된 본체가 죽음): **방 단위 즉시 리셋**.
- **game over는 쓰지 않는다.**

### 6.5 장악·종료·타이머

- **외부 조종 = 1회 장악.** 패턴은 오브젝트당 **한 번만** 푼다. 성공 시 대상이 **파랑(장악, §7)** 이 되고, 이후 **재해킹 없이** 바라보며 조종한다. 조종을 멈추면 파랑으로 남는다 → **"조종 종료" 개념 최소화.** (필요 시 Q = 장악 해제로 초록 복귀, 퍼즐상 불필요하면 생략.)
  - **터렛도 여기 해당한다** — 한 번 장악하면 계속 파랑이고 재해킹 없이 총구를 돌린다. 다만 **사격은 무차별이라 장악해도 나를 쏜다**(§6.2).
- **시점 진입 = Q 복귀**로 종료(한 번에 하나만 빙의, §6.3).
- **조종 타이머 없음.** 이 게임은 퍼즐(§15)이라 인위적 조종 타이머는 사고를 벌준다. 긴장은 **경비병 위협(§2.3)·본체 취약(§6.3)** 이 이미 제공 → 타이머는 이중 처벌.
  - **예외**: 보스 스턴만 n초 + 쿨다운(§11.3).
- **6DoF 드리프트 대응**: 타이머가 아니라 **스냅 격자(§6.2) + graceful degradation(§4.3) + 수 분 재보정(§4.2)** 으로 흡수. ARCore VIO는 가속도계처럼 초 단위로 붕괴하지 않고 분 단위로 완만히 드리프트하므로 통상 조종 길이는 문제없다. 실기 층2(§10-4)에서 재판단하되, 필요 시 **"재해킹 시 기준점 리셋"**(조작 흐름을 안 끊음)을 타이머보다 우선한다.

## 7. 해킹 시각 언어

- 맵 = **흑백**(무채색). **색 언어: 초록 = 해킹 가능 / 밝은 파랑(하늘색) = 해킹 완료(장악) / 진한 파랑 = 목표·경유지 / 빨강 = 위험.** 초록·하늘색 파랑은 **해킹 대상에만**, 빨강은 **위험 범위에만**, 진한 파랑은 **목표 조명에만**.
- **두 파랑 구분(중요)**: 겹치지 않게 **밝기 + 형태** 둘 다로 가른다. **장악 = 밝은 하늘색, 오브젝트 아웃라인·연결 실**(물체 표면). **목표 = 진한 파랑, 공간 볼류메트릭 빛기둥**(바닥·문에서 뻗는 조명). "파랑 = 내 것/가야 할 곳"이라는 정서만 공유, 혼동은 형태로 차단.
- **초록의 의미 재해석**(폐공장·비SF, §0.3): 초록·글리치는 "디지털/전류"가 아니라 **"거미 실이 스며 조작 가능한 부분"** 표식이다. 글리치 톤도 "전류"보다 **"실이 파고들어 기계가 억지로 깨어나는"** 느낌으로 조정(완전 재작업 아님, 기존 셰이더 톤만).
  - **초록** = 아직 안 먹음(해킹 가능). 종류는 색조로 — **진한 청록 = 시점 진입 / 연두 = 외부 조종.**
  - **밝은 파랑/하늘색** = **이미 장악**(내 것). 외부 조종은 1회 장악 후 이 상태로 남는다(§6.5).
  - **빨강** = 위험 범위(경비병 감지). CCTV 스포트라이트는 보류(§6.1).
  - **진한 파랑 = 목표 블루라이트**(DOOM 초록 라이트의 역할). **목표지점 + 가는 길의 중간 경유지**를 안내. 조명 담당 애셋을 쓰되 **애셋 전체가 아니라 "빛을 내는 부분(광원·렌즈)만" 진파랑**으로 색을 갖고 나머지 기구는 무채색. 그리고 **그 빛이 퍼져 밝게 비추며 흑백 주변을 진파랑스럽게 물들인다** — 광원 발광 **+ 스필(퍼진 빛) 둘 다** 흑백의 예외. 어둠 속 진파랑 웅덩이가 **비컨처럼** 멀리서도 "저기가 목표"로 읽힘. 내비게이션은 §14.
  - ⚠️ 실측: 진파랑 스필 강도는 그 구역의 **초록(해킹)·빨강(위험) 가독성을 흐리지 않게** 조절.
- 대상 테두리에 **3가지 정보가 중첩**된다:

| 채널 | 의미 |
| --- | --- |
| **색** | 상태·종류 — 초록(가능: 청록=시점진입 / 연두=외부조종) · **파랑=장악** · 빨강=위험 |
| **테두리 두께** | **거리** — 가까울수록 두꺼움(과하지 않게 클램프), 아주 멀면 매우 얇음. 공통 |
| **글리치 애니** | 사거리 밖 = 정적 / **사거리 안(가능) = 치직치직** / **장악(파랑) = 차분한 정적 발광**(색맹 대비: 초록↔파랑을 움직임으로도 구분) |

- 효과 = **화면공간 2D 외곽선**(3D 물체에 붙지만 플레이어 시점에선 2D). 후처리 엣지 디텍션 방식.
- **하이라이트는 상시 발동** — 화면 안 **모든 해킹 대상**에 테두리가 항상 뜬다(색=종류/상태, 두께=거리, 글리치=사거리 여부). 시선을 줘야 켜지는 게 아니다.
- **사거리 밖** = **정적 테두리로 표시되되**(위치·종류 파악용) **해킹 불가**(치직 애니 없음). **사거리 안** = 치직치직.
- **시선(레티클)으로 조준 중인 대상** = 그 **2D 글리치가 훨씬 격렬하게 지지직**거린다(선택 피드백). 시선은 "무엇을 해킹할지 고르는 것"일 뿐, 하이라이트 자체는 상시다(§2.1).
- **위험 범위 = 빨강** (경비병 감지 범위): **빨간 테두리** + 면적을 **3D 일정 간격 점(dot)** 으로 채워 입체감 있게 확실히 표시. 경비병 감지 = **구 형태**, **벽 투과 안 함**(벽 뒤로 숨으면 안전). 은신 삭제 자리를 메우는 핵심 UI — "어디가 위험한지"를 눈으로.
  - CCTV 스포트라이트는 보류(§6.1)라 지금 위험 범위는 **경비병 하나뿐**이다. 되살리면 같은 빨강 언어를 그대로 쓴다.
  - 1인칭 사각(시야 한계) 표시는 **터렛이 외부 조종으로 바뀌면서 불필요해졌다** — 시점을 빌리는 대상이 경비병·로봇팔뿐이고 둘 다 시야 클램프가 없다.
- 구현: 이식 툴킷 절차적 발광(URP Unlit HDR) + Bloom. 스크롤 노이즈로 치직, 거리 판정으로 두께·정적↔애니 토글. 색맹은 색·두께·움직임 3채널로 구분.

## 8. 이동 (Locomotion)

- **왼엄지 플로팅 조이스틱 = 스무스 이동**(§2.1). 이전 "순간이동 기반" 방침은 폐기하고 조이스틱으로 통일.
- 조종 중에도 이동 가능. 시점 진입 중 이동은 그 대상으로 하며, **경비병은 점프·절벽 이동까지 플레이어와 동일**하다(§6.3).
- Snap Turn(45°) 권장.
- ⚠️ **카드보드에서 스무스 이동은 멀미 위험이 크다** → 실측 필수. 필요 시 비네트·가속 제한 등 완화책 적용.

## 10. 만드는 순서 (검증 우선)

1. **층 1(회전+터치)만으로** 컨트롤러 → 헤드셋 자세 전송 + VR 안 큐브 회전. 지연·좌표계 해결
2. PD 제어로 **로봇팔·레일 캐리어** 조종 (모니터)
3. 해킹 패턴(SYB `HackGrid`) + 초록 하이라이트 + 경비병 1 → **재미 판정**
4. 되면 **6DoF(층 2)** 를 얹는다 — ARCore, position 필드, 그립 설계
5. **빙의·릴레이·연출** 붙이기
6. 카드보드 렌즈·하드보드지 마감

> 1~3(층 1)이 재미없으면 6DoF를 얹어도 무의미하다. 반대로 1~3이 되면 그 자체로 완성 가능한 게임 → 어느 쪽이든 손해 없다.

## 11. 보스 (초거대 로봇)

핵심 볼거리 = **단계적 파괴 연출**. 타협 없이 디테일하게 간다.

### 11.1 3가지 상태

| 상태 | 외형 | 등장 |
| --- | --- | --- |
| **A. 원본** | 완전 구형 머리, 눈알이 사람처럼 적당히 들어감 | 2막 시작 |
| **B. 넙죽이** | 머리 납작하게 눌림, **눈알이 튀어나옴**(카이스트 넙죽이 형태) | 2막 끝 ~ 4막 |
| **C. 완전 찌부** | 완전히 눌린 사망 상태 | 4막 끝 |

- A→B = 2막 **초거대 유압프레스** 1차 압사. B→C = 4막 **초초거대 유압프레스** 2차 압사.

> ⚠️ **아래 표는 §0.4와 충돌한다.** §0.4(2026-07-31 확정)에서 **머리 찌그러짐을 구현하지 않기로** 했다 —
> "그냥 깡 하고 부딪히는 느낌", 마지막도 "깡 내려찍고 보스가 뒤로 넘어감". 3상태 모델 스왑을 어디까지
> 유지할지는 **아직 안 정했다.** 이 표를 근거로 작업하기 전에 §0.4를 먼저 볼 것.

> **📌 초거대 프레스는 별도 프리팹으로 만든다** (아직 착수 안 함, 메모).
> - **일반 `HydraulicPress`의 스케일만 키우면 안 된다.** `strokeMin`/`strokeMax`가 **월드 미터** 기준이라
>   스케일을 키워도 행정이 같이 안 커지고, `_worldPerLocal` 환산 때문에 오히려 어긋난다.
>   크기·행정·속도가 전부 다른 **별개 개체**로 두는 것이 맞다.
> - **압사 판정(CrushZone)이 아직 없다.** 지금은 프레스가 내려와도 아무것도 죽이지 않는다.
>   보스 압사는 §11.1의 **모델 스왑**과 묶여 있어 일반 경비병 압사보다 복잡하다.
> - `Hackable.kind`는 `HydraulicPress`를 그대로 쓰고 보스 전용 동작만 별도 컴포넌트로 얹는다 —
>   열거형 값은 저장된 int라 건드리면 기존 프리팹의 종류가 뒤바뀐다(§HackableKind 경고).

### 11.2 제작 방식

- **부위별 고퀄 생성**(머리·눈알·몸통·팔·다리 분리, 좌우 미러). **전완 = 아이언맨 팔보다 고퀄**인 히어로 파트 → 디테일 집중.
- **눈알은 분리 오브젝트** → 고어 팝아웃 + 리깅에 사용.
- **상태 전환 = 압사 순간 유압프레스가 화면을 가리는 틈에 모델 스왑**(A→B, B→C). 프레스가 가려주니 모프 불필요.
- 리깅은 중립 A-포즈. 스케일이 크므로 §13 부위별 파이프라인으로 밀도 유지.
- 보임: 제어실=전신 / 추격 중=상체만 → **상체 디테일 우선**.
- **메시 분할 범위(확정)**: 자동 분할 결과(머리·눈알·판넬·팔다리·관절 다부품)를 그대로 쓴다. **파이프·전선까지의 세밀 분할은 시간상 안 함.**
- **관절 처리 = 스키닝 대신 "부품 위상차 꺾기"(로봇 연출)**:
  - 팔꿈치 등 관절이 여러 부품으로 나뉜 건 유지하되, **제대로 된 스키닝 변형(부드러운 살덩이 굽힘)은 안 함**(시간·난이도).
  - 관절을 구부리면 메시 **찌그러짐은 용인**한다.
  - 대신 찌그러짐을 연출로 전환 — **관절을 이루는 부품 각각을 서로 다른 타이밍(위상차) + 서로 다른 정도(진폭)로 꺾이게** 하여 "부품들이 제각기 어긋나 움직이는 **기계 관절**" 느낌을 낸다.
  - 구현 힌트: 각 부품을 관절 축의 자식으로 두고 **부품별 오프셋(phase)·배율(multiplier)** 로 회전(스크립트/절차). 제대로 된 스킨 리깅 불필요. 흑백+글리치 톤이라 찌그러짐도 "의도된 기계미"로 읽힘(§12 원칙과 일관).

### 11.3 추격전 보스 해킹 (스턴)

- **2·4막 추격 중 보스를 해킹 가능** — 바라봄 → 드래그 → 점 패턴 → **보스 n초 스턴**.
- **연속 해킹 불가**: 한 번 하면 **쿨다운(일정 시간) 뒤에야** 재가능.
- 사거리 안(초록 하이라이트)에서만. 목적 = 도주·유압프레스 유인 시간 확보.
- 해킹 결과 3종 중 **스턴**(보스 전용) — 조종/빙의와 달리 시점 전환·조종 없음.
- 하이라이트 = 초록 + STUN 표시(색 조정 가능). 수치(스턴 n초·쿨다운)는 튜닝.

## 12. 파괴 연출

### 12.0 규모로 나눈다 (물리 금지 → 조건부 허용으로 정정)

"물리 시뮬 금지"는 **대규모 파괴**를 두고 한 말이다. 규모에 따라 방식이 다르다.

| 규모 | 예 | 방식 |
| --- | --- | --- |
| **소규모** (조각 ~15개) | 경비병 1기 파손 | **런타임 리지드바디 허용.** 단순 콜라이더(박스·캡슐·convex)면 최신 모바일에서 충분히 싸다 |
| **대규모 setpiece** (수십~수백) | 2·4막 벽·구조물 붕괴 | **물리 베이크** — 에디터에서 물리를 한 번 돌려 트랜스폼을 `AnimationClip`으로 굽고(`UnityEditor.Animations.GameObjectRecorder`), 런타임엔 재생만 |

**베이크가 유리한 이유**는 성능만이 아니다. 결과가 **항상 동일**해서 컷 타이밍(§11.2 모델 스왑)이 프레임 단위로 고정된다. 에디터에서 고품질로 뽑아 저장할 수도 있다.
베이크의 약점("플레이어와 상호작용 불가")은 **애초에 상호작용을 안 하기로 했으므로 손해가 아니다**(아래 충돌 규칙).

> ⚠️ **베이크는 물리 비용만 없앤다. 렌더 비용은 그대로다.** 조각 200개면 드로우콜·그림자 200개는 그대로이고,
> **VR에서 2배가 되는 쪽이 렌더링**이다. 대규모의 진짜 병목은 물리가 아니라 렌더 → 조각 수 상한·빠른 despawn·배칭으로만 잡힌다.
> 레벨 지오메트리를 고치면 구운 결과가 어긋나므로 **레벨 확정 후 굽는다**.

### 12.1 잔해 충돌 규칙 (공통)

- **플레이어와 충돌하지 않는다. 지형과만 충돌하고 중력으로 떨어진다.** 잔해 전용 레이어 + Physics 충돌 매트릭스로 처리.
- 이유: 잔해가 플레이어를 밀거나 끼우면 조작이 망가진다. 위협은 §6.1의 기믹(프레스 등)이 담당한다.

### 12.2 기타

- **흑백+글리치 스타일** 덕에 단순 잔해도 "의도된 연출"로 읽힘 → 싸게 만들어도 티 안 남.
- 되돌아가는 길 = **1막 지오메트리 재사용**. 4막 새 길 = 파괴로 여는 **대체 루트**(미리 배치).
- ⚠️ 조각 수 제한 + 빠른 despawn + 배칭/GPU 파티클 (드로우콜·파티클 폭주 방지).
- **4막 오프닝 반전**(옆벽 파괴 → 구조물 투척 → 컷신 자동 회피 → 반대벽 파괴 → 새 길)은 전부 **스크립트 setpiece**.

## 14. 레벨 구조 — 아레나·복도

- **용어**: **아레나 = 퍼즐 구간**, **복도 = 아레나 사이를 잇는 통과 구간**.
- **흐름**: 복도 통과 → 아레나 진입 시 **뒤 게이트가 닫혀 가둠** → 그 아레나의 퍼즐(기믹 조종·빙의로 길 만들기)을 풀면 **앞 게이트가 열림** → 다음 복도.
- **아레나 클리어 조건 = 퍼즐 해결**(목표 지점 도달/장치 작동). (이식 소스는 "웨이브 전멸"이었으나 MINDHEXER는 퍼즐로 교체.)
- **게이트** = 기계식 슬라이드 문(공장 무드). **소프트락** 시 아레나 단위로 즉시 리셋(§6.4).
- **이식 연결**: `ArenaRoom`(가둠/해제·현재 아레나 추적)·`ArenaGate`(문)·`ArenaAssemblyTool`(마스터 씬 `Level_Main`에 아레나 프리팹을 이어붙임). 테스트 씬 `Arena_test.unity`. 상세 [이식_환경.md](이식_환경.md).
- 4막 스토리(§0.2)는 이 **아레나-복도 타일 위에** 얹힌다. 3막 복귀·4막 새 길 = 1막 지오메트리 재사용/대체 루트(§12).
- **내비게이션 = 진한 파랑 블루라이트(§7)**: 목표지점과 **가는 길의 중간 경유지**를 빛기둥으로 안내(DOOM 초록 라이트 역할). 흑백 맵의 조명 예외.
  - **시작 = 탈출 지점**: 시작하는 공장 가장자리 **breach(뜯긴 환풍구·격자)** 에 블루라이트 → "여기로 들어왔고 여기로 나간다"를 각인. 진입 시 뒤 게이트가 닫혀(§14 흐름) "돌아와야 나간다"를 몸으로 학습. 3막 복귀 목표도 이 블루라이트.
  - **4막 반전과 정합**: 3막에 A(원래 탈출구, 블루라이트)를 **눈앞까지** 데려간 뒤 → 보스가 옆벽 부수며 등장해 **A를 막음** → 보스 투척이 **반대편 벽을 부숴 새 길 B**를 엶 → **블루라이트가 B로 옮겨/새로 켜져** 재유도(반전 중 길 안 잃음). A·B 둘 다 "바깥"을 향해 방향 일관. "저 입구로 나간다"는 밑밥 → **통쾌한 배신**(§0.2·§12).

## 16. 사망·추격 연출

### 16.1 보스 추격 연출 (2·4막)

- 보스가 **좁은 통로를 부수며 추격.** 머리가 커서 앞 지형지물을 파괴하고, **양팔로 옆벽을 짚으며** 전진.
- **팔 벽 짚기 = 절차적 IK**: 2본 IK로 손 타겟을 **옆벽 앞쪽 멀리**에 잡고 좌우 팔을 번갈아 짚음. 외부 패키지 없이 자체 솔버(`BossArmRig`)로 구현했다.
- ⚠️ **짚는 곳 파괴는 폐기**(2026-07-30). 손이 닿을 때마다 벽 조각을 부수는 것은 만들 비용 대비 얻는 게 적다. **정면에 있는 것을 부수며 오는 것만 남긴다**(아래).
- **정면 파괴만 남긴다** — 보스가 지나가는 **앞쪽 장애물**을 부순다. 이것이 유일하게 남은 파괴 연출이다.
  **물리 베이크로 굽는다**(§12.0): 에디터에서 물리를 한 번 돌려 조각 트랜스폼을 `AnimationClip`으로 굽고 런타임엔 재생만 한다. 결과가 항상 같아 타이밍이 프레임 단위로 고정된다.
- **연출**: 화면 흔들림(이식 `CombatFeedback`의 Cinemachine Impulse) + 파괴 VFX(이식 `VfxLibrary`) + 굉음(이식 `CombatAudio`).
- ⚠️ **VR 멀미**: 화면 흔들림은 VR에서 강한 멀미 → **PC 단계만 그대로**, VR 단계엔 **카메라 말고 보스·파편을 흔들거나** 짧고 약하게·비네트로 완화.

### 16.2 사망 시스템 — **연출 하나로 통일** (2026-07-30 개정)

**원인이 무엇이든 같은 연출을 쓴다.** 보스·터렛·경비병 전부 동일하다.

```
암전  →  1초  →  죽인 대상의 정면 클로즈업 팍  →  치지직  →  방 단위 리셋
```

- 사인(死因)만 클로즈업으로 갈아 끼우면 되므로 **연출을 하나만 만들면 된다.** 사망 종류가 늘어도 추가 작업이 없다.
- 1인칭이라 **암전이 실제 사망 순간을 가려 준다**(고어 모델 불필요). game over 화면은 없다(§6.4).
- 이식한 `DeathScreen`·`ScreenFx`·`CutsceneDirector`·`CombatAudio` 재활용.

**폐기된 것**: 보스 사망의 "양팔 IK로 카메라를 감싸 찌부"(Poppy Playtime식)는 **구현하지 않기로 확정**했다. 팔 IK로 카메라를 감싸는 연출은 비용에 비해 얻는 게 적고, 위 통일 연출로 충분하다. 그래서 `BossChase`에도 잡기(catch) 판정이 없다.

| 사망 | 클로즈업에 쓰는 대상 | 비고 |
| --- | --- | --- |
| **보스** | 보스 얼굴 | 2막 추격 |
| **터렛** | 터렛 총구/헤드 | |
| **경비병** | 경비병 얼굴 | |
| **낙사** | (클로즈업 없음) | 급강하 짧게 + 낙하음 → 암전 → 마지막 안전지점 리셋 |
| ~~**CCTV**~~ (보류 §6.1) | CCTV 렌즈 | 되살릴 때 같은 파이프라인에 얹으면 된다 |

- ⚠️ **VR 멀미**: 사망 중 **카메라 흔들기·강제 회전 금지.** 카메라는 고정하고 대상이 다가오게, 빠르게 암전으로 끝낸다.
- 미정: 클로즈업 지속 시간, 치지직 길이, 정면샷을 실시간 카메라로 잡을지 미리 만든 이미지로 갈지.
