# MINDHEXER 기초 설계안 (KJH 초안)

> KJH 개인 문서. 상태: **초안**. shared 승격 전.
> 팀원(SYB) 통신 스캐폴드(`docs/SYB/SPEC.md` v3)와 정합이 필요한 항목은 §5·§9에 명시한다.
> 수치는 전부 **출발점**이며 실측·튜닝 대상이다.

---

## 0. 게임 정의와 컨셉

> 폰 2대(S24+ 카드보드 HMD + S10e 컨트롤러)로 하는 **VR 침투 해킹 퍼즐 게임.**
> **컨트롤러(폰)로 공장 안의 기계·지형지물을 해킹·조종해, 없던 길을 만들어 목표 지점에 도달하는 것이 게임의 본체다.**

### 0.1 무대와 목표

초거대 로봇을 연구·생산하는 공장. 주인공은 침투해 **공장을 무력화**한다.

### 0.2 흐름 — 2막 구조

- **1막 (침투 퍼즐)**: 해킹으로 **지형지물을 조종**하고 **경비병에 빙의**하며 퍼즐을 풀어, 초거대로봇 제작 메인 장소에 도달한다. **메인은 3D 맵 공간 조작 퍼즐**이다.
- **2막 (추격 클라이맥스)**: 제어실 버튼을 누르면 초거대로봇이 각성해 추격한다. 빠른 해킹 + 이동으로 도주, 마지막에 **초거대 유압프레스로 추격 로봇을 압사**시킨다(파피 플레이타임1 처치 방식).

### 0.3 핵심

- **핵심 동사 = 해킹.** 해킹으로 기계(레일 캐리어·갠트리·로봇팔·유압프레스·터렛·CCTV)를 **조종**하고, 경비병을 **빙의/살해/이용**한다.
- **은신·드론은 삭제.** 플레이어는 항상 노출되며 경비병은 **상시 위협**이다. 긴장은 "경비병을 처리·회피하며 필요한 기믹을 조종해 길을 뚫는" 데서 나온다.

## 2. 핵심 게임 루프 & 조작

> **공장 기계를 해킹·조종해 길을 만들고 경비병을 처리하며 목표로 전진한다.**

- 플레이어는 **항상 노출**된다(은신 없음).
- 경비병은 사거리·시야 안 플레이어를 조준 → n초 후 발사 → 사살하는 **상시 위협**이다(§2.3).
- 해킹은 **시간·주의를 점유**한다: 패턴 푸는 동안 정지, 조종 중엔 이동 가능.
- 따라서 판단은 "경비병 사거리 안에서 해킹을 감행할 것인가, 먼저 경비병을 (기믹으로) 치우고 안전하게 해킹할 것인가"이다.

### 2.1 조작 스킴

- **파지**: 폰을 **가로로 양손 파지**(브롤스타즈 등 일반 모바일 게임 자세).
- **왼손 엄지 — 이동**: **플로팅 조이스틱**(처음 터치한 지점이 중심).
- **오른손 엄지**:
  - 짧은 **탭 = 점프**
  - **드래그 = 해킹 패턴**
  - **오른쪽을 꾹(정지) = 빙의 해제·본체 복귀**
  - 구분: 탭=짧게 / 드래그=움직임 있음 / 복귀=오른쪽 영역을 움직임 없이 유지(오발동 방지 위해 살짝 길게). 실측 튜닝.
- **대상 지정** = HMD 머리 시선(head gaze) Raycast. 콜라이더는 모델보다 넉넉하게.

### 2.2 해킹 흐름 (펫 거미)

플레이어는 신적 존재가 아니라 **오른손 위 애완 거미(펫)** 로 해킹한다.

- **흐름**: 대상 바라봄 → 오른엄지 드래그 → 거미가 줄을 순식간에 뽑아 대상에 꽂음 **+ 점 패턴 즉시 등장(병렬)** → 패턴 풀면 성공.
- **모든 해킹 = 점 패턴 통일**(조종·빙의 공통). 시도 즉시 패턴이 뜨므로 대기 시간이 없다.
- **사거리 = 초록 하이라이트로 즉시 판정**(§7). 사거리 밖 대상은 하이라이트되지 않아 시도 자체가 안 됨 → 거미 낙하·귀환 로직 불필요.

접속 성공 시 종류별 연출:

| 종류 | 연출 |
| --- | --- |
| **조종형** (레일·갠트리·로봇팔·프레스·터렛·CCTV) | 줄 **퐉** 꽂음 → 반짝 → 패턴 → 조종(폰 6DoF) |
| **빙의형** (경비병·로봇손) | 줄 **톡** 꽂음 → 대상 **스턴·찌직**(= 패턴 푸는 시간의 연출) → 성공 시 거미가 대상으로 날아가 붙음 → 화면 **초록 지직 + 암전** → **경비병 1인칭 전환**(그 몸도 손에 거미를 들고 줄이 꽂혀 빛남 = 조종 중 표시) |

- 조종 단계는 §6(PD 제어). ⚠️ 왼엄지 조이스틱 + 폰 모션 동시 파지의 부담은 실측 필요.

### 2.3 경비병 위협 모델

- 경비병은 **감지 범위 + 시야**를 가진다. 은신이 없으므로 범위·시야 안에 들면 **항상 감지**한다.
- 감지하면 → **멈춰서 조준 → n초 후 발사 → 명중 시 사살**(n = 튜닝값).
- 회피 = 사거리·시야 밖으로 **이동**, 엄폐, 또는 경비병 **제거**(로봇팔·터렛·유압프레스)·**빙의로 치우기**.
- 패턴 푸는 동안 정지하므로 사거리 안이면 그대로 맞는다 → 해킹은 경비병 없는 위치에서 하는 것이 원칙.
- (미정) 조준 후 시야 이탈 시 해제 여부, 발사 전 취소 가능 여부 → 실측.

## 3. 컨트롤러 입력 능력과 한계 (설계의 물리적 전제)

컨트롤러로 무엇을 잡을 수 있고 없는지가 조작 설계 전체를 규정한다. **DoF(자유도)** 로 정리한다.

| 입력 | 어떻게 잡나 | 됨? | 원리 |
|---|---|---|---|
| **회전** (기울임·도리질·갸웃) | 자이로 (3DoF) | ✅ | 적분 1번이라 안정. 카메라 불필요 |
| **터치 / 스와이프** | 터치스크린 | ✅ | 자명 |
| **임펄스** (휙 휘두른 세기) | 가속도계 | ✅ | 짧은 윈도우 1번 적분. ZUPT로 리셋 |
| **절대 위치** (앞으로 30cm 밀기) | **VIO(카메라+IMU) 필요** | 조건부 | 가속도 2번 적분은 몇 초면 붕괴. 카메라로 바깥을 봐야 앎 |

**핵심 사실**: 가속도만으로는 위치를 못 잡는다(두 번 적분 → 오차가 시간 제곱으로 폭발). 위치는 카메라로 실제 세상 특징점을 보고 자기 이동을 역산하는 VIO가 필요하다.

## 4. 6DoF 결정 — 채택 (위치 조작 필요)

**결정**: 컨트롤러의 **6DoF(위치 포함) 추적을 채택**한다. 위치는 ARCore VIO로 얻는다.

**근거**: "폰을 실제로 움직여 물체를 그만큼 이동"이 재미의 필수 요소. 회전만으로는 물체 조종의 공간감이 나오지 않는다.

### 4.1 SYB SPEC v3와의 차이

SYB 통신 명세는 "6DoF/VIO 폐기"로 적혀 있다. 이 설계안은 그것을 뒤집어 6DoF를 복원한다. 대립이 아니라 아직 확정 안 된 게임 디자인을 여기서 정하는 것이다. 다만 6DoF 복원은 통신·컨트롤러 앱 변경을 요구(§5)하므로 **SYB 합의가 전제**다. 상세는 [../decisions/0001-6dof-controller-tracking.md](../decisions/0001-6dof-controller-tracking.md).

### 4.2 6DoF의 대가

| 문제 | 대응 |
|---|---|
| **카메라 가림** (손가락이 후면 카메라 → 추적 끊김, SW 해결 불가) | **그립 형상 설계** |
| **환경 조건** (저조도·단색 흰 벽 실패) | 시연 공간을 밝고 무늬 있게 |
| **발열** (카메라+VIO 상시) | 통풍 + 세션 시간 제한 |
| **드리프트** (수 분 누적) | 수 분마다 재보정 |
| **좌표계 분리** (두 폰 원점 무관) | 수동 캘리브레이션 정렬 |
| **빠른 동작** (모션 블러) | 빠른 휘두르기를 핵심 조작으로 안 삼기 |

### 4.3 층 구조 — 3DoF 위에 6DoF를 얹는다

- **층 1 — 3DoF (회전 + 터치 + 임펄스)**: 항상 동작. 저발열·저지연·카메라 불필요.
- **층 2 — 6DoF (위치)**: VIO 필요.
- **Graceful degradation**: 층 2가 깨지면 층 1로 자동 강등("연결 품질 저하" 연출). 층 1만으로도 물체 조종이 성립하도록 먼저 만든다.

## 5. 프로토콜에 미치는 영향 (SYB 협의 필수)

6DoF를 쓰면 컨트롤러가 **위치(position)** 를 함께 보내야 한다. 현재 공유 `InputPacket`에 위치 필드가 없다.

- 현재 `InputPacket` = 60바이트. `Position(float×3)` **+12바이트 → 72바이트**.
- `shared/com.mindhexer.shared`에서만 변경(양쪽 자동 반영). `PacketSerializer`·`NETWORK_PROTOCOL.md`·`ProtocolVersion` 동시 갱신.
- 컨트롤러 앱: ARCore(VIO) 세션 구동 → 카메라 상시 동작. 현재 `TouchGyroCapture`에 없는 부하.

> 근본 비용은 몇 바이트가 아니라 **컨트롤러 앱에 VIO 파이프라인 전체가 얹히는 것**이다. SYB와 스코프 합의 선행.

## 6. 해킹 대상 & 조종

### 6.1 대상 로스터

**조종 (연두 하이라이트, §7)**

| 대상 | 용도 |
| --- | --- |
| **레일 캐리어** | 레일 위 1D 이동. **레일을 레벨마다 임의 방향 배치**(벽 세로=옆면 위아래 / 바닥 / 천장 / 대각·꺾임) → "방향 상관없이 전부" 커버 |
| **다축 갠트리** | 상자 공간 안 **XYZ 자유 이동** |
| **로봇팔** | 지형지물 이동해 **길 만들기**, 경비병 살해 가능 |
| **유압프레스** | **경비병 압사**, 2막 추격 로봇 처치. (조종 방법 미확정) |
| **터렛** | 경비병 **사격 살해**, 방향 조종. (미확정) |
| **CCTV** | 정찰/시야 확보. (미확정) |

**빙의 (진한 청록 하이라이트, §7)** — 경비병(로봇): §6.3.

### 6.2 조종 매핑 & 구동

- **레일 캐리어**: 폰을 레일 방향으로 기울임 → 그쪽 이동(기울기 크기 = 속도). 벽 세로 레일이면 앞뒤 기울임이 곧 위아래 이동.
- **다축 갠트리**: 폰 XY 기울임 = 트롤리 XY, 상하 밀기(6DoF)/상하 스와이프 = 승강(Z). 6DoF의 진가가 나오는 대상.
- **로봇팔**: 자이로 회전 = 손목 자세, 넓은 터치 = 쥐기, 상하 스와이프 = 팔 높이, 위치 밀기 = 이동.
- **구동 = PD 제어**: `torque = Kp*error - Kd*angularVelocity`. 물체별 Kp/Kd로 "무게"(갠트리 무겁게 Kd↑ / 캐리어 경쾌).
- **힘·토크 계산은 전부 S24+.** 컨트롤러는 자기 자세·위치·터치만 안다(SSOT = 헤드셋).
- 미확정: 유압프레스·터렛·CCTV 조종 세부.

### 6.3 빙의 & 릴레이

- 경비병 접속 성공 → 거미가 **그 몸으로 옮겨가 손에 꽂힘** → **본체는 그 자리에 남고** 시점이 경비병 1인칭으로 전환.
- 빙의로 할 수 있는 것: 발판 밟기 / 플레이어가 못 닿는 **버튼 누르기** / 지형 **정찰** / 경비병을 **멀리 이동**시켜 길 정리.
- **제약**: 빙의 중 **점프 불가**, **절벽 쪽 이동 불가**.
- **릴레이**: 거미가 빙의한 몸에 있으므로 그 몸에서 **다시 해킹 가능** → 사거리를 릴레이로 확장(본체 → 경비병A → 경비병B …). "신호" 설정 없이 물리적으로 성립.
- **복귀**: 오른엄지로 **오른쪽 꾹 → 본체로 즉시 복귀**(연쇄일 때도 본체로 한 번에).
- 미정: 릴레이 홉 제한, 본체만 할 수 있는 것(릴레이가 게임을 대신 못 하게).

## 7. 해킹 시각 언어

- 맵 = **흑백**(무채색). 강조색 = **초록 계열 = 해킹**. 강조색은 **해킹 대상에만**(+ 2막 경고색 1개까지).
- 대상 테두리에 **3가지 정보가 중첩**된다:

| 채널 | 의미 |
| --- | --- |
| **색** | 종류 — **진한 청록 = 빙의 / 연두 = 조종** |
| **테두리 두께** | **거리** — 가까울수록 두꺼움(과하지 않게 클램프), 아주 멀면 매우 얇음. 두 색 공통 |
| **글리치 애니** | 사거리 밖 = 정적 테두리 / **사거리 안 = 치직치직**(전류·글리치처럼 흐르고 튐) |

- 효과 = **화면공간 2D 외곽선**(3D 물체에 붙지만 플레이어 시점에선 2D). 후처리 엣지 디텍션 방식.
- 사거리 밖은 하이라이트되지 않음 → 해킹 시도 불가.
- 구현: 이식 툴킷 절차적 발광(URP Unlit HDR) + Bloom. 스크롤 노이즈로 치직, 거리 판정으로 두께·정적↔애니 토글. 색맹은 색·두께·움직임 3채널로 구분.

## 8. 이동 (Locomotion)

- **왼엄지 플로팅 조이스틱 = 스무스 이동**(§2.1). 이전 "순간이동 기반" 방침은 폐기하고 조이스틱으로 통일.
- 조종 중에도 이동 가능. 빙의 중 이동은 경비병 몸으로(점프·절벽 불가).
- Snap Turn(45°) 권장.
- ⚠️ **카드보드에서 스무스 이동은 멀미 위험이 크다** → 실측 필수. 필요 시 비네트·가속 제한 등 완화책 적용.

## 10. 만드는 순서 (검증 우선)

1. **층 1(회전+터치)만으로** 컨트롤러 → 헤드셋 자세 전송 + VR 안 큐브 회전. 지연·좌표계 해결
2. PD 제어로 **로봇팔·레일 캐리어** 조종 (모니터)
3. 해킹 패턴(SYB `HackGrid`) + 초록 하이라이트 + 경비병 1 → **재미 판정**
4. 되면 **6DoF(층 2)** 를 얹는다 — ARCore, position 필드, 그립 설계
5. **빙의·릴레이·연출** 붙이기
6. 카드보드 렌즈·하드보드지 마감

> 1~3(층 1)이 재미없으면 6DoF를 얹어도 무의미하다. 반대로 1~3이 되면 그 자체로 완성 가능한 게임 → 어느 쪽이든 손해 없다.
