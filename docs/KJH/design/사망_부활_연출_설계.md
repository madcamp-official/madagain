# 사망·부활 연출 설계

> KJH 개인 문서. 상태: **확정(§7 미결 3건 제외)**. 2026-07-30.
> 관련: [기초_설계안.md](기초_설계안.md) §16(사망·VR 멀미) · [보스전_설계.md](보스전_설계.md) §1
>
> 이 문서는 기초_설계안 §16의 사망 연출을 **대체한다** — "암전 → 클로즈업 → 치지직"에서
> "암전 → 하얀 가로선 → 암전 → 기상"으로 바뀌었다.

---

## 0. 결정 요약

- 사망 연출은 **원인 무관 하나로 통일**한다(프레스·보스·낙사 전부 같은 연출).
- **죽인 대상 클로즈업은 폐기.** 대신 하얀 가로선 한 번.
- **부활 카메라 연출 = 게임 시작 인트로 연출.** 같은 컴포넌트를 재사용한다 —
  "눈을 뜬다"는 동작이 두 곳에서 같아야 하고, 두 벌 만들면 반드시 어긋난다.

## 1. 시퀀스

```
t = 0.00   사망 확정. 입력 동결. 즉시 암전
           ★ 이 순간 리셋 — 화면이 완전히 검으니 순간이동이 안 보인다
0.00~1.50  암전 유지
1.50~1.70  치지직 아주 크게. 이 구간에서 검정이 걷힌다 — 치지직 사이로 세상이 돌아온다
     1.70  기상 시작
```

기상은 치지직과 겹쳐 시작한다. 총 **1.5초**.

```
기상 t = 0.00~0.85  바닥에 쓰러진 채 좌우로 휘청. 높이는 그대로 −0.9m
                    "흔들.. 흔들.." — 흔들림 2회 + 롤 7°
     0.85~1.50  비스듬히 쭈욱 상승. 눈높이·시선(PC)이 기본으로,
                기울기는 중간에 최대(12°)를 찍고 다 올라오면 0으로 풀린다
          1.50  정면 도달
     1.50~ +    팔이 올라온다(꼬리. armDelay·armRiseTime으로 조절)
```

숫자는 전부 인스펙터 값이다. **실측으로 잡아야 한다** — 여기 적힌 것은 시작점일 뿐이다.

> 팔 올림은 기상 1.5초의 **뒤에 붙는 꼬리**다. `armDelay = 0`으로 두면 상승과 겹쳐서
> 총 길이가 1.5초에 가깝게 유지된다.

## 2. 화면 덮개 (`ScreenVeil`)

암전과 하얀 가로선을 그리는 것. **캔버스를 쓰지 않는다.**

### 왜 캔버스가 아닌가

`PossessionTransition`이 쓰는 `ScreenSpaceOverlay` 캔버스는 **VR 스테레오에서 보이지 않는다**(확인된 결함).
`VrStatsHud`가 같은 이유로 월드 스페이스 `TextMesh`를 쓴다. 그래서 덮개도 **카메라 자식 쿼드**다.

### 어느 카메라에 붙이는가 — 여기가 함정이다

`ViewmodelCamera`가 팔을 **별도 카메라**로 그린다.

```
[Main Camera]     depth = d      ← 세상
[ViewmodelCam]    depth = d + 1  ← 팔만(Viewmodel 레이어), clearFlags = Depth
```

`depth`가 큰 쪽이 나중에 그린다. 그래서 **메인 카메라에 덮개를 붙이면 팔이 덮개 위에 그려진다.**
덮개는 **마지막에 그리는 카메라**에 붙이고, 그 카메라가 보는 레이어에 둬야 한다.

전용 카메라를 하나 더 두는 방법도 있지만 **쓰지 않는다** — 모바일 VR에서 카메라 하나는 렌더 패스
하나이고, 이미 S24+에서 35fps까지 떨어진 적이 있다(ADR-0007). 쿼드 하나 그리려고 패스를 늘릴 이유가 없다.

### 구성

- 카메라 자식 쿼드 2장: **검정**(전체 덮음) + **하얀 선**(가로 막대)
- Unlit, `ZWrite off`, `ZTest Always` — 무엇이 앞에 있든 덮는다
- 근평면 바로 앞에 두고, 카메라 FOV로 크기를 계산해 화면을 정확히 채운다
- 뷰모델 카메라가 없으면 메인 카메라로 폴백한다

### 치지직 — 기존 셰이더를 그대로 쓴다

`MINDHEXER/HackGlitch`를 재사용한다. **해킹 대상에 걸리는 치지직과 같은 룩**이어야 게임이
한 덩어리로 읽힌다. 새로 만들지 않는다.

그 셰이더의 성질이 여기에 딱 맞는다.

- **강도 = 켜진 가로선의 개수**다. 알파를 흐리는 게 아니라 몇 개가 켜질지를 바꾼다.
  그래서 강도를 올리면 "선이 흐릿해짐"이 아니라 "선이 많아짐"으로 읽힌다.
- 가로줄 밴딩(VHS/CRT 스캔 노이즈) + 이따금 옆으로 튀는 트래킹 에러.
- UV를 안 쓰고 월드 좌표로 패턴을 만든다(Tripo 메시 UV가 못 쓰는 상태라 그렇게 만들어졌다).
  덮개는 카메라에 붙어 있고 사망 중엔 플레이어가 멈춰 있으므로 문제되지 않는다.

| 값 | 기본 | 뜻 |
|---|---|---|
| `glitchPeak` | 1.0 | 최대 강도 |
| `glitchColor` | 흰색 | 프로젝트 기본은 인광 초록. 사망은 흰색으로 둔다 |
| `glitchRows` | 220 | 가로줄 밀도 |
| `glitchScrollSpeed` | 30 | 줄 갱신 속도. 기본 18보다 올려 더 격렬하게 |
| `blackClearAt` | 0.5 | 치지직 절반쯤에 검정이 완전히 걷힌다 |

## 3. 기상 연출 — **아주 높은 곳에서의 착지** (`WakeUpSequence`)

실제로 떨어지지는 않는다. **착지 순간부터**를 보여 준다. 총 **0.8초 이내의 짧은 컷**이다.

### 3.0 기존 착지를 재사용할 수 없는 이유

`MotionFeel.OnLand`는 **평범한 점프 착지용**으로 튜닝돼 있다.

| 값 | 실제 | 높은 곳 착지에 필요한 것 |
|---|---|---|
| `landDipMax` | **0.22m 상한** | 1.0m 내외 |
| `landRollDeg` | 2.5° | 8~12° |
| `landDuration` | 0.3s, **단조 곡선** | 눌린 채 **머무는 구간**이 있어야 함 |

상한 22cm·롤 2.5°는 2m 점프용 수치다. 그걸 배율로 키워도 **머무는 구간이 없어** 트램폴린처럼 튄다.
그래서 별도로 만든다.

### 3.1 핵심 — 착지는 곡선 하나가 아니라 4단이고, 3단에서 성질이 바뀐다

```
① 충격    0.00 ~ 0.04s   순간. 머리가 관성으로 급강하 + 고주파 흔들림 + FOV 펀치
② 눌림    0.04 ~ 0.16s   최저점에서 머문다. ★ 이 hold가 무게를 만든다
③ 복귀    0.16 ~ 0.50s   다리를 펴며 올라온다. 여기서 스프링으로 인계
④ 정착    0.50 ~ 0.80s   2차 진동이 잦아든다
```

**곡선 → 스프링 인계가 이 설계의 핵심이다.**

- **스프링은 hold를 만들 수 없다.** 목표를 주면 곧장 그리로 간다. ②의 "눌린 채 잠깐 멈춤"은
  손으로 잡은 곡선만 만들 수 있다. 스프링 하나로 하면 무게가 사라진다(지난 시도가 그랬다).
- **곡선은 자연스러운 잔여 진동을 만들 수 없다.** ④의 미세 흔들림을 키프레임으로 잡으면
  프레임률에 따라 성격이 변하고 손으로 잡을 양이 많다.

그래서 ①② 구간은 곡선이 침하를 직접 지정하고, ③ 진입 시점에 **그 순간의 값·속도를 스프링에
넘겨준다**(`SnapTo` + 목표 0). 이후는 스프링이 알아서 튀어 오르고 정착한다.

### 3.2 레이어 7개

| # | 레이어 | 채널 | 값(시작점) |
|---|---|---|---|
| 1 | 수직 침하 | `MotionFeel.ExternalPosOffset.y` | 최저 **−1.0m** |
| 2 | 고주파 흔들림 | 같은 채널 x·y·z | ①에서만. 0.06s, 진폭 0.05m, 감쇠 |
| 3 | 롤 킥 | `MotionFeel.ExternalRoll` | **10°**, 감쇠 진동 2회 — 한쪽 발이 먼저 닿는다 |
| 4 | FOV 펀치 | `MotionFeel.ExternalFovOffset` | **+8°**, 0.25s 복귀 |
| 5 | 시선 | `MouseLook.SetLook` | ①에 아래 **30°** → ③에서 정면. 고개는 몸보다 늦게 |
| 6 | 눈꺼풀 | `ScreenVeil.eyelidOpen` | 충격과 동시에 번쩍(0.1s) → 한 번 찡그림 → 뜸 |
| 7 | 팔 | 뷰모델 루트 y | ②에서 화면 안으로 짚고 ③에서 빠진다 |

### 3.3 왜 `ExternalPosOffset`인가 — VR 처리가 공짜로 따라온다

| 레이어 | VR | 어떻게 |
|---|---|---|
| 1·2 침하·흔들림 | **자동 25%** | `ExternalPosOffset`이 `vrPositionScale`(기본 0.25)을 탄다 |
| 3 롤 | **자동 제거** | `ExternalRoll`이 `vrRollScale`(기본 0)을 탄다 |
| 4 FOV 펀치 | **직접 0으로** | VR에서 FOV를 건드리면 렌즈 왜곡과 안 맞아 멀미가 심하다 |
| 5 시선 | 없음 | VR엔 `MouseLook`이 없어 자동으로 빠진다 |
| 6·7 눈꺼풀·팔 | 그대로 | 화면·손은 멀미와 무관 |

수직 가속은 VR 멀미의 주범이다. `VrTuning.SetWakeOffset`에는 이 축소가 없으므로 **침하는
`ExternalPosOffset`으로 넣어야 한다** — 지난 구현이 틀린 지점이다.

### 3.4 지금 없는 것 (높이를 전달하는 데 큰 몫)

- **먼지·파편 파티클 없음.** 발밑에서 퍼지는 먼지가 높이를 가장 직관적으로 전달한다.
- **착지 사운드 없음.** 있는 건 살점 타격음과 검 소리뿐이다. 소리는 시각보다 높이를 잘 전달한다.
- **충격 화면 왜곡 없음.** `RadialInvert`는 예측정지 전용 URP RendererFeature라 재사용하려면
  그쪽을 손대야 한다.

→ 카메라와 화면만으로 먼저 만들고, 위 셋은 자산이 생긴 뒤에 얹는다. **셋 다 없으면 "높은 곳"이
카메라 진폭만으로 표현되므로, 진폭을 과하게 키우고 싶어지는 것을 경계해야 한다.**

## 3.5 기상 연출 공통 사항

### VR에서는 시선을 강제할 수 없다 — 이게 설계를 갈랐다

VR은 머리 회전이 HMD에서 온다(`TrackedPoseDriver`, `RotationOnly`). 코드가 회전을 써도
**다음 프레임에 HMD가 이긴다.** 게다가 기초_설계안 §16.2가 **VR 멀미 때문에 카메라 강제 회전을 금지**한다.

| 요소 | PC | VR |
|---|---|---|
| 눈높이 오프셋(낮은 자리 → 기본) | ○ | ○ |
| 좌우 위치 흔들림 | ○ | ○ |
| **롤**(휘청임·비스듬한 상승) | ○ | **✗ — `vrRollScale` 기본 0** |
| 바닥 → 정면 시선 회전 | ○ | **✗ — 플레이어가 알아서 본다** |

VR에서는 "낮게 쓰러진 자리에서 좌우로 밀리며 일어선다"만 남는다. 롤과 시선을 안 건드리는 쪽이
오히려 "내가 일어나는" 느낌이 강하고 멀미도 없다.

### 소유권 — 남의 값을 직접 쓰지 않는다

| 무엇 | 소유자 | 기상이 하는 일 |
|---|---|---|
| 시점 회전 | `MouseLook` (유일) | `MouseLook.SetLook(yaw, pitch)`로 **부탁한다** |
| 눈높이·좌우 오프셋 | `VrTuning` (`[Head]` 로컬) | `SetWakeOffset(offset)`으로 **부탁한다** |
| 롤 | `MotionFeel` | `MotionFeel.ExternalRoll`에 대입한다 |
| 팔 | 뷰모델 루트 | 루트 로컬 y 오프셋 |

롤을 `MotionFeel`에 넣는 이유가 중요하다. 롤은 리그 배치에 따라 `MotionFeel`이 직접 적용하거나
(`OwnsRotation`) `MouseLook`이 합성하는데, **둘 다 `CurrentRoll`을 통과한다.** 그래서 거기 넣으면
두 배치에서 모두 걸리고, `vrRollScale`을 같이 타서 **VR 억제가 공짜로 따라온다.** 연출이 회전을
직접 쓰면 배치에 따라 되거나 안 되거나 한다.

`VrTuning`은 `ApplyHead()` 하나에서 **눈높이 + 빙의 리프트 + 기상 오프셋을 합성**한다.
`[Head]` 로컬 위치의 소유자가 한 곳이므로 서로 덮어쓸 일이 없다.

`MouseLook`은 매 프레임 `transform.localRotation`을 자기 `_pitch/_yaw`로 덮어쓴다. 그래서
다른 컴포넌트가 `localRotation`을 직접 쓰면 **다음 프레임에 사라진다.** `SetLook`을 추가해
소유자를 하나로 유지한다.

눈높이는 `VrTuning`이 이미 `[Head]` 로컬 y에 `_possessLift`를 더하는 자리가 있다 —
같은 방식으로 `_wakeLift`를 하나 더 얹는다. 새 좌표계를 만들지 않는다.

### 팔 올림

뷰모델 루트를 아래로 내려놨다가 올린다. 포즈를 바꾸는 게 아니라 **위치 오프셋**이다 —
포즈로 하면 `FingerPoser`·`HandIK`와 소유권이 겹친다.

## 4. 리셋 범위

> ⚠️ **이번 작업에서는 구현하지 않는다.** 연출만 먼저 만들고, 스테이지를 실제로 이을 때
> `DeathSequence`가 남겨 둔 훅에 연결한다.

### 현재 상태 — 선언만 되고 구동되지 않는다

`IRunResettable`을 구현한 컴포넌트가 5개(`RailSet`·`RotationPlatform`·`ActuatorControl`·
`PartsPoser`·`StageEntranceFlow`)인데 **호출하는 코드가 없다.** 인터페이스 주석이 참조하는
`Main.RestartRun`이 존재하지 않는다. 즉 지금은 죽어도 아무것도 초기화되지 않는다.

### 범위가 필요하다

| 죽은 곳 | 부활 지점 | 초기화 대상 |
|---|---|---|
| 스테이지 N | N 시작 | **N만** — 1..N−1은 움직인 그대로 보존 |
| 보스 추격전 | 보스 조우 전 지점 | 추격 관련 |

한 메인 씬에 전부 들어가므로(최적화 계획: 거리 컬링 + Static + 텍스처 압축) 씬 단위로 못 나눈다.
→ **계층 단위**로 나눈다.

```
StageRoot (StageScope, index = 2)
├ ... 이 밑의 IRunResettable만 초기화된다
└ Checkpoint          부활 지점
```

`RunReset.ResetScope(scope)`가 `scope.GetComponentsInChildren<IRunResettable>()`를 돌린다.
`IRunResettable`에 스테이지 번호를 넣지 않는다 — 컴포넌트마다 번호를 손으로 맞추는 것은
반드시 틀린다. 계층이 곧 범위다.

`GameOverManager`는 지금 `OnGUI` 최소 버전이다. `DeathSequence`가 실제 연출을 맡고,
`GameOverManager.Trigger`는 그것을 부르는 진입점으로 남긴다 — 호출하는 쪽(`PressCrusher`·
`StageEntranceFlow`)을 안 고쳐도 되게 하기 위해서다.

---

## 6. 인트로와의 공유

게임 시작도 같은 `WakeUpSequence`를 쓴다. 차이는 **앞에 붙는 것뿐**이다.

```
시작:  검정에서 시작 → 1s 페이드 → WakeUp
사망:  암전 → 선 0.5s → 암전 → 리셋 → 1s 페이드 → WakeUp
```

그래서 `WakeUpSequence.Play(onDone)`는 사망을 전혀 모른다.

## 9. 개발 명령 (DevConsole, 백틱으로 열기)

|---|---|
