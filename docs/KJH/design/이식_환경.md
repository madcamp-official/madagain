# MINDHEXER 이식 환경 — 이전 프로젝트에서 가져오는 것

> KJH 개인 문서. 상태: **초안**. 아직 shared 승격 전.
> 이전 프로젝트(`26s-w3-c3-04` / PrecogPrototype)에서 MINDHEXER로 **그대로 또는 부분적으로 이식할 툴·세팅·패턴**을 정리한다.
> 코드 원본은 이전 프로젝트 `docs/shared/재사용_툴킷.md`에 있다. 여기서는 "무엇을·왜·어떻게 이식하느냐"의 판단만 기록한다.

---

## 0. 이 문서의 목적

두 Unity 프로젝트(`headset-s24`, `controller-s10e`)를 새로 세우면서, 매번 바닥부터 다시 만들지 않도록 **검증된 개발 환경을 옮겨온다.** 다만 무지성 복붙이 아니라, MINDHEXER의 맥락(2폰 P2P, VR, 예측 없음)에 맞는지 항목별로 판단한다.

---

## 1. ⚠️ 먼저 확정할 것 — Unity 버전 불일치

| 출처 | 버전 |
|---|---|
| 이전 프로젝트 재사용 툴킷 | **Unity 6 (6000.x) / URP** 기준으로 작성됨 |
| MINDHEXER 현재 스캐폴드(SYB) | **Unity 2022.3 LTS / URP** (`docs/SYB/SETUP.md`) |

**툴킷 코드는 Unity 6 API를 전제**한다. 2022.3에서 다음이 걸릴 수 있다.

- `FindFirstObjectByType` / `FindObjectsByType` — Unity 2021.3+ 존재하므로 2022.3에서 사용 가능. 문제없음.
- `Time.realtimeSinceStartupAsDouble` — 2020.2+ 존재. 문제없음.
- URP Volume/Bloom API 이름 — 2022.3과 6에서 대체로 동일하나 네임스페이스 확인 필요.
- Cinemachine — 툴킷은 `Unity.Cinemachine`(CM3) 네임스페이스. **2022.3 기본은 Cinemachine 2.x(`Cinemachine` 네임스페이스)**. 컷신 스켈레톤 이식 시 이 부분은 반드시 수정해야 한다.

> **판단**: MINDHEXER는 SYB가 이미 세운 **2022.3을 유지**한다(팀원 환경을 뒤집지 않는다). 툴킷 이식 시 위 항목만 API 조정한다. 코드는 대부분 그대로 동작하고, Cinemachine만 실질 수정 대상이다.

| # | 항목 | MINDHEXER에서의 용도 | 이식 | 버전 조정 |
|---|---|---|---|---|
| 1 | 빠른 Play + 정적 리셋 규율 | 개발 반복 속도. 2폰 반복 테스트에 특히 유효 | **즉시** | 없음 |

| 4 | UI 표시 토글 | 스크린샷·데모 촬영 | 필요 시 | 없음 |

## 3. 결정론 Sim/Bridge/View — 부분만 이식

이전 프로젝트에서 이 아키텍처가 필요했던 이유는 **예측·리플레이·롤백** 때문이었다. "미리 굴린 미래"와 "실제 결과"가 해시 단위로 일치해야 했다.

**MINDHEXER에는 예측 시스템이 없다.** 따라서:

| 요소 | 이식? | 이유 |
|---|---|---|
| **계층 분리** (로직 ↔ Unity 참조 분리) | ✅ 이식 | 폰 없이도 게임 로직을 에디터에서 테스트 가능. 입력 소스(UDP 패킷)와 게임 규칙을 분리하면 SYB의 `InputBridge` 하류가 깔끔해진다. |
| **결정론 규율** (WorldHash, Snapshot, DetRng, 고정 틱) | ❌ 미이식 | 재현·롤백이 필요 없다. 이 규율을 지키는 비용만 남고 이득이 없다. |
| **포트(ICollision 등)** | △ 선택 | 물체 조종의 물리 판정을 테스트 가능하게 만들려면 유용하나, MVP에는 과함. |

> **결론**: "로직과 Unity를 섞지 않는다"는 **규율만** 가져오고, 해시·스냅샷 같은 **결정론 장치는 버린다.** 예측이 없는 게임에 결정론을 이식하면 그건 임시방편도 아니고 순수 낭비다.

---

## 4. 이식하지 않는 것

- **흑백 + 파란색 아트 디렉션 전체** — 그건 "초거대로봇 공장(DOOM형)" 프로젝트용 아트 방향이다. MINDHEXER의 아트 방향은 별도로 정한다. 단, **§2-8 발광 재질 + "상호작용 요소만 강조색"** 규율은 잠입 게임에서도 유효하므로 발광 재질만 이식한다.
- **결정론 해시/스냅샷** (위 §3).
- **예측·Beam Search·리듬 실행 관련 전부** — MINDHEXER에 예측 없음.

## 5. 버전 정합성 체크리스트 (툴킷 코드를 실제로 붙일 때)

- [ ] `EnterPlayModeOptions.DisableDomainReload` — 2022.3 동작 확인
- [ ] URP `Volume` / `Bloom` API 네임스페이스 확인 (`UnityEngine.Rendering.Universal`)
- [ ] Cinemachine — 2.x(`Cinemachine`) vs 3.x(`Unity.Cinemachine`) 확인 후 컷신 코드 수정
- [ ] `Shader.Find("Universal Render Pipeline/Unlit")` — 2022.3 URP에 존재 확인
- [ ] 정적 리셋(`RuntimeInitializeOnLoadMethod`)이 **네트워크 스레드·소켓 정리**까지 포함하도록 확장 (SYB의 `UdpReceiver` 스레드, `MainThreadDispatcher` 큐)

> 마지막 항목이 중요하다. 도메인 리로드를 끄면 소켓·백그라운드 스레드가 플레이 사이에 안 죽을 수 있다. 이식하는 정적 리셋 규율에 **네트워크 자원 해제**를 반드시 포함시킨다.
