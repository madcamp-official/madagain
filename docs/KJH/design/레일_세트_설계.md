# 레일 세트 설계 (외부 조종 — 이송 기믹)

> 대상: 다른 계정/세션에서 이어서 구현할 사람
> 관련: `기초_설계안.md` §6.2(외부 조종 축·입력 모드), §2.5(PC 조작 매핑)
> 작성 시점 상태: **부분 구현됨. 아래 §6에 "지금 코드가 틀린 부분"이 있으니 반드시 먼저 읽을 것.**

---

## 1. 무엇인가

레일 위를 미끄러지는 이송 기믹. 플레이어가 해킹해서 **밖에서 조종**하는 대상이다(빙의 아님).
레일 위에는 터렛·벽 같은 오브젝트가 얹히고, 그 오브젝트가 길을 막거나 열어 퍼즐을 만든다.

**핵심: 레일과 그 위의 오브젝트가 통째로 함께 움직인다.**
레일이 고정 트랙이고 그 위를 라이더가 달리는 구조가 **아니다**. 레일 자체가 이동체의 일부다.

그래서 **레일은 실제로 보이는 구간보다 길게 만든다.** 세트가 이동 범위 끝까지 가도 레일 끝이
플레이어 시야에 드러나지 않게 하기 위한 것이다. 이건 미술/배치 규칙이지 코드 규칙이 아니다(§5 참조).

---

## 2. 구조

```
[RailSet]                     ← RailSet + Hackable(외부 조종) + ControlAxisGizmo
 ├ Rails/                     ← 레일 칸들. 두 줄짜리 한 벌 = 1칸
 │   ├ Rail_0                 ← 스케일로 길이를 임의 조정한 것. 이 길이가 스냅 단위
 │   ├ Rail_1
 │   └ ...
 └ Riders/                    ← 레일에 종속된 오브젝트들
     ├ Turret                 ← Hackable(시점 진입) + ViewEntryTarget — 별도 해킹 대상
     ├ Wall
     └ [RailSet]              ← 중첩 가능 (§4)
```

**용어**
| 말 | 뜻 |
|---|---|
| **레일 1칸** | 두 줄짜리 레일 한 벌. 스케일로 길이를 조정한다. **= 스냅 단위 = 플릭 1회 이동량** |
| **레일 세트** | 레일 여러 칸 + 그 위의 라이더들. 이 전체가 하나의 이동 단위이자 해킹 대상 |
| **라이더** | 레일에 종속된 오브젝트. 터렛·벽 등. 여럿 가능하며 **전부 같이 움직인다** |

## 3. 이동 규칙

### 3.1 기준은 "세트의 중앙"

이동량(offset)은 라이더의 배치 위치가 아니라 **레일 세트의 중앙**에서 잰다.
그래야 씬에서 무엇을 어디에 놓든 이동 범위가 흔들리지 않는다.

- `rangeMin` / `rangeMax` — 중앙 기준 이동 한계. **미터로 직접 입력**하며, 툴이 "±N칸" 버튼으로도 채워준다
- 비대칭 지정 가능 (예: −2 ~ +6)

### 3.2 두 가지 조종 모드 (§6.2)

| 입력 | 동작 |
|---|---|
| 좌/우클릭 **홀드** | 등속 크립. 연속 이동. 범위 끝에서 멈춤 |
| 좌/우 **더블클릭** | **플릭 — 정확히 레일 1칸 이동** |

**플릭 판정**: 현재 위치를 격자에 반올림한 뒤 ±1칸으로 간다. 현재 위치가 칸 사이 어디에 있든
다음 칸에 정확히 안착한다(§6.2 "1/5에서 오른쪽 확 → 1/4까지").

```
cell   = round(offset / railLength)
target = clamp((cell + dir) * railLength, rangeMin, rangeMax)
```

**범위를 넘어가는 플릭은 범위 끝에 붙인다**(확정). 무시하지 않는다.

**플릭 중에는 아날로그 입력을 무시해야 한다.** 더블클릭 직후에도 버튼이 눌려 있어서, 아날로그가
플릭을 취소하게 두면 플릭이 시작하자마자 1프레임 만에 죽는다. (실제로 겪은 버그다)

### 3.3 축

- 축은 **월드 좌표에 고정**된 방향이다(§6.2). 레벨 배치가 정한다
- 레일 세트는 **1축**이다. 2축은 갠트리의 몫

---

## 4. 중첩

**라이더 안에 레일 세트가 또 들어갈 수 있다.** 바깥 세트가 움직이면 안쪽 세트가 통째로 실려 간다.

이 요구 때문에 구조가 하나 확정된다:

> **모든 이동 계산을 자기 트랜스폼의 로컬(부모 기준) 공간에서 한다. 월드 좌표를 직접 쓰지 않는다.**

월드 기준으로 계산하면 바깥 세트가 움직인 뒤 안쪽 세트의 중앙·범위가 전부 어긋난다.
로컬로 처리하면 Unity의 트랜스폼 계층이 합성을 알아서 해준다.

---

## 5. 배치(authoring) 규칙

1. **레일 총 길이 ≥ 보이는 구간 + 이동 범위 폭.** 세트가 범위 끝까지 가도 레일 끝이 안 보여야 한다
2. 레일 칸들은 축 방향으로 끝끝 이어 붙인다. 칸 길이가 곧 플릭 이동량이므로 **칸마다 길이가 다르면 안 된다**
3. 라이더는 `Riders/` 아래에 둔다. 여럿이어도 되고 전부 같이 움직인다
4. 터렛처럼 그 자체로 해킹 가능한 라이더는 **자기 `Hackable`을 따로 갖는다**(§7)

## 6. 지금 코드 상태 — 반드시 읽을 것

구현 파일 2개가 이미 있다. **핵심 로직 하나가 틀렸다.**

| 파일 | 상태 |
|---|---|
| `Assets/_Project/View/Hacking/Control/RailSet.cs` | **수정 필요** (아래) |
| `Assets/_Project/Editor/RailSetEditor.cs` | 대체로 유효. 아래 항목만 손보면 됨 |

### 6.1 고쳐야 할 것 — 무엇이 움직이는가

현재 `RailSet.Update()`는 **`riderRoot`만** 옮긴다:

```csharp
riderRoot.localPosition = _riderAuthoredLocal + AxisLocal * (Offset - _authoredOffset);
```

이건 "레일은 고정, 라이더만 이동"을 전제한 것이라 **틀렸다.**
레일과 라이더가 **함께** 움직여야 한다.

**고칠 방향**: `riderRoot`가 아니라 **`RailSet` 자신의 트랜스폼**을 옮긴다.
`Rails/`와 `Riders/`가 모두 자식이므로 통째로 따라간다. 중첩도 자동으로 성립한다.

이때 "중앙"의 의미가 바뀐다:
- 지금: 레일 바운즈의 중앙(세트 안에서의 위치)
- 바뀐 뒤: **이동 범위의 기준점**. 세트가 배치된 자리를 부모 공간에 기록해 두고 거기서 ±로 잰다

즉 `center`는 "세트 내부의 기하학적 중앙"이 아니라 **"부모 공간에 박힌 앵커"**가 되어야 한다.
배치 시점의 `localPosition`을 앵커로 잡는 방식이 가장 단순하다.

### 6.2 부수 효과 (좋은 쪽)

세트 루트가 직접 움직이면, 미해결로 남겨뒀던 두 문제가 저절로 풀린다:

- `ControlAxisGizmo`(축 방향 막대)가 루트에 그려지는데, 루트가 곧 움직이는 것이므로 맞다
- `ControlTether`(플레이어↔대상 실)가 `Hackable` 트랜스폼에 붙는데, 그것도 루트라 맞다

`riderRoot`만 움직이던 설계에서는 이 둘이 "가만히 있는 원점"에 붙어 어색했다.

### 6.3 에디터 툴에서 손볼 것

`RailSetEditor.cs`의 버튼·핸들은 대부분 그대로 쓸 수 있다. 다만:

- **"라이더를 중앙으로" / "가장 가까운 칸에 정렬"** — 이제 세트 전체가 움직이므로 "세트를 …"로 의미를 바꿔야 한다
- **중앙 재계산** — 레일 바운즈 중앙이 아니라 앵커 개념으로 재정의(§6.1)
- 나머지(레일 길이 측정, 축 산출, ±N칸 버튼, 칸 눈금 기즈모, 범위 드래그 핸들)는 유효하다

### 6.4 이미 되어 있어 건드릴 필요 없는 것

- `IExternalControl` 구현 → 해킹 성공 시 조종 대상으로 잡히고, 매핑 고정·실·축 표시가 자동 적용
- 플릭 스냅 계산과 "플릭 중 아날로그 무시" 처리
- 생성 메뉴 `GameObject > MINDHEXER > 레일 세트`

---

## 7. 해킹 대상 분리 (확정)

`Hackable`은 `controlType`을 하나만 가진다. 레일 위 터렛처럼 두 방식이 겹치는 경우:

- **레일 조종용 `Hackable`(외부 조종)** → `RailSet` 루트에 붙인다
- **터렛 빙의용 `Hackable`(시점 진입)** → 터렛 본체에 붙인다

조준 지점이 둘로 나뉜다. 레일 몸통을 보면 레일이 조종되고, 터렛을 보면 터렛에 빙의한다.

## 8. 기존 시스템과의 접점

| 대상 | 관계 |
|---|---|
| `IExternalControl` | `RailSet`이 구현. `AxisCount`=1, `AxisWorld(0)`=월드 축, `Drive(0, analog, flick)` |
| `HackDriver` | 해킹 성공 시 조종 대상으로 잡음. **좌/우클릭 슬롯 배정과 부호를 성공 순간의 시점 기준으로 고정** — 조종 중 시점을 돌려도 방향이 안 흔들린다 |
| `ControlAxisGizmo` | 축 방향 막대(임시 표현) |
| `ControlTether` | 플레이어↔대상 실. 해킹 시도 시 초록 → 성공 시 파랑 |
| `RailCarrier` | **구버전 테스트용.** 레일 프리팹이 나오기 전까지 남겨둔다. 레일 세트로 대체될 예정 |

---

## 9. 임시 표현 (교체 대상)

- 축 방향 막대 = 색 다른 직육면체 → 화살표 메시·셰이더로
- 조종 실 = 길이 가변 직육면체 → 실 메시·트레일·셰이더로 (§2.2 스티치와 이어짐)

## 10. 미결

1. **레일 프리팹 미완성.** 두 줄짜리 레일 에셋이 나와야 실제 배치·길이 측정을 검증할 수 있다
2. `center` 앵커의 정확한 정의 — §6.1의 "배치 시점 `localPosition`" 방식으로 갈지 확정 필요
3. 라이더가 여럿일 때 개별 오프셋을 줄 일이 있는지 (현재 전제: 전부 같이 고정 배치)
4. 아날로그 이동을 놓았을 때 가까운 칸으로 붙일지 (`snapAnalog`, 현재 기본 끔)
