# 레일 세트 설계 (외부 조종 — 이송 기믹)

> 관련: `기초_설계안.md` §6.2(외부 조종 축·입력 모드), §2.5(PC 조작 매핑), §14(아레나·복도)
> 상태: **설계 확정 + 1차 구현 완료.** 남은 것은 §9(미결)뿐.

---

## 1. 무엇인가

레일 위를 미끄러지는 이송 기믹. 플레이어가 해킹해서 **밖에서 조종**하는 대상이다(빙의 아님).
레일 위에는 터렛·벽·발판이 얹히고, 그것이 길을 막거나 이어 퍼즐을 만든다.

**핵심: 레일과 그 위의 오브젝트가 통째로 함께 움직인다.**
레일이 고정 트랙이고 그 위를 라이더가 달리는 구조가 **아니다**. 레일 자체가 이동체의 일부다.

그래서 **레일은 보이는 구간보다 길게 만든다.** 세트가 끝까지 가도 레일 끝이 시야에 드러나지
않게 하기 위한 것이다(§5).

---

## 2. 구조

```
[RailSet]                     ← RailSet + Hackable(외부 조종) + ControlAxisGizmo + 조준 콜라이더
 │                              ★ 움직이는 것은 이 트랜스폼이다
 ├ Rails/                     ← 레일 칸들. 두 줄짜리 한 벌 = 1칸. 렌더러만(콜라이더 없음)
 │   ├ Rail_0                 ← 이 길이가 스냅 단위
 │   └ ...
 └ Riders/                    ← 함께 실려 가는 것들
     ├ Turret                 ← Hackable(시점 진입) — 별도 해킹 대상
     ├ Floor                  ← RailPlatform — 위에 탄 것을 같이 나름
     └ [RailSet]              ← 중첩 가능 (§4)
```

| 말 | 뜻 |
|---|---|
| **레일 1칸** | 두 줄 레일 한 벌. **= 스냅 단위 = 플릭 1회 이동량** |
| **레일 세트** | 레일 + 라이더 전체. 하나의 이동 단위이자 해킹 대상 |
| **라이더** | 세트에 실린 오브젝트. 여럿 가능하며 **전부 같이 움직인다** |
| **앵커** | 씬에 배치된 자리. 이동 범위의 기준점 |

## 3. 좌표 모델 — 루트가 움직인다

```
_anchorLocal = 배치 시점 transform.localPosition          (부모 공간)
axisParent   = (transform.localRotation * axis).normalized (Awake에 캐시 — 런타임 회전 없음)

transform.localPosition = _anchorLocal + axisParent * Offset
```

- **기준은 앵커.** `rangeMin`/`rangeMax`는 앵커에서 ±로 잰다. 루트 위치는 라이더 배치와 무관하므로
  "무엇을 어디에 놓든 범위가 안 흔들린다"는 원래 의도가 그대로 지켜진다.
  `ControlAxis.travelMin/Max`("시작 위치 기준")와도 규칙이 통일된다.
- **단위는 부모 공간** — `Offset`·`railLength`·`range*`가 전부 `localPosition`과 같은 단위.
  > ⚠️ 길이 측정은 **부모 스케일**로 환산한다(자기 스케일이 아니다). 세트가 부모 공간에서
  > 움직이기 때문이다. `RailSet.ParentScaleAlongAxis`가 그 환산값이다.
- **비대칭 범위** 가능(예: −2 ~ +6).

## 4. 중첩

**라이더 안에 레일 세트가 또 들어갈 수 있다.** 바깥이 움직이면 안쪽이 통째로 실려 간다.

이 요구가 구조를 결정한다:

> **모든 이동 계산을 부모 기준 로컬 공간에서 한다. 월드 좌표를 직접 쓰지 않는다.**

바깥이 움직여도 안쪽 `localPosition`은 그대로라 앵커·범위가 유효하다. 축도 평행이동만 하므로
월드 방향이 안 변한다 → `HackDriver`가 해킹 성공 시 고정한 슬롯·부호와 충돌하지 않는다.

> 알려진 한계: 같은 프레임에 바깥·안쪽 중 어느 쪽 `LateUpdate`가 먼저 도는지는 보장되지 않아
> 중첩 발판의 탑승 이송이 **1프레임 늦을 수 있다**. 체감상 문제가 되면 실행 순서를 고정한다.

## 5. 배치(authoring) 규칙

1. **레일 총 길이 ≥ 보이는 구간 + 이동 폭.** 끝까지 가도 레일 끝이 안 보여야 한다.
   툴이 `레일 총 길이 < 이동 폭`이면 경고한다. 씬뷰의 **양 끝 고스트**로 눈으로 확인한다.
2. 레일 끝은 **벽 개구부(소켓)** 로 물려 시야에서 사라지게 한다.
3. 칸은 축 방향으로 끝끝 이어 붙이고 **칸마다 길이가 같아야 한다**(길이가 곧 플릭 이동량).
4. **레일에는 콜라이더를 두지 않는다.** 세트가 통째로 미끄러지므로 레일 콜라이더는 벽을 뚫고
   지나간다. 물리는 라이더가 담당한다. (툴이 위반을 경고한다)
5. **조준용 콜라이더**는 루트에 `isTrigger`로 따로 둔다(이동을 막지 않음). 레이어 `Hackable`.
6. 발판·바닥 역할 라이더에는 **`RailPlatform`** 을 붙인다(§7).
7. 하이라이트(`Hackable.glowRenderers`)는 **레일 몸통만** 지정한다. 터렛은 자기 청록 하이라이트를
   따로 가지므로, 두 조준 지점이 색으로 구분된다.

## 6. 이동 규칙

### 6.1 두 가지 조종 (§6.2)

| 입력 | 동작 |
|---|---|
| 좌/우클릭 **홀드** | 등속 크립 + 짧은 가감속 램프(`accelTime`). 범위 끝에서 정지 |
| 좌/우 **더블클릭** | **플릭 — 정확히 레일 1칸** |

```
cell   = round(Offset / railLength)
target = clamp((cell + dir) * railLength, rangeMin, rangeMax)
```

- 현재 위치가 칸 사이 어디에 있든 **다음 칸에 정확히 안착**한다.
- **범위를 넘는 플릭은 범위 끝에 붙인다**(확정). 무시하지 않는다.
- **플릭 중에는 아날로그를 무시한다.** 더블클릭 직후에도 버튼이 눌려 있어서, 아날로그가 플릭을
  취소하게 두면 시작하자마자 1프레임 만에 죽는다. (실제로 겪은 버그)

### 6.2 왜 "1칸"인가

세트 전체가 움직이므로 "월드의 특정 레일 칸에 정렬"은 의미가 없다. 격자는 **앵커에 고정된
이동 양자**이고, 그 크기를 레일 1칸으로 잡는 이유는 **레일이 정확히 한 마디 밀린 것처럼 보여
"기계식 인덱싱"으로 읽히기** 때문이다.

### 6.3 플릭 곡선 — 철컥

시간 기반(`flickTime`)이다. 거리가 항상 1칸이라 속도가 아니라 시간으로 잡는 게 맞다.

```
smootherstep + 끝 40% 구간의 사인 범프(overshoot)
```

목표를 살짝 지나쳤다 돌아와 **철컥 안착**한다(Precog `FanSpawnActor.Mech()`와 같은 곡선 — 공장
무드와 일치). `overshoot=0`이면 순수 smootherstep.

### 6.4 축

- 축은 **월드에 고정된 방향**이다(§6.2). 레벨 배치가 정한다.
- 레일 세트는 **1축**(`AxisCount=1` → 슬롯0 = 좌/우클릭). 2축은 갠트리의 몫.

## 7. 발판 탑승 (`RailPlatform`)

세트가 움직여도 그 위에 서 있는 플레이어는 **자동으로 따라오지 않는다**(CharacterController).
"길을 만들어 도달"이 코어인 게임에서 이건 치명적이라 별도 처리한다.

**방식: 델타 이송.** 계층 부모 지정(SetParent) 대신, 세트가 이동한 **월드 델타만큼
`CharacterController.Move`를 한 번 더** 불러 준다.

- 계층을 안 건드리므로 VR 리그·`AutoTraversal`·`MantleRig`와 충돌하지 않는다.
- `RailSet`이 자기 이동 직후 `RailPlatform.Carry(delta)`를 부른다(`LateUpdate` — 플레이어 이동
  이후라 서로 안 싸운다).
- 탑승 판정 = 발밑 SphereCast가 그 발판을 맞추는지.
- **중첩 이중 이송 방지**: 각 `RailPlatform`은 가장 가까운 조상 `RailSet`만을 소유자로 삼고,
  세트는 자기 소유 발판만 나른다.
- **조종하면서 자기가 탄 발판을 움직이는 것**은 의도된 플레이다(§6.2 "조종 중 이동 가능").
- ⚠️ 현재 `CharacterController`만 대상. **경비병(NavMeshAgent) 탑승은 미구현**.

### 밀치기·압사는 없다 (MVP 확정)

라이더가 플레이어 쪽으로 밀고 들어와도 밀어내거나 죽이지 않는다. **압사는 유압프레스의 역할**이고,
레일은 배치로 "플레이어를 쓸고 지나가는 궤적"을 만들지 않는다. 끼임이 실제로 보이면 그때
depenetration을 추가한다.

## 8. 런타임 계약

| 멤버 | 용도 |
|---|---|
| `IExternalControl` | `AxisCount=1`, `AxisWorld(0)`, `Drive(0, analog, flick)` |
| `IRunResettable` | **아레나 리셋 시 앵커로 즉시 복귀**(플릭 취소). §14 소프트락 대응 |
| `Offset` / `CurrentCell` / `AtRest` | 상태 조회 |
| `event OnCellArrived(int cell)` | **정지 상태에서 칸이 바뀔 때.** 퍼즐 조건(게이트 개방) 배선용 |
| `WorldDelta` | 이번 프레임 월드 이동량(발판 이송용) |

기존 시스템과의 접점:

| 대상 | 관계 |
|---|---|
| `HackDriver` | 해킹 성공 시 조종 대상으로 잡고 **슬롯·부호를 그 순간의 시점 기준으로 고정** |
| `ControlAxisGizmo` | 축 방향 막대 — 루트에 붙고 루트가 곧 움직이므로 자연히 맞다 |
| `ControlTether` | 플레이어↔대상 실. 시도 시 초록 → 성공 시 파랑 |
| `RailCarrier` | **구버전.** 레일 세트로 대체됨. 정리 대상 |

### 해킹 대상 분리 (확정)

`Hackable`은 `controlType`을 하나만 가진다. 레일 위 터렛처럼 두 방식이 겹치면:

- **레일 조종용 `Hackable`(외부 조종)** → `RailSet` 루트
- **터렛 빙의용 `Hackable`(시점 진입)** → 터렛 본체

조준 지점이 둘로 나뉜다. 레일 몸통을 보면 레일이 조종되고, 터렛을 보면 터렛에 빙의한다.

## 9. 미결

1. **레일 프리팹 미완성** — 지금은 `GameObject > MINDHEXER > 레일 세트 (그레이박스)`가 만드는
   막대 두 줄로 테스트한다. 에셋이 나오면 교체.
2. **경비병 탑승** — `RailPlatform`이 `CharacterController`만 나른다. NavMeshAgent 처리 필요.
3. **오디오** — 이동 루프(모터) / 플릭 안착 클렁크 / 범위 끝 정지음. 훅만 잡혀 있고 미구현.
4. **수치 튜닝** — `moveSpeed 2` / `accelTime 0.08` / `flickTime 0.28` / `overshoot 1.6`은 전부
   출발점. 실기 확인 후 확정. (F1 튜닝 패널 노출은 미정)
5. **중첩 1프레임 지연**(§4) — 실측 후 필요하면 실행 순서 고정.
6. **퍼즐 조건 배선** — `OnCellArrived`를 아레나 클리어(§14)에 어떻게 물릴지 미정.

## 10. 결정 기록 (왜 이렇게 했나)

| 결정 | 이유 |
|---|---|
| 루트가 움직인다 (라이더만 X) | 레일과 라이더가 함께 미끄러지는 것이 원래 그림. 중첩·기즈모·조종 실이 전부 자동으로 맞아떨어진다 |
| `center` 삭제 → 앵커 | 세트가 통째로 움직이면 "세트 내부의 기하학적 중앙"은 의미가 없다. 범위 기준은 배치 위치 |
| 레일 콜라이더 없음 | 세트가 미끄러지면 레일이 벽을 관통한다. 물리는 라이더가 담당 |
| 탑승 = 델타 이송 | 계층 부모 지정은 VR 리그·이동 시스템의 좌표계를 흔든다 |
| 라이더 개별 오프셋 없음 | 독립 이동이 필요하면 **중첩 세트**로. 규칙이 하나로 유지된다 |
| `snapAnalog` 기본 끔 | 크립은 미세 조정용인데 강제 스냅이 그걸 방해한다 |
| 밀치기·압사 없음 | 압사는 유압프레스의 역할. 레일까지 치명적이면 위험 표현이 흐려진다 |

## 12. 테스트 방법

1. `GameObject > MINDHEXER > 레일 세트 (그레이박스)` 로 생성.
2. `Riders/` 밑에 발판(콜라이더 있는 큐브)을 놓고 **`RailPlatform`** 을 붙인다.
3. 씬뷰에서 앵커·범위선·칸 눈금·양 끝 고스트 확인. 레일이 짧으면 인스펙터가 경고한다.
4. Play → 레일을 보고 해킹 → **홀드**로 크립, **더블클릭**으로 1칸 플릭.
5. 확인할 것: 칸에 정확히 안착하는가 / 끝에서 멈추는가 / 플릭이 즉시 취소되지 않는가 /
   **발판 위에 서 있을 때 같이 실려 가는가** / 조종하면서 타고 이동이 되는가.
