## 0. 전제
- **이음새만 읽는다**: `Hackable.{controlType, DistanceToPlayer, InRange, IsGazed, captureState}` + `GuardDetection.DetectRadius`.
- **`HackableStateMock`으로 상태 수동 세팅** → 게임플레이 로직 없이 독립 개발·튜닝·테스트.
- 재활용: git `4ac48c4`의 `EnemyOutline.shader`(Sobel→네온)·`EnemyGlow.cs`(MPB+HDR). Shaders 자산 있으면 그대로, 없으면 재추출.
- **파일 disjoint**: 새 파일만 추가(아래). `Hackable.cs`·`HackDriver.cs`(로직/사용자 C)는 **안 건드림**.

## 1. 이음새 → 시각 파라미터 (§7 색 언어)
| 시각 채널 | 읽는 이음새 | 규칙 |
|---|---|---|
| **색** | `captureState`·`controlType` | Captured→**파랑(하늘색)** / else ExternalControl→**연두**·ViewEntry→**진한 청록**·Stun→**초록** |
| **테두리 두께** | `DistanceToPlayer` | 가까울수록 두껍게(clamp min~max) |
| **글리치 애니** | `InRange` | 안=치직 스크롤 / 밖=정적(해킹 불가 표시) |
| **격화 + 3D 치직** | `IsGazed` | 조준 대상=글리치 진폭·밝기 부스트 + 표면 3D 노이즈 |
| **위험 범위(빨강)** | `GuardDetection.DetectRadius` | 별개(B4) |
- **색맹 대비**: 색 + 두께(거리) + 움직임(글리치/정적) 3채널.

## 2. 아키텍처 (컴포넌트·셰이더 — 전부 신규 파일)
- **`View/Hacking/HackableOutline.cs`** — 각 Hackable에서 매 프레임 이음새 읽어 상태색·두께·글리치·격화를 MPB로 아웃라인에 전달. ("이음새→시각" 변환 단일 지점.)
- 아웃라인 렌더 (2단):
  - **B1a(MVP) 헐 아웃라인** `Shaders/HackOutlineHull.shader` — 노멀 확장 + 상태색 unlit HDR. per-object, 빠름.
  - **B1b(정식 §7) 화면공간 엣지** `View/Hacking/HackOutlineFeature.cs`(URP ScriptableRendererFeature) — Hackable 레이어→상태색 마스크 RT→풀스크린 Sobel 엣지+글리치(HDR→Bloom).
- **`View/Hacking/GazeGlitch.cs`**(B3) — IsGazed면 표면 3D 노이즈 치직(변위 셰이더 오버레이).
- **`View/Hacking/GuardDangerZone.cs` + `Shaders/HackDangerSphere.shader`**(B4) — DetectRadius 빨강 반투명 구 + 3D 도트, `ZTest LEqual`로 벽 뒤 안 보임.

## 3. 구현 순서 (각 단계 mock으로 즉시 확인)
1. **B0** `HackableOutline` + `HackOutlineHull.shader` 골격 (큐브에 상태색 헐 아웃라인).
2. **B1a** 색(controlType/captureState) + 두께(distance) 매핑.
3. **B2** 글리치 토글(InRange).
4. **B3** 격화 + 3D 치직(IsGazed).
5. **B1b** 화면공간 엣지 렌더러 피처 승격(§7 정식).
6. **B4** 경비병 위험 범위 구+도트.

## 4. 테스트
