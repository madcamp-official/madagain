## 0. 기초_설계안 §11.1 메모가 이미 정한 것 (그대로 따른다)

> - **일반 `HydraulicPress`의 스케일만 키우면 안 된다.** `strokeMin`/`strokeMax`가 **월드 미터** 기준이라
>   스케일을 키워도 행정이 같이 안 커지고, `_worldPerLocal` 환산 때문에 오히려 어긋난다.
>   크기·행정·속도가 전부 다른 **별개 개체**로 두는 것이 맞다.
> - `Hackable.kind`는 `HydraulicPress`를 그대로 쓰고 보스 전용 동작만 **별도 컴포넌트로 얹는다** —
>   열거형 값은 저장된 int라 건드리면 기존 프리팹의 종류가 뒤바뀐다.

**실측으로 확인했다.** 경고가 정확하다.

| | 값 |
|---|---|
| `HydraulicPress` scale 1 | **7.48 × 9.52 × 4.68 m**, `strokeMax = 1m`, `flickDuration 0.12` |
| 같은 것 scale 4 (지금 `base.unity`에 놓인 상태) | 몸집 **29.9 × 38.1 × 18.7 m**, 행정은 **그대로 1m** |
| `MegaRobot` scale 50 | **머리 본 y = 43.8 m** |

38m짜리 프레스가 1m만 내려온다. 43.8m 높이의 머리를 찍는 건 불가능하다.

> ⚠️ 보스 바운즈는 못 쓴다. `SkinnedMeshRenderer` 118개의 `localBounds`가 전부 `size(3,3,3)`으로
> 통일돼 있어(가까이서 컬링돼 사라지는 문제를 막으려고) ×50 하면 150×150×150이 나온다.
> **머리 크기·입구 크기는 바운즈가 아니라 마커로 재야 한다.**

## 1. 별개 프리팹 — "완전 별개" 대신 **프리팹 배리언트**를 권한다

메모의 표현은 "별개 개체"인데, 구현 수단으로는 **프리팹 배리언트**가 낫다고 본다. 메모의 요구
(크기·행정·속도가 전부 다름)는 배리언트로 전부 만족되고, 이쪽이 유지보수에서 유리하다.

| | 완전 복사 | **프리팹 배리언트(권장)** |
|---|---|---|
| 크기·행정·속도 독립 | ○ | ○ (오버라이드) |
| `PressCrusher`·`ActuatorControl` 배선 | 복사본에 따로 존재 → **따로 썩는다** | 원본에서 상속 → 원본 수정이 자동 전파 |
| 모델 교체·버그 수정 | 두 곳을 고쳐야 함 | 한 곳 |

메모가 경계한 것은 **"스케일만 키우고 행정을 안 고치는 것"** 이다. 배리언트가 위험한 게 아니다.
행정·속도를 명시적으로 오버라이드하면 메모의 의도를 지킨다.

```
GiantPress.prefab   (HydraulicPress.prefab 의 Variant)
  ├ scale            오버라이드
  ├ strokeMin/Max    오버라이드   ← 여기를 잊으면 메모가 경고한 그 상태가 된다
  ├ linear/flickDuration 오버라이드
  └ (상속) Hackable(kind=HydraulicPress) · ActuatorControl · PressCrusher · Model_Presser
```

`Hackable.kind`는 손대지 않는다. 보스 전용 동작은 `StageEntranceFlow`가 **밖에서** 얹는다 —
이미 그렇게 만들어져 있고, 그 컴포넌트가 없으면 초거대 프레스는 그냥 큰 유압프레스다.

### 값을 정하는 순서 (숫자를 지어내지 않는다)

1. 보스를 배치하고 **머리 접촉 마커**를 머리 표면에 꽂아 실제 높이를 읽는다.
2. 프레스를 그 위에 놓고, **완전 수축 상태에서 헤드 밑면이 머리보다 얼마나 위인지** 잰다.
3. `strokeMax` = 그 거리 + 머리를 파고들 여유. `strokeMin` = 0.
4. 속도는 §11.2 규약대로 **플릭 = '쾅'**. 기존 0.12s를 크기에 맞춰 조금 늘린다(질량감).

**단계가 오르면 머리가 낮아지므로 `strokeMax`는 4단계 중 가장 낮은 머리에 닿을 만큼** 잡는다.
실제 정지 지점은 `TelescopingActuator.LimitT`가 매 프레임 계산하므로 넉넉히 잡아도 안전하다.

## 2. `base.unity` = 작업장

지금 상태: 프리팹 인스턴스 1,182개(대부분 TallCity 벽·홀더), `HydraulicPress` 1개가
**월드 (63.97, 17.25, 7.00) scale 4**, `_Environment`·`[GameBoot]`·라이트·`Main Camera` 있음.
**보스는 아직 없다.**

여기에 배치할 것:

```
StageEntrance (StageEntranceFlow)
├ Passage/            (기존 입구·옆벽 재사용)
│   └ ExitGeo         PartsPoser — "홈" / "찌그러짐" / "부서짐"
├ PlayerTrigger       플레이어 통과 감지
├ SealWall            투명벽(콜라이더만) — 임시방편
├ WedgeStop           BossWedgePoint. 머리가 와서 멈추는 지점
├ SealHandTarget      보스 팔이 짚어 출구를 막을 지점
└ GiantPress          (신규 배리언트) + PressCrusher(상속)
Boss/  MegaRobot scale 50
└ HeadContact         프레스가 닿을 머리 표면 마커
```

**프레스 위치 규약**(보스전_설계 §6): 천장 정중앙이 아니라 **앞쪽 위 비스듬히**. VR에서 위를
쳐다보게 만들면 목이 아프다.

## 3. 낑김·팔 봉쇄를 어떻게 "만드는가" — 포즈 캡처가 아니다

이게 이 문서에서 제일 중요한 정정이다. 나는 앞서 팔 봉쇄를 자세 스냅샷으로 만들 것처럼 말했는데,
**`BossArmRig`는 월드 지점을 향하는 런타임 IK**다.

```csharp
rig.Aim(side, worldTarget, palmNormal);   // Relax까지 유지된다
```

즉 저작 작업은 **자세를 굽는 것이 아니라 마커를 놓는 것**이다. 그리고 그걸 위한 도구가
`BossArmRig`에 이미 있다.

```
BossArmRig.preview = true
BossArmRig.previewTargetL / previewTargetR   ← 이 트랜스폼을 씬에서 끌면 팔이 실시간으로 따라온다
BossArmRig.previewPalmNormal
```

**작업 순서**

1. `base.unity`에 보스를 놓고 입구 앞에 세운다.
2. `BossWedgePoint.headStop`을 입구 구멍에 놓는다. → 런타임에 `StageEntranceFlow`가
   **루트를 평행이동**해 머리를 거기 맞춘다(IK 아님. 머리가 척추 말단이라 오차 0).
3. `HeadContact` 마커를 머리 **표면**(프레스가 닿을 곳)에 꽂는다.
   ★ 이 마커를 **머리 찌그러짐 자세 목록에 포함**시켜야 단계가 오를 때 같이 내려온다 —
   그러면 회차마다 프레스가 더 깊이 들어가는 것이 공짜로 얻어진다.
4. `preview`를 켜고 `previewTargetL`을 출구 쪽 벽으로 끌어 **팔이 출구를 막는 모양**을 만든다.
   `elbowHint`·`rollOffset`으로 팔꿈치·손바닥을 잡는다. 손등으로 짚는다(`braceWithBackOfHand`).
5. 그 마커를 `StageEntranceFlow.sealHandTarget`에 물리고 **preview를 끈다**.
   (preview가 켜진 채 저장되면 미리보기 자세가 씬에 굳는다 — 그래서 `BossArmRig`가
   저장 직전·비활성 시 홈으로 복원하게 되어 있다.)
6. `ExitGeo`에 `PartsPoser` + `PartsPose` 애셋. **"홈"을 먼저 캡처**한 뒤 파츠를 손으로 눌러
   "찌그러짐", 더 부숴 "부서짐"을 캡처하고 **홈으로 복원 후 저장**.

**팔은 자세를 굽지 않고 마커만 놓는다. 굽는 것은 출구 지오메트리뿐이다.**

## 5. 문서 정리 필요 (이 작업 중에 같이)

- **`CrushZone`은 만들 필요 없다.** `PressCrusher`가 이미 그 역할을 하고 `HydraulicPress.prefab`에
  붙어 있다(경비병·플레이어 즉사, 빙의 중 경비병 구분까지). 보스는 트리거가 아니라
  **프레스가 `LimitT`에 닿는 것**으로 판정한다. → 기초_설계안 §11.1의 "압사 판정이 아직 없다"와
  보스전_설계 §6·§9의 `CrushZone` 항목을 갱신할 것.
- **"초초거대 유압프레스(4막)"는 근거 소멸.** `보스전_설계.md`가 4막 구성을 2막으로 바꿨다.
  기초_설계안 §11.1의 A→B→C 2회 압사 서술도 같이 갱신 대상.
