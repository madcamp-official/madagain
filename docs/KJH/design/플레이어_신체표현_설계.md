# 플레이어 신체 표현 설계 (1인칭 손 · 등반 · 3인칭 전신 · 펫 거미)

> 관련: `기초_설계안.md` §2.2(해킹 흐름), §2.6(펫 거미 모션 세트), §6.2(외부 조종), §6.3(시점 진입), §7(시각 언어)
> 관련 결정: `decisions/0002-precog-purge.md`(뷰모델 도구가 통째로 삭제된 경위)
> 상태: **설계 확정. 구현 착수 전.** 수치 튜닝은 구현 후 실기에서 잡는다(§11).

---

## 1. 무엇인가

플레이어의 몸이 화면에 보이는 모든 경우를 하나로 묶어 설계한다.

| 상황 | 보이는 것 | 담당 |
|---|---|---|
| 평상시 (자기 몸) | **1인칭 손** | `ViewmodelMotion` |
| 잡고 올라가기 | **모서리 잡은 손** | `MantleRig` |
| 빙의 중 뒤돌아봄 | **남겨진 셸 전신** | `BodyIdleMotion` |
| 상시 (빙의 제외) | **오른손 위 펫 거미** | `SpiderRig` |

네 가지가 **같은 Protag 인스턴스 하나**를 공유한다. 그래서 소유권 분리(§3)가 설계의 중심이다.

**핵심 문제**: 시스템 넷이 같은 뼈를 쓰려 들면 서로 덮어쓴다. 각자 **다른 채널**만 만지도록 나눈다.

## 2. 조사로 확정된 사실

구현 전에 실제로 확인한 것들. 추측이 아니다.

| 항목 | 결과 | 영향 |
|---|---|---|
| Protag 리그 | `R_`/`L_` 접두사. 손가락 **4개**(Pinky 없음) × 3관절 + 끝본 | 기존 도구의 좌우 판별(Mixamo `Right`/`Left`)이 안 맞아 수정함 |
| 거미 모델 | `Spider.fbx`/`SpiderPet.fbx` — **뼈 0개, 스킨 0개** | 다리 IK 불가. 리깅 대기(§11) |
| `ControlTether.handOffset` | 주석: *"오른손 위 펫 거미 자리(§2.6)"* | **줄 시작점은 원래 거미 자리였다.** 카메라 고정 오프셋은 거미가 없어서 둔 임시값 |
| `HackDriver` 공개 멤버 | `Controlled`, `tether`, `viewEntry` 전부 public | 거미가 **수정 없이** 상태를 읽을 수 있다 |
| `ViewEntryController` | `Active`, `Shell` public | 빙의 판정·셸 위치를 읽을 수 있다 |
| 패널 단축키 | F1=이동 튜닝, F2=조명 튜닝 사용 중 | 포팅할 포즈 패널은 **F3/F4**로 재배치 |
| `HandIK.weight` | `Slerp(원래자세, IK해, weight)` — 진짜 블렌드 | §4의 전환 방식이 성립하는 근거 |

## 3. 소유권 — 겹치면 버그

| 시스템 | 만지는 것 | 실행 시점 | 활성 조건 |
|---|---|---|---|
| `PlayerBodyModeController` | 파츠 활성화 · 부모 전환 | Update | 항상 |
| `SpiderRig` | 거미 **월드 TRS** · `tether.originOverride` | Update | 항상 |
| `ViewmodelMotion` | 뷰모델 **루트** TRS | LateUpdate **−50** | **1인칭에서만** |
| `MantleRig` | `HandIK.weight` · `target` · 손가락 **시점** | Update / LateUpdate **−40** | 항상(대기) |
| `BodyIdleMotion` | 척추·목·쇄골 **뼈** (additive) | LateUpdate **−30** | **3인칭에서만** |
| `HandIK` | **팔** 뼈 (어깨·팔꿈치·손목) | LateUpdate 0 | weight > 0 |
| `FingerPoser` | **손가락** 뼈 (스무딩 소유) | LateUpdate 0 | 항상 |

**규칙 셋**

1. `ViewmodelMotion`과 `BodyIdleMotion`은 **절대 동시에 돌지 않는다.** `PlayerBodyModeController`가 모드 전환 시 서로 켜고 끈다.
2. 손가락 스무딩은 `FingerPoser.sustainSpeed`가 **단독 소유**한다. `MantleRig`는 목표값과 **시점**만 준다. 양쪽에서 곡선을 먹이면 이중 스무딩이 된다.
3. 실행 순서는 **루트 → 타깃 → 뼈** 순이어야 한다. 어긋나면 한 프레임 밀린다.
   - `Update`는 모든 `LateUpdate`보다 먼저 돌므로, `MantleRig`의 상태 갱신은 `Update`에 둔다.

## 4. 1인칭 손 ↔ 등반 손 전환

### 4.1 루트를 건드리지 않는다

처음엔 "뷰모델 루트를 아래로 내려 숨긴다"를 검토했다. **기각**한다. 두 가지 이유:

- 루트를 내리면 **어깨까지 내려가** 등반 중 팔이 어깨부터 아래에서 뻗는 모양이 된다.
- 루트는 `ViewmodelMotion`이 소유한다. 소유권이 겹친다(§3).

대신 `HandIK.weight`만 쓴다. `park`(카메라 기준 화면 아래 대기점)에 타깃을 두면:

| weight | 결과 |
|---|---|
| 0 → 1 | 손이 기본 자세에서 **아래로 내려가 사라짐** |
| 1 → 0 | 손이 아래에서 **기본 자세로 올라옴** |

`HandIK`가 이미 원래 자세와 IK 해를 `Slerp`하므로 공짜로 나온다. 루트도 `ViewmodelMotion`도 수정하지 않는다.

### 4.2 상태 기계

| 단계 | 지속 | weight | 타깃 | 손가락 | 보이는 것 |
|---|---|---|---|---|---|
| **Idle** | — | base | — | 0 | 기본 손 |
| **Lowering** | `lowerTime` | base→1 | park 고정 | 0 | 기본손 **아래로 사라짐** |
| **Reaching** | `reachTime` | 1 | park→모서리 | 후반 쥠 | **올라오며 뻗어 잡음** |
| **Holding** | 등반 내내 | 1 | 모서리 고정 | 쥠 | 손이 모서리에 **월드 고정** |
| **Releasing** | `releaseTime` | 1 | 모서리→park | 초반 폄 | **놓고 아래로 사라짐** |
| **Raising** | `raiseTime` | 1→base | park 고정 | 0 | 기본손 **위로 올라옴** |

진입 `내려감 → 올라옴`, 이탈 `내려감 → 올라옴`. 대칭이다.
**손이 안 보이는 바닥 지점에서 시스템이 교대**하므로 팝이 원리적으로 발생하지 않는다.

### 4.3 손 회전은 앵커 두 점에서 유도한다

`AutoTraversal`이 `Show(leftHand, rightHand)`로 넘기는 두 점만으로 기저가 완성된다. 추가 정보가 필요 없다.

```
edgeRight = normalize(rightHand − leftHand)          모서리 축 = 손가락이 감싸는 축
toEdge    = flatten(edgeCenter − 머리위치)
approach  = normalize(toEdge − edgeRight·dot)        직교화 = 손가락이 넘어가는 쪽
baseRot   = LookRotation(approach, up)
```

**`approach`는 `Show()` 시점에 한 번만 잡아 고정한다.** 매 프레임 `transform.forward`로 다시 구하면 고개를 돌릴 때마다 손 회전이 따라 헤엄쳐 **월드 고정의 의미가 사라진다.**

리그마다 손 뼈가 보는 축이 다르므로 `handEulerR`/`handEulerL`로 보정한다(§11에서 실기 조정).

### 4.4 신호가 늦게 오는 문제 — `Prepare()` 추가

`AutoTraversal`은 `BeginPull()`에서 `Show()`를 부른다. 그때는 **이미 몸이 올라가기 시작하는 시점**이라, 손이 모서리에 닿기 전에 당기는 모양이 된다.

| 경로 | `Show()` 전 여유 |
|---|---|
| 도약 후 매달림 | 비행 0.18~0.9초 |
| 벽 앞 바로 잡기 (`directLatchRange`) | **0초** (같은 프레임) |

**결정**: `AutoTraversal.StartFlight()`에 예고 한 줄을 넣는다.

```csharp
if (_rig != null && thenMantle) _rig.Prepare();
```

도약 경로는 비행 시간만큼 여유가 생겨 전체 시퀀스가 자연스럽게 재생된다.
**바로 잡기 경로는 여유가 구조적으로 0**이므로, `MantleRig`가 남은 구간을 압축 재생하도록 만든다. 두 경우를 모두 처리한다.

### 4.5 파라미터

```
lowerTime 0.10 / reachTime 0.14 / releaseTime 0.12 / raiseTime 0.16
parkLocalR/L, parkEulerR/L      카메라 기준 대기 위치·회전
handEulerR/L                    리그 손 뼈 축 보정
palmForwardOffset / palmUpOffset
gripAmount 0.85 / gripCloseAt 0.6 / gripOpenAt 0.3
```

이징은 smoothstep 고정. `AnimationCurve` 노출은 과하다 — 조절할 것은 **시간**이지 곡선 모양이 아니다.

### 4.6 손목 꺾임은 별도 구현하지 않는다

`HandIK.ClampWrist()`가 `wristMaxSwing`(70°)·`wristMaxTwist`(85°)로 이미 처리한다.
타깃 회전이 인체 한계를 넘으면 자동으로 깎인다. **중복 구현하면 서로 싸운다.**

## 5. 3인칭 전신

### 5.1 언제 보이나

**빙의(시점 진입) 중 뒤돌아봤을 때** 남겨진 셸(`viewEntry.Shell`)이 보인다.
외부 조종은 내 시점을 유지하므로 내 몸이 안 보인다.

셸은 항상 제자리에 서 있다(리그만 대상으로 이동). 따라서 **걷기·달리기 애니메이션이 필요 없다.** 서 있는 자세 하나면 된다.

### 5.2 기본 자세 = 포즈 JSON 하나

§2.6이 셸의 자세를 이미 규정한다:

> 본체는 **하늘색 생명줄을 손으로 꽉 쥔 자세**(§6.3).

"자연스럽게 서 있기"가 아니라 **생명줄을 쥔 자세**다. 오른손이 줄을 쥐고 있어야 한다.

`PoseJsonTool`로 `pose_shell_idle.json` 하나 저장하고 3인칭 진입 시 적용한다.
**Animator도 클립도 필요 없다.** (걷기 등이 나중에 필요해지면 `ClipBuildTool` → Animator로 확장. 구조를 막지 않는다.)

### 5.3 `BodyIdleMotion` — 뼈 단위 additive

`ViewmodelMotion` 방식(루트를 통째로 흔듦)은 **쓸 수 없다.** 전신에 적용하면 **발이 미끄러진다.**

`FingerPoser`와 같은 방식으로 간다 — rest 자세를 캡처하고 그 위에 각도를 더한다.

| 레이어 | 뼈 | 내용 |
|---|---|---|
| 호흡 | `Spine02`, `NeckTwist01/02` | 가슴 확장 + 목 미세 상하. ~0.25Hz (4초 주기) |
| 체중 이동 | `Waist`, `Pelvis` | 좌우 미세 롤. ~0.1Hz, 호흡과 위상 어긋남 |
| 팔 늘어짐 | `R/L_Upperarm`, `R/L_Clavicle` | 호흡과 위상차를 둔 미세 회전 |
| 머리 | `Head` | (선택) 아주 가끔 두리번 |
| **발·다리** | — | **건드리지 않는다** — 접지 유지 |

뼈 이름은 배열로 노출해 리그가 바뀌어도 대응한다.
오른손은 생명줄을 쥔 자세를 유지해야 하므로 팔 레이어에서 **오른팔 진폭을 따로 낮출 수 있게** 한다.

### 5.4 모드 전환

Protag 인스턴스는 **하나**다. 파츠를 팔·나머지 두 그룹으로 분류해 전환한다.

| 모드 | 파츠 | 부모 | 활성 시스템 |
|---|---|---|---|
| 1인칭 (자기 몸) | 팔만 | 카메라 하위 | `ViewmodelMotion` |
| 3인칭 (빙의 중) | 전체 | 월드 앵커 | `BodyIdleMotion` |

파츠 분류는 각 파츠의 **본 가중치**로 자동 판정한다(이름이 `tripo_part_21_037` 식이라 의미가 없다).
메시를 잘라내지 않고 **활성화만** 바꾸므로 되돌릴 수 있다.

## 6. 펫 거미

### 6.1 본에 붙이지 않는다

§2.6의 거미는 장식이 아니라 **해킹의 물리적 실체**다. 빙의 시 대상으로 날아가고, 릴레이로 옮겨 다니고, 줄이 그 엉덩이에서 나간다.

따라서 **손목 뼈의 자식으로 묶으면 안 된다.** 떨어져 나갈 수 없다.

**소프트 추종 제약**으로 간다 — 위치는 앵커를 스프링으로 따라가되, 언제든 이탈 가능하다.
부모 재설정 없이 가중치 블렌드만으로 전환되고, 스프링 지연이 생명감을 준다. 1인칭·3인칭에서 동일하게 동작한다.

### 6.2 상태 기계

| 상태 | 위치 | 줄 시작점 | 트리거 |
|---|---|---|---|
| **Perched** | `R_Hand` 앵커 스프링 추종 | 거미 엉덩이 | 기본 |
| **Launching** | 손목 → 대상 비행 | 거미 엉덩이 (실을 끌며) | `viewEntry.Active` 켜짐 |
| **Attached** | 대상에 붙음 | **해제** → 셸 | 도착 |
| **Returning** | 대상 → 손목 | 거미 엉덩이 | `viewEntry.Active` 꺼짐 |

**전환 규칙** (`HackDriver`를 읽기만 한다):

```
viewEntry.Active                      → 빙의    → 대상으로 날아감
Controlled != null && !viewEntry.Active → 외부 조종 → 손목에 남고 줄만 나감
그 외                                  → Perched
```

외부 조종에서 거미가 대상으로 날아가면 줄 길이가 0이 되므로 **손목에 남아야 한다.** §2.6의
*"실 문 채 자세 잡음(손↔대상 연결 유지)"* 와 일치한다.

### 6.2b 다리 — 끝을 팔에 고정하고 몸통이 움직인다

**다리는 4개.** 끝점을 팔에 고정하고, 몸통만 들썩이게 한다.

**보통의 IK와 방향이 반대다.** 손 IK는 몸이 고정이고 손끝이 목표를 좇지만, 여기서는
**발끝이 고정**이고 몸통이 움직인다. 결과적으로 몸통이 들썩일 때 다리가 알아서 굽었다 펴지며,
그게 "팔을 붙잡고 버티는" 모양이 된다(§2.6 "이동: 다리로 손 붙잡고 버팀").

| | 담당 |
|---|---|
| 다리 끝 앵커 4개 | 팔 뼈의 자식 — 팔을 따라 움직인다 |
| 몸통 | `SpiderRig`가 몬다 (들썩임 + 좌우 이동 + 앞뒤 까딱) |
| 다리 각도 | `SpiderLegs`가 2본 IK로 푼다 |

`HandIK`를 재사용하지 않는다 — 인체 관절 제한(팔꿈치 과신전 금지, 어깨 원뿔, 손목 클램프)이
거미 다리엔 방해만 된다. 전용 `SpiderLegs`를 따로 둔다.

**비행 중에는 다리 가중치를 0으로 내린다.** 앵커가 팔에 남아 있어 그대로 두면 다리가 찢어진다.

**점프·착지 반응은 넣지 않는다** — 검토했으나 범위에서 제외했다. 몸통 들썩임만으로 충분하다.

### 6.2c 줄 발사 자세 — 엉덩이를 든다

실이 나갈 때 **엉덩이 마디만** 돌려 방적돌기가 대상을 향하게 한다(§2.6 "방적돌기에서 실 발사").
몸통 자체는 다리에 붙들려 있으므로 통째로 돌리면 다리가 뒤틀린다.

신호는 `ControlTether.Active` / `EndPoint`를 읽는다 — 실이 실제로 그려지는 동안만 조준한다.

### 6.3 회전 안정화 — 독수리 원리

매잡이의 팔이 기울어도 매는 수평을 유지한다. 거미도 같아야 한다.

그냥 추종하면 **손목이 꺾일 때 거미가 같이 뒤집힌다.** `HandIK`는 손목을 ±70° 스윙, ±85° 트위스트까지 꺾으므로, 등반으로 모서리를 잡으면 거미가 거꾸로 매달린다.

- 위치는 **100% 추종**
- 회전은 **yaw만 따라가고 roll/pitch는 감쇠** + 스프링 지연

등반 중 거미는 손목에 **그대로 붙어 있는다**(이동시키지 않음). 안정화만으로 해결된다.

### 6.4 줄 시작점 — `originOverride`

`ControlTether`에 필드 하나와 한 줄을 더한다.

```csharp
public Transform originOverride;   // 지정하면 handOffset 대신 이 지점에서 시작
...
Vector3 a = originOverride != null ? originOverride.position
                                   : from.TransformPoint(handOffset);
```

`SpiderRig`가 Perched/Launching/Returning일 때 자기 엉덩이 앵커를 넣고, Attached일 때 해제한다.
**null이면 기존 동작 그대로**이므로 위험이 낮고, `HackDriver`는 건드리지 않는다.

### 6.5 이번 범위 — §2.6의 일부만

§2.6은 상황별 모션 15종을 명세한다. 대부분 **다리 움직임**이 필요하므로 리깅 후에나 가능하다.

| 이번에 하는 것 | 리깅 후 연결만 하면 되는 것 | 아예 안 하는 것 |
|---|---|---|
| 부착·추종·안정화 | 다리 4개 IK (`SpiderLegs` 완성됨) | 점프·착지 웅크림 |
| 비행 상태 기계 (§6.2) | 엉덩이 조준 (`abdomen` 연결) | 다리 까딱, 두리번 |
| 몸통 들썩임 | | 앞다리 겨냥, 다리 정돈 |
| 줄 시작점 연결 | | 곤두섬 |

`SpiderLegs`는 이미 만들어 뒀다. 리깅된 fbx가 오면 다리 체인 4개와 엉덩이 뼈를
인스펙터에 연결하고 `앵커 자동 생성`을 누르면 된다. 코드 작업은 없다.

## 9. 복원할 도구

퍼지 때 삭제됐고 아직 안 가져온 것들. `ClipBuildTool`이 빠져 **포즈 저장과 재생 사이가 비어 있었다.**

| 파일 | 역할 | 손볼 것 |
|---|---|---|
| `ClipBuildTool.cs` | **JSON 명세 → .anim 클립 (프레임 단위)** | 이름 일반화 |
| `PoseTunePanel.cs` | 재생 타이밍·스프링 실시간 조절 | F2 → **F3** (F2는 조명 패널) |
| `PoseSeqPanel.cs` | 포즈 사이 간격 구간별 조절 | F3 → **F4** |
| `PoseInputBinder.cs` | 키 → 시퀀스 재생 미리보기 | **재설계** — 칼 콤보 전용이라 골격만 남김 |
| `ScreenCenterDot.cs` | 화면 중앙 조준점 | 그대로 |

### 복원되는 작업 흐름

```
씬에서 자세 잡기
  → PoseJsonTool        pose_<이름>.json 저장
  → anim_<이름>.json    어느 포즈를 몇 프레임에, 어떤 이징으로 (손으로 작성)
  → ClipBuildTool       .anim 클립으로 굽기
  → PosePlayer + F3/F4  Play 중 타이밍 조절하며 확인
```

`anim_*.json` 형식:

```json
{ "clip": "Assets/.../Shell_Idle.anim", "frameRate": 60,
  "keys": [ {"frame":0,  "pose":"shell_idle", "ease":"auto"},
            {"frame":8,  "pose":"reach",      "ease":"flat"},
            {"frame":14, "pose":"grab",       "ease":"linear"} ] }
```

이징: `auto`(부드럽게) / `flat`(그 지점에서 멈춤) / `linear`(직선, 급가속) / `step`(즉시 전환).
회전은 쿼터니언 4채널로 굽되 연속 키의 부호를 맞춰 한 바퀴 도는 현상을 막는다.

## 11. 미결 · 범위 밖

### 구현으로 해결할 수 없는 것 (실기에서 눈으로 잡아야 함)

- `handEulerR/L` — 리그 손 뼈가 보는 축. 모델마다 다르다.
- `parkLocalR/L` — 화면 아래 대기 위치.
- `palmForwardOffset` / `palmUpOffset` — 손바닥이 모서리에 얹히는 정도.
- 거미 손목 앵커 위치·엉덩이 앵커 위치.
- **셸 idle 포즈 자체** — 생명줄을 쥔 자세(§5.2)는 손으로 잡아야 한다.

도구와 기즈모를 갖춰두고, §8 씬에서 조정한다.

### 이번 범위 밖

| 항목 | 이유 |
|---|---|
| **거미 다리 IK** | 모델에 뼈가 0개. 리깅 진행 중 — 오면 얹는다 |
| **등반을 클립으로 굽기** | 모서리 위치·높이·각도가 매번 다르다. 절차적이어야 한다 |
| **등반 중 팔꿈치 폴 제어** | 1차는 뷰모델 고정 폴. 어색하면 그때 추가 |
| **3인칭 걷기·달리기** | 셸은 제자리에 서 있다(§5.1). 필요해지면 `ClipBuildTool`로 확장 |
| **VR** | `ViewmodelCamera`가 URP 오버레이라 XR 스테레오와 충돌. 별도 과제 |
