## 0. 이 세션의 결론 요약

지시 3건(A/B/C) 중 **C는 구현했다가 폐기**했고, 나머지는 형태가 바뀌었다.
그보다 **실기에서 드러난 판정 버그 10여 건이 본체**였다. 아래 §2가 핵심이다.

## 1. 지시 3건의 처리 결과

| 지시 | 결과 |
|---|---|
| **A. 원뿔 안 최근접** | ✅ 채택. `distancePenalty` 제거, **수평(XZ) 거리** 오름차순 정렬 후 첫 통과 후보. 원뿔은 필터로만. |
| **B. 비행 시간 min/max** | ✅ 채택하되 **재설계**. `flightGravity` 자체를 없앴다 — 시간은 **실제 이동거리/`airSpeedCap`** 로 정하고 `[minFlightTime, maxFlightTime]`로 클램프, **중력은 `g=(k/total)²`로 역산**. (`k=√(2·rise)+√(2·fall)`) |
| **C. 상승/하강 지수 분리** | ❌ **구현 후 폐기.** 수직이 이미 탄도라 가감속이 물리로 들어 있는데 시간 워핑을 얹으니 **정점에서 감속이 이중**으로 걸려 "공중에서 걸리는" 느낌이 났다. 지금은 **워핑 없이 실제 시간 그대로** 재생한다. |

> B의 재설계 이유: 기준 중력 탄도 시간을 하한으로 쓰면 **0.5m 단차도 0.45초짜리 큰 포물선**이 되어
> 작은 턱마다 조작이 끊겼다. 이동거리 기반으로 바꾸니 짧은 도약은 0.18초로 끝난다.

## 2. 실기 피드백 → 원인 → 조치 (이번 세션의 본체)

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | 가장자리에서 **야금야금 밀려 끼고**, 그 자리에선 도약도 안 됨 | 발동 판정을 **결과 속도**(`move.Output`)로 해서, 가장자리 정지가 속도를 깎는 순간 "안 움직인다"로 뒤집혀 **스스로 풀림** | `FirstPersonPlayer.Wish`(이동 입력) 노출 → **입력 의도 기준**으로 판정 |
| 2 | 착지 직후 가장자리 낙하 방지가 빔 | 쿨다운이 도약·등반뿐 아니라 **정지까지** 막음 | 쿨다운은 **개시만** 막도록 분리 |
| 3 | **평지에서 매달림 등반이 100% 거부** (조용히 return) | 매달림 발 위치 = `모서리−팔길이−키` = 항상 발밑(바닥 속) → `BlockedAt` 항상 참 | `HangSpaceOk()` — **서 있는 높이 이하면 검사 생략**. 로그도 추가 |
| 4 | 초록으로 표시되는데 등반 안 됨 | `ClimbLedge` 콜라이더가 건물보다 커서 플레이어가 **footprint 안**에 서게 됨 → 내가 넣은 "바깥면 검사"가 네 면 전부 거부 | footprint **안일 때만** '가장 가까운 면'으로 fallback. 밖에 있을 땐 그대로라 **먼 면 오발동은 계속 차단** |
| 5 | 경사·발판에서 도약이 안 됨 | `PathClear`가 **출발 지점 발밑 지형**에 걸림 | 출발 근처(반경 `r*2+0.3`) 샘플 스킵 + **오르려는 대상 콜라이더 제외** |
| 6 | 기즈모가 빨강이라 "못 오른다"고 오판 | 기즈모가 **오브젝트 전체 높이**로 색을 칠함(판정은 발 기준 상대 높이인데) | 면별로 **바깥에서 아래로 레이 → 설 바닥 찾아** "그 앞에 섰을 때 오를 높이" 표시. 숫자 라벨 + 노랑(바닥 없음) |
| 7 | 등반·착지 순간 화면이 한 번 튐 | CC를 다시 켤 때 **`Physics.SyncTransforms()` 누락** → 물리 쪽 위치가 옛값 | 두 지점(직행 착지·등반 종료)에 추가 |
| 8 | 벽→바닥 넘어가는 게 뻑뻑 | Over 구간이 **1.25m를 0.15초**에 (≈8m/s) | `overDuration` 0.28s + **smoothstep** |
| 9 | 착지 후 가끔 떨어짐 | `landingInset` 0.45m뿐이라 캡슐(r=0.3)이 테두리에 걸침 | `SettleLanding()` — **안쪽으로 반지름만큼 더** + 아래 레이로 **바닥 확인**(없으면 후보 제외) |
| 10 | 옆걸음·대각선으로 가장자리 가면 그냥 떨어짐 | 가장자리 감지·궤적은 **이동 방향** 기준인데 원뿔만 **시선** 기준 | 원뿔 축을 **시선 OR 이동 방향** 둘 다 인정 |
| 11 | 대각선 도약만 어색 | 베지어 출발 접선이 이동 방향이라, 목표가 옆이면 **크게 스윙** | 휘어짐(`curveBias`)을 **정렬도에 비례** — 벌어질수록 직선 |
| 12 | 낮은 단차 앞에서 **낑겨서 못 움직임** | `DropDepth` 프로브가 **발+0.1m**라 코앞 턱 **내부에서 출발** → 유니티가 그 콜라이더를 못 잡음 → **무저갱 오판 → EdgeStop** | 프로브를 **발+0.6m**에서 쏘고, 그래도 지형 안이면 `CheckSphere`로 감지해 **낙차 0** 처리 |
| 13 | (12 시도 중) stepOffset 0.45로 올렸더니 더 심해짐 | 크게 잡으면 컨트롤러가 턱 면을 타고 떠 **`Below` 접지가 풀림** → `Grounded=false`라 등반 판정 자체가 안 돎 | **0.3(기본값) 복귀**, `minHeight`도 **0.3**으로 낮춰 사각지대 제거 |
| 14 | 바닥에서 카메라가 계속 위아래로 흔들림 | `landMinSpeed`를 2.0으로 내렸는데 **접지 중 `_vy`가 정확히 -2** → 접지 깜빡일 때마다 발화 | **4.5**로 (0.5m 미만 낙하는 무시) |
| 15 | "업킥" 체감 없음 | 침하 0.05/m vs 킥 0.055/m, 지속도 0.18 vs 0.15 → **서로 상쇄** | (그리고 애초에 원한 건 상하가 아니라 **좌우 롤**이었음 → §3) |
| 16 | 앞의 낮은 단차 대신 **멀리 있는 발판으로** 도약 | 근접 하한 `dist < 0.6f`에 걸려 **가까운 후보가 목록에서 빠짐** | 하한 0.2m로 낮추고, 대신 **"의미 있는 이동" 필터** 도입 |
| 17 | (16 직후) 앞으로 뛰면 **제자리 왕복** | 하한을 풀었더니 **서 있는 발판의 자기 모서리**(거리 0.3m·높이차 0)가 후보로 들어옴 | `dh ≥ minHeight` **또는** `dh ≤ -safeDrop` **또는** `dist ≥ 0.6m` 중 하나는 있어야 후보 |
| 18 | 낮은 턱에서도 화면 연출이 나옴 | `StartFlight`가 크기 무관 항상 발화 | `feelMinTravel`(1.2m) 미만이면 연출 생략 |
| 19 | 낮은 단차는 안 쳐다봐도 넘고 싶다 | 전방 원뿔이 모든 높이에 적용 | `lowStepHeight`(0.7m) 이하는 **방향 판정 생략** |

## 3. 화면 연출 — 상하 킥 → **롤 킥**으로

"박차기 느낌"의 요구는 **카메라 상하 이동이 아니라 좌우 기울임**이었다(등반 당김의 교차 기울임과 같은 계열).

- `MotionFeel`에 **롤 킥** 추가: `sin(u·cycles·2π)·(1−u)` 감쇠 진동. **방향은 매번 반대쪽부터.**
  - 도약 `3.5° / 0.26s / 1.25왕복`, 착지 `2.5° / 0.3s / 1.25왕복`
- 상하 킥(`launchKick*`/`landKick*`)은 필드만 남기고 **기본 0**. 필요하면 F1에서 켠다.
- ⚠️ VR에선 `vrRollScale` 기본 0이라 롤이 안 나온다. 멀미 실측 후 올릴 것.

## 4. 현재 기본값 (전부 F1에서 조절 가능)

```
이동:      maxSpeed 6 · accel 40 · decel 60 · airControl 0.35
단차:      CC.stepOffset 0.3  ≥  minHeight 0.3   (겹치게 — 사각지대 금지)
           lowStepHeight 0.7 (이하는 방향 판정 없음)
등반:      maxDirectUp 1.1 · maxMantleUp 2.0 · directLatchRange 1.0
낙차:      safeDrop 0.6 · maxSafeFall 2.5 · maxDropTarget 4.0
도약:      coneAngle 25 · jumpSearchRadius 8 · airSpeedCap 7
           minFlightTime 0.18 · maxFlightTime 0.9 · clearance 0.35 · curveBias 0.35
           pathSamples 8 · feelMinTravel 1.2
등반연출:  pullDuration 0.25~0.45 · overDuration 0.28 · exitBoost 4.5/0.08s
연출:      landMinSpeed 4.5 · 롤킥 도약3.5°/착지2.5°
```

**불변식 2개 — 깨지 말 것**
1. `minHeight ≤ CC.stepOffset` — 어기면 그 사이 높이를 엔진도 등반도 처리 못 해 **낀다**.
2. `landMinSpeed > 2.0` — 접지 중 수직 속도가 -2로 고정이라, 이하로 두면 **상시 발화**한다.

## 5. 디버깅 방법

- **F1** → `▶ 잡고 올라가기` 펼치면 맨 아래 **`판정 로그`** 체크박스(기본 접혀 있음).
- 로그 형식:
  ```
  [Jump] 후보 탈락 — 제자리 (거리 0.32m · 높이차 0.01m) @Wall
  [Jump] 후보 탈락 — 착지 바닥 없음 / 원뿔 밖 / 높이차 / 착지 막힘 / 매달림 막힘 / 경로 막힘
  [Climb] 대상 없음 — 콜라이더 4개 중 ClimbLedge 3개 (면 0 · 방향/거리 1 · 높이 2 · 막힘 0)
  [Climb] 거부 — 매달릴 공간 막힘 (h=1.60m)
  ```
  `ClimbLedge N개`가 **0이면 그 오브젝트에 컴포넌트가 없는 것**이다(코드 문제 아님).
- 씬뷰 기즈모: 면별 **오를 높이 숫자** + 초록(가능)/빨강(너무 높음)/노랑(설 바닥 없음).

## 6. 남은 일

### 즉시
- **마지막 수정(§2-17 왕복 방지) 실기 검증 안 됨.** 이어받는 사람이 먼저 확인할 것.
- **`ClimbLedge`가 씬에 5개뿐**(전부 `wall 01` 계열). 오르게 하려는 오브젝트마다 붙여야 한다.
  → **선택한 오브젝트들에 일괄 부착하는 에디터 툴**을 만들 것을 권한다(반복 작업이 확실하다).

### 구조
- `AutoTraversal`이 **800줄 가까이**. 목표 선정 / 궤적 / 등반 시퀀스로 분리할 여지.
- F1 패널은 **PC 전용**(OnGUI). 값이 확정되면 코드 기본값으로 굳힐 것.

### 미검증
- **VR 실기 전무.** `vrRollScale 0`, 지연 보상 수치 전부 추정값.
- 네트워크 입력 경로(`NetworkHexInputSource.Map`) 여전히 null — VR 입력 죽어 있음.
