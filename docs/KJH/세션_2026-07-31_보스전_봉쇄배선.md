## 0. ⚠️ 제일 먼저 — MainScene 저장 여부를 확인할 것

이 세션의 씬 작업이 **미저장 상태로 끝났을 수 있다.** 아래가 다 들어 있어야 한다.

```
MegaRobot        루트 y = -15.31452          (걷기 높이)
                 + BossChase, BossSpineAim, PartsPoser 신규 부착
                 + Head/HeadAim 마커 신규
입구 4곳          walkRootY = -15.31452
                 armPoser · spineAim · chase · pressFace 배선
                 SealWall 자식 신규
WedgePoint 4곳    로컬 (-6.273, 13.260, -6.829)
Model_Presser 4대 Head/PressFace 마커 신규
전환점 프레스      startExtension = 1
```

**확인 방법**: 아래 §7 검증 스니펫을 `execute_code`로 돌리면 전부 한 번에 나온다.

### ⚠️ 플레이 중에 붙인 컴포넌트는 사라진다
이 세션에서 실제로 겪었다. `PartsPoser`를 붙인 직후 사용자가 Play를 눌러, 정지하면서 컴포넌트가
통째로 날아갔다(같이 붙인 `BossSpineAim`은 Play 전이라 살아남아 대비가 됐다).
**씬을 만지기 전에 `EditorApplication.isPlaying`을 반드시 확인할 것.**

## 1. 고친 버그 — 전부 실측으로 원인 확정

### 1.1 시작하자마자 유압프레스가 올라간다

`StageEntranceFlow.LockPress()`에 있던 한 줄이 원인이었다(내가 앞 세션에 쓴 줄이다).

```csharp
pressActuator.Target = 0f;   // "홈으로 되돌린다" ← 틀린 가정
```

프레스는 축이 아래(−Y)라 **`t=0`이 완전히 올라간 상태**다. `Awake()`가 `LockPress()`를 부르므로
모든 프레스가 시작 즉시 올라갔다. 시작 상태는 `startExtension`이 소유해야 한다 → **줄 삭제.**

### 1.2 대왕프레스 해킹이 안 된다

1.1을 고치자 드러난 버그다. `LockPress()`는 `Hackable.enabled = false`도 하는데,
`Awake()`가 `PlayerTrigger` 입구에서 이걸 불러 **전반부 내내 대왕프레스를 못 만졌다.**

전까지 안 드러난 이유: 1.1의 `Target = 0f`가 프레스를 강제로 열어 둬서 아무도 막힌 걸 못 느꼈다.

```csharp
// Awake — 두 진입 모드 다 평상시(= 일반 유압프레스)로 시작한다
RestorePress();
```
`ResetForRestart()`도 같은 이유로 `LockPress()` → `RestorePress()`로 바꿨다.
`LockPress()`는 이제 `Succeed()`·`HandleTimeout()`에서만 불린다(낑김 사이클 종료 직후 — 정당한 용도).

### 1.3 게임 시작하자마자 보스가 쫓아온다

`BossChase.Update()`가 `BossChaseState.Active`를 안 봤다. `move` 기본값이 `true`라 Play 즉시 전진했다.

```csharp
if (!BossChaseState.Active) return;   // 전환점 전엔 걷지 않는다
```

> **가설 하나가 틀렸다**: "도메인 리로드가 꺼져 있어 `BossChaseState.Active`가 이전 Play에서
> 눌어붙는다"고 단정했는데, 라이브로 찍어 보니 `Active = False`였다. **실측이 반증했다.**
> `RunCheckpoints.Start()`에 초기화를 넣자는 제안은 **불필요하므로 철회**했다.

### 1.4 (1.3을 고쳐도) 보스가 계속 걷는 것처럼 보인다

**이동이 아니라 애니메이션이었다.** 위치는 배치 좌표 그대로였는데 `Animator.speed = 1`로 걷기 클립이
제자리에서 루프하고 있었다. 배속을 정하는 줄이 새 가드보다 아래라 도달하지 못했다.

→ 사용자 판단: **"등장 전에는 숨김"**. §2.1로 해결했다.

### 1.5 보스 몸이 전환점 프레스 조준을 막는다

```
보스 콜라이더  x 474.0~511.6   y −16.3~40.9   z −19.8~21.7
전환점 프레스   x 485.7  z 7  헤드 밑면 y ≈ 10.9   → 콜라이더 <b>안에</b> 완전히 들어감
```

50배 스케일 보스가 프레스를 통째로 감싸고 있어 **해킹 레이가 프레스보다 보스에 먼저 맞았다.**
숨김(§2.1)이 콜라이더까지 끄므로 같이 해결된다. 렌더러만 껐다면 이건 안 고쳐졌다.

### 1.6 보스 루트가 "낑김 높이"로 저장돼 있었다

```
저장돼 있던 값  y = -36.06452   ← 낑김 높이
있어야 할 값    y = -15.31452   ← 걷기 높이 (사용자 실측)
```
앞 세션 문서 §0에 "`MegaRobot 루트 y −37.00 → −7.56` 미저장"이라 적혀 있던 그 변경이 날아간 것이다.

> **★ 앞 문서의 `-7.56`은 틀린 값이다.** 사용자 확정값은 **걷기 −15.31452 / 낑김 −36.06452**.
> 입구 4곳의 `walkRootY`도 전부 `-7.564521789550781`로 들어가 있어 같이 고쳤다.
> 안 고치면 낑김이 끝날 때 `RestoreWalkHeight()`가 8m 틀린 높이로 되돌린다.

### 1.7 ★ `WedgePoint` 4곳이 틀린 자리였다 (가장 위험했던 것)

**내가 앞서 "이미 끝나 있다"고 잘못 보고했다.** 4곳의 로컬 좌표가 서로 같길래 배선만 보고
값을 검산하지 않았다. 실제로는:

```
기존   로컬 (0, 10, 0)      → 낑김 루트 y = -39.325   (정답 -36.065, 3.26m 어긋남)
                              게다가 x·z도 6.27m / 6.83m 밀려 <b>입구 옆으로 비껴 박음</b>
수정   로컬 (-6.273, 13.260, -6.829)
검산   낑김 루트 = (490.46280, -36.06452, 0.86326)  ← x·z 이동 없이 수직으로만 20.75m 하강
```

역산 방법(다시 잴 일이 있을 때):
```
drop      = walkY - wedgeY = 20.75
wantWorld = HeadContact 월드 위치에서 y만 drop 만큼 내린 점
localOffset = Entrance.InverseTransformPoint(wantWorld)
```
**이게 틀리면 프레스가 머리에 영영 안 닿아 `AtLimit`이 안 나고 낑긴 채 타임아웃만 반복된다.**

### 1.8 `pressFace` 미지정 — 판정이 5m 일찍 났다

`StageEntranceFlow.PressFaceWorld`가 `pressFace`가 비면 헤드 **피벗**을 쓴다. 실측 결과 피벗과
메시 밑면이 **정확히 5.0324m** 차이났다(4대 전부 동일 — 같은 프리팹).

→ `Model_Presser/Head/PressFace` 마커 4개 신규 생성(렌더러 바운즈 실측으로 밑면에 배치) + 배선.

### 1.9 팔 봉쇄가 아무 일도 안 했다 — 메커니즘이 두 개였다

```
캡처해 둔 것   Art/Boss/BossArmSealPose.asset
               PartsPose · 스냅샷 "홈"/"봉쇄" · 팔 본 14개 로컬 TRS
               재생하려면 PartsPoser 필요 → <b>씬에 없었다</b>
코드가 쓰던 것  arms.Aim(sealHand, sealHandTarget.position, ...)   2본 IK
               sealHandTarget이 없어 <b>호출조차 안 됐다</b>
```

**자세 애셋 쪽이 옳다.** 본 로컬 값이라 입구마다 좌표를 안 잡아도 4곳에서 동일하게 나오고,
무엇보다 사용자가 눈으로 확정한 자세다(*"딱 내가 원하는 자세야"*). §2.3으로 전환했다.

### 1.10 `BossSpineAim`이 편집 모드에서 씬을 오염시켰다

`[ExecuteAlways]`라 에디터에서 `Main Camera`를 향해 계속 허리를 굽힌다. 이 때문에
**측정이 한 번 통째로 틀렸다** — `HeadContact`가 걷기 자세에서 벗어나 낑김 루트가
`502.80`으로 나왔다(정답 `490.46`, **12m 오차**).

→ `BossArmRig`와 같은 규약으로 게이트를 넣었다. `editorPreview`(기본 꺼짐)를 켤 때만
편집 모드에서 동작하고, 끄는 그 프레임에만 한 번 홈으로 복원한 뒤 손을 뗀다.

## 2. 새로 만든 것

### 2.1 보스 숨김 — `StageEntranceFlow.SetBossHidden()`

**게임오브젝트 전체를 끈다.** 렌더러만 끄면 §1.5가 안 고쳐진다.

| 시점 | 동작 |
|---|---|
| `Awake()` | 추격 중이 아니면 숨김 |
| `BeginBurst()` | **등장** — 루트를 옮기기 **전에** 켜야 그 프레임부터 보인다 |
| `Begin()` | **등장** (`PlayerTrigger` 입구는 `Bursting`을 안 거친다) |
| `ResetForRestart()` | 추격 중이 아니면 다시 숨김 |

- 한 번 등장하면 다시 숨기지 않는다 — 추격 중엔 입구 사이를 걸어와야 한다.
- 이미 원하는 상태면 아무것도 안 하므로 입구 4곳이 각자 불러도 순서 무관.
- `bossVisual`을 비우면 `bossRoot`의 게임오브젝트를 쓴다 — **배선 불필요.**

### 2.2 추격 시작 시 전 프레스 상승 — `HandleChaseActiveChanged()`

사용자 확정: *"보스 추격을 시작할 때는 유압프레스를 끝까지 올려야겠지."*

`BossChaseState.OnActiveChanged`를 구독해, 추격이 열리는 순간 `Idle`인 나머지 입구의 프레스를
`Flick(0f)`로 끝까지 올리고 잠근 채로 둔다. 전반부에 플레이어가 어디까지 열어 뒀든 무관하게
**후반부 도주로가 열려 있고 낑길 자리가 확보된다.**

```
전반부 시작   프레스가 내려와 입구를 막음        startExtension = 1
플레이어      직접 올려서 지나감                 수동
★ 추격 시작   나머지 3곳이 즉시 끝까지 올라감    t = 0
후반부        낑긴 머리 위로 내려찍음            LimitT까지
```

### 2.3 팔 봉쇄 — 소유권 인계가 핵심

`StageEntranceFlow`에 `armPoser`·`spineAim`·`armSealPose`·`armHomePose` 필드 추가.

**팔 본을 건드리는 컴포넌트가 셋이라, 자세를 재생하기 전에 전부 꺼서 소유권을 가져와야 한다.**

| 컴포넌트 | 그냥 두면 | 처리 |
|---|---|---|
| `BossArmRig` (order 50) | `LateUpdate`에서 IK로 덮어씀 | 봉쇄 동안 `enabled = false` |
| `BossChase` (order 40) | 매 프레임 `_rig.Aim()`으로 벽 짚기 지시 | 봉쇄 동안 `enabled = false` |
| `BossSpineAim` (order 45) | 허리를 굽혀 **어깨째 손을 끌고 감** | 봉쇄 동안 `enabled = false` |

```
SealArms()          chase → spineAim → arms 순으로 끄고 armPoser.GoTo("봉쇄")
ReleaseArms()       armPoser.GoTo("홈")   ※ 리그는 여기서 안 켠다
RestoreArmOwners()  Finish()에서 셋 다 되살림
```

> ⚠️ **끄는 것이 먼저다.** `BossArmRig.OnDisable()`이 `RestoreHome()`을 부르므로,
> 순서가 반대면 방금 재생한 봉쇄 자세가 홈으로 지워진다. 지금 순서면 홈에서 출발해
> 봉쇄로 보간되어 오히려 자연스럽다.

> ⚠️ `ReleaseArms()`에서 리그를 안 켜는 이유: 보간이 끝나기 전에 켜면 IK가 도중에 낚아챈다.
> 사이클이 끝나는 `Finish()`에서 한꺼번에 돌려준다.

`armPoser`가 없으면 예전 IK 경로(`sealHandTarget`)로 떨어지므로 기존 구성도 안 깨진다.

### 2.4 `SealWall` 4곳 — 위치는 **입구가 아니다**

봉쇄 자세를 실제로 적용해 손 위치를 재서 정했다(추측 금지).

```
L_Palm  (457.42, 4.13, -2.01)
R_Palm  (457.42, 4.13,  2.63)     두 손 간격 4.64m
입구     (485.70, 0.00,  7.00)
→ 입구 기준 로컬 x = -28.28
```

보스가 −X를 보고 팔이 33m 넘게 뻗어 있어, **손은 입구에서 28m 떨어진 플레이어 쪽 바닥을 짚는다.**

```
       ← 플레이어 도주 방향(−X)
  [손 x=457]                  [입구/프레스 x=485.7]   [보스 x=490]
       ↑                              ↑
   뒤로 못 감                  보스 머리가 물고 있어 앞으로도 못 감
              ─── 이 사이에 갇힌다 ───
```

즉 역할은 "출구 차단"이 아니라 **도주로 차단**이다. 처음에 입구 자리에 만들었다가 재배치했다.

| 입구 | 벽 x | 입구 x |
|---|---|---|
| `Entrance_0_전환점` | 457.4 | 485.7 |
| `Entrance_1_S3` | 263.2 | 291.5 |
| `Entrance_2_S2` | 149.7 | 178.0 |
| `Entrance_3_S1` | 36.2 | 64.5 |

크기 `4 × 20 × 80`(로컬 오프셋 `(-28.28, 0, 0)`, center `(0,10,0)`), 평소 `enabled = false`.
넘거나 옆으로 돌아가는 것을 확실히 막으려고 넉넉히 잡은 **임시 치수**다.
**팔은 바닥 근처(y≈4)를 짚는데 벽은 y 0~20이라 팔보다 높다** — 사용자 확인 대기.

### 2.5 `tp` 콘솔 명령

```
tp        체크포인트 목록
tp <번호>  0=게임시작 1~3=스테이지1~3 4=보스추격직전
```
`RunCheckpoints.MoveTo()`를 그대로 쓴다. **부활 지점(`RunCheckpoints.Current`)은 안 건드린다** —
테스트 이동일 뿐 저장 지점을 바꾸는 게 아니다.

### 2.6 `BossChase` 부착 · `target` 늦은 바인딩

플레이어는 씬 오브젝트가 아니라 런타임 스폰 프리팹이라 인스펙터에서 연결할 수 없다.
`GameOverManager`와 같은 방식으로 `Update`에서 `FirstPersonPlayer.Instance`를 잡는다.
(`BossSpineAim.target`은 원래부터 `Camera.main` 폴백이 있어 배선 불필요.)

```
BossChaseState.End()           부르는 곳 없음
StageEntranceFlow.OnFinished   구독하는 곳 없음
"게임 클리어" 담당 스크립트      존재하지 않음
```
마지막 입구(`Entrance_3_S1`)에서 성공해도 **추격이 끝나지도, 게임이 클리어되지도 않는다.**
`CrushCount`만 조용히 올라간다.

**사용자 확정 연출**: 애니 클립 없이 **절차적으로** — 허리가 굽고 몸이 굽으며 머리가 뒤로 가서
나자빠진다. (`BossSpineAim`이 이미 척추 본을 소유하므로 그 자리를 쓰면 된다.)

미확정 사항 3가지 — **착수 전에 물어볼 것**:
1. "마지막"을 어떻게 판정할지 — `StageEntranceFlow`에 `isFinalEntrance` 플래그를 두는 안
2. 쓰러진 뒤 무엇을 할지 — 클리어 UI가 씬에 아예 없다(별도 작업)
3. 척추 본 이름 — `Waist`/`Spine01`/`Spine02`/`Head` 확인됨

### 4.2 실기 검증 (사용자 눈 필요)

1. `tp 4` → 프레스 살짝 올리기 → 등장·낑김·봉쇄·6초 사망·내려찍기 성공
2. **등장 순간 팔이 정상인지** — `SetActive` 재활성화로 `BossArmRig`가 재초기화될 수 있다
3. `SealWall` 치수 — 팔보다 높은 것이 맞는지("팔 밑으로 기어나가는 게 보여야 한다"면 낮춘다)
4. 통로 바닥 이음새(`x=113.5·227·340.5`)에서 **보스 하반신이 드러나는지**
5. 보스 속도(`walkSpeed 12`, `speedFar 16`, `speedNear 5`) — 전부 스크립트 기본값

### 4.3 보류 항목

- `geo`(`PartsPoser` + 입구 찌그러짐 자세) — 사용자가 미루자고 했다
- 체크포인트 `CP_4`가 x=410.5→430.5로 전환점(485.7)보다 앞 — 의도 확인 필요

## 5. 이번에 겪은 함정

**배선만 보고 "끝났다"고 하지 말 것.** §1.7이 그 사례다. `WedgePoint` 4곳이 서로 같은 값이라
정리된 줄 알았는데, **값 자체가 틀려** 보스가 입구 옆으로 비껴 박는 상태였다. 4곳이 일관되게
틀릴 수도 있다 — **일관성은 정확성의 증거가 아니다.**

**`[ExecuteAlways]` 컴포넌트는 측정을 오염시킨다.** §1.10. 재기 전에 껐다가, 다 재고 되살려야 한다.
`BossArmRig`는 이미 이 대비가 돼 있었는데 `BossSpineAim`은 없었다 — 새로 붙이는 리그 계열은
이 규약을 먼저 확인할 것.

**하나의 증상에 하나의 원인이라고 가정하지 말 것.** "보스가 걷는다"는 (1) 가드 없음 → 고침 →
(2) 애니메이션 제자리걸음이 남았고, "프레스가 안 먹힌다"는 (3) 콜라이더 가림이었다.
**세 원인이 숨김 하나로 정리됐지만, 그건 결과였지 처음부터 안 것이 아니다.**

**추측을 사실처럼 말하지 말 것.** §1.3에서 "도메인 리로드 때문"이라고 단정했다가 실측에
반증당했다. `Active`를 한 번 찍어 보는 데 드는 비용이 훨씬 쌌다.

**플레이 모드를 매번 확인할 것.** §0. 씬 변경도, 컴포넌트 부착도 전부 날아간다.
