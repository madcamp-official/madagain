### 1.1 `GameBoot.cs` — `farClip` / `layerCullRules`

```csharp
[Header("렌더 거리 (모바일 VR 부하의 최대 변수)")]
public float farClip = 40f;   // 150 → 100 → 50 → 40 순서로 낮춰가며 테스트 중. 아직 확정 아님

[System.Serializable]
public struct LayerCullRule { public string layerName; public float distance; }
public LayerCullRule[] layerCullRules = new LayerCullRule[0];
```

`EnsureCamera()`에서 `farClipPlane = farClip` 적용 + `ApplyLayerCullDistances(c)` 호출.
**`layerCullRules`는 만들어만 놓았고 아직 아무 항목도 안 채웠다** — 배경만 따로 더 멀리 살리고
싶을 때 쓰는 용도(§4 참고).

### 1.2 `DevConsole.cs` — `far` 명령

```
far           현재 far clip 값 출력
far <거리>     즉시 적용 + 그 거리 안 렌더러 수/비율 출력
```

**⚠️ 이 명령이 세는 "렌더러 수"는 실제 부하 수치가 아니다.** `Renderer.bounds.ClosestPoint(eye)`
거리로 후보만 센 것 — 진짜 Batches/Tris/FPS는 **Play 중 Game 뷰 Stats 패널**에서만 확인 가능하다.
과거 세션에서 이 구분을 흐려 잘못된 결론(6.45M 버텍스 등, 중복 카운트)을 낸 적이 있다
([메인씬통합_체크포인트 §5](세션_2026-07-31_메인씬통합_체크포인트.md)의 자기 정정 참고).

## 2. 측정한 것 — 거리별 렌더러/삼각형 후보 (에디터 정적 분석, Play 아님)

기준점 = 1스테이지 체크포인트 근처 `(50.00, 1.60, 0.00)`. 활성 렌더러 총 9,639개.

| far(m) | 렌더러 | 비율 | 삼각형(참고, 서브메시0만) |
|---|---|---|---|
| 30 | 374 | 3.9% | 118,711 |
| 40 | 602 | 6.2% | 171,352 |
| 50 | 906 | 9.4% | 238,286 |
| 60 | 1,217 | 12.6% | 410,404 |
| 80 | 1,785 | 18.5% | 590,454 |
| 100 | 2,439 | 25.3% | 1,044,612 |
| 150 | 4,097 | 42.5% | 1,607,975 |

**100→50에서 렌더러 2.7배, 삼각형 4.4배 감소.** 100m 근처에 무거운 덩어리(옆 스테이지 벽·홀더)가
몰려 있어 100↔50 구간의 낙폭이 유독 크다.

### ⚠️ 이 표를 결론으로 쓰지 말 것

- 삼각형 수는 **서브메시 0번만** 센 것이라 실제보다 적게 잡혔을 수 있다
- 정적 배칭이 걸린 메시는 **중복 카운트** 가능성이 있다(레일 세그먼트에서 실제로 발견된 패턴)
- **실측(Play 중 Stats)은 딱 한 번만** 했다 — 아래 §3

## 3. 유일한 실측 (사용자 제공 Stats 스크린샷)

farClip이 얼마였는지 정확히 특정 안 된 시점(100~150 사이로 추정, 재확인 필요)에:

```
FPS 14.1 / 프레임 70.8ms
GPU Frametime  ?   (스크린샷에 값 있었으나 본 문서 작성 시점 재확인 안 함)
```

**CPU 바운드로 판단**(Global Frametime과 GPU Frametime 격차 근거) — 단, 이 판단도 값 하나로
내린 것이라 확정은 아니다. 후속자는 **`far 40`으로 바꾼 지금 상태에서 Stats를 다시 찍어** 비교할 것.

보스 `SkinnedMeshRenderer`(95개, `Animator.AlwaysAnimate`)가 CPU 비용 후보로 지목됐으나
**사용자가 명시적으로 보류 지시**: "보스가 헛도는건 문제가아님. 어짜피 후반부에서 보스가 생길건데."
→ **지금 손대지 말 것.** 나중에 실기 숫자가 여유 없을 때만 `cullingMode`를 `CullUpdateTransforms`로.

## 4. 다음에 할 것

1. **`far 40`으로 Play → Stats 재측정** (Batches/Tris/FPS) — 이게 최우선, 아직 안 함
2. **눈으로 확인**: 스테이지 간격이 113.5m인데 far=40은 그 1/3 수준이다. 복도 끝·문 너머가
   안개처럼 잘려 보이는지, 이동 중 팝인이 있는지 반드시 볼 것
3. 잘려 보이면:
   - `far`를 60~80으로 올리거나
   - `layerCullRules`로 **구조물은 짧게, 배경만 길게** 차등 적용(코드는 이미 있음, 값만 채우면 됨)
4. far clip 다음 후보(효과 대비 작업량 순, 사용자에게 이미 구두로 전달한 목록):
   - **Occlusion Culling 베이크** — 가장 효과 크지만 **레벨 지오메트리 확정 후**에 해야 함(지금은 이름)
   - Layer Cull Distances 값 채우기
   - URP Render Scale 하향
   - 텍스처 압축 포맷(ASTC) 점검 — forDev에서 가져온 텍스처 중 미압축 가능성
   - LOD 그룹(보스·프레스 등 반복/고비용 오브젝트)
   - [최적화_후보.md](design/최적화_후보.md)의 Stage1 정적 분석 항목들(Static 플래그·GPU 인스턴싱·
     실시간 그림자 3개 정리) — **이 문서 자체가 아직 미적용 상태**임을 재확인함
