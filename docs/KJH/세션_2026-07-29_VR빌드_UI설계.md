# 세션 2026-07-29 — S24+ VR 빌드 · 리그 통합 · UI 설계 착수

> 브랜치 `docs/kjh-initial`. 컨트롤러(S10e)는 별도 브랜치 `kjh/controler`(worktree `madagain-udp`).
> 이 문서는 **UI 설계를 다른 계정에서 이어가기 위한 인수인계**다.

---

## 0. 결론 요약

S24+ 헤드셋에서 **VR이 실제로 돌아간다**. 60fps, Cardboard 스테레오, 머리 트래킹, 컨트롤러 UDP 수신까지 확인.
리그를 갈아엎어 PC/VR이 **같은 몸**을 쓰게 했다.

**다음 주제는 UI인데, 렌즈 프로파일(FOV)이 확정되기 전엔 설계를 시작할 수 없다** — UI 안전영역과
검은 테두리가 같은 미지수에 걸려 있다. §4 참조.

---

## 1. 통합 리그 (완료)

PC와 VR이 **같은 몸**을 쓴다. 차이는 카메라에 붙는 시점 드라이버 하나뿐이다.

```
[PlayerBody]  ← CharacterController + FirstPersonPlayer(이동·중력·밀림감지·EdgeStop)
   │            + AutoTraversal + MantleRig.   ★ 회전하지 않는다. 위치만 소유.
   └ Main Camera ← 시점의 유일한 소유자
                   PC : MouseLook (신규 — FPP에서 뜯어냄)
                   VR : TrackedPoseDriver (RotationOnly)
                   + MotionFeel(연출), HackDriver(조준=정면)
```

**원칙 3개**

1. **몸은 회전하지 않는다.** CC 캡슐은 어차피 수직이라 잃는 게 없다.
2. **시점은 카메라만 소유한다.** 고개를 돌려도 몸은 가만히 있다.
3. **이동 방향은 시점을 읽기만 한다.** 조이스틱 앞 = 보는 방향(VR 표준 로코모션이자 PC의 원래 동작).
   시점이 몸을 돌리거나 이동이 시점을 돌리는 일은 없다.

**몸 원점 = 눈높이.** 기존 이동·등반 코드 전부가 "트랜스폼 위치 = 눈"을 전제하므로 그 규약을 유지했다
(발 위치는 CC의 `center = -0.7`이 만든다). 카메라 로컬은 0.

폐기된 것: VR 전용 `[XR Rig]` + `FreeLookController` 경로. 몸이 없어서 충돌·중력 없이 벽을 뚫고 다녔고,
눈높이도 TPD가 덮어써 **땅이 꺼져 보였다**.

## 2. 실기에서 잡은 함정 (전부 근본 원인까지 확인)

다음 세션이 같은 데 빠지지 않도록 **증상 → 원인** 형태로 남긴다.

| 증상 | 진짜 원인 | 조치 |
|---|---|---|
| **정확히 30.0fps 고정** (`spike`가 `avg`와 소수점까지 동일) | Unity는 Android에서 `Application.targetFrameRate`를 지정 안 하면 배터리 절약으로 **30에 묶는다**. 성능 문제가 아니었다 | `GameBoot.ApplyFrameRate()` — vSync 0 + targetFrameRate 60 |
| **스플래시는 회전하는데 게임은 안 돎** | 구형 VR은 유니티가 메인 카메라에 머리 포즈를 자동 적용했지만 **신형 XR SDK는 안 한다**. 트래킹은 살아 있고 카메라가 값을 안 받은 것 | `TrackedPoseDriver` 부착. 바인딩은 Cardboard 공식 샘플에서 그대로 읽음(`<XRHMD>/centerEyeRotation`) — 추측하면 틀린다 |
| **땅이 꺼져 보임** | TPD를 `RotationAndPosition`으로 붙였더니 Cardboard(3DoF)의 거의-0 위치가 카메라 로컬을 덮어써 눈높이 1.6m가 지워짐 | `RotationOnly`. 위치는 `[PlayerBody]`가 소유 |
| **에디터가 UDP를 못 받음** (PowerShell은 받는데) | `Unity.exe`에 인바운드 `Public/Block` 규칙. **Block을 끄기만 하면 안 된다** — 기본 인바운드가 차단이라 명시적 Allow가 필요 | 핫스팟 서브넷 한정 규칙 추가 (§6) |
| **에디터 포커스 빠지면 수신 멈춤** | 포커스 없으면 `Update`가 안 돌아 큐가 안 비워짐(수신 스레드만 살아 `accepted`만 증가) | `PlayerSettings.runInBackground = true` |
| **`HackGlitch` 셰이더 못 찾음** | 빌드에 미포함 | Always Included Shaders에 추가 |
| **컨트롤러 조작이 기기에서 전혀 안 먹음** | `ControllerDriver`가 `FirstPersonPlayer`를 못 찾으면 `Update`를 통째로 return. VR 리그엔 FPP가 없었음 | 리그 통합으로 해소(§1) |

## 3. 현재 동작 상태

### 실기 검증됨 (S24+ SM-S926N, Android 16)
- Cardboard 스테레오 렌더, 머리 트래킹, **59.9fps / 16.7ms**
- `CardboardProfile.Apply()` → `ReloadDeviceParams()` 실행됨 (렌즈 프로파일 주입 경로 자체는 동작)
- 컨트롤러 UDP 수신 (S10e → S24+ `192.168.137.20:45710`)

### 에디터 검증됨
- 프로토콜 v3 수신 (128B, `MHX2`), 좌우 절반 터치 판정, 자이로 시점, 조이스틱 이동
- 해킹 탭/취소 (오른쪽 절반), 패턴 그리기(적응형 격자 + 커서 스냅)

### 미완성
- **A3 부품 조종 서보** — 코드는 있으나 **실기에서 잘 안 됨**. 원인 미규명. `HandCalibration` +
  `ControllerDriver.ApplyServo` 참조. 리센터는 `HackDriver.OnControlledChanged`에 걸려 있다
- **최악 시나리오 최적화 씬** — 사용자 요청(보스 6명 리깅 동시 구동 + demoscene + 경비병 사망 등
  엉망진창 씬). **아직 착수 안 함**

## 4. UI — 조사 결과와 막힌 지점 ★ 이번 세션의 본론

### 현황

| 대상 | 방식 | VR 상태 |
|---|---|---|
| `PatternUI` | `ScreenSpaceOverlay` 캔버스 (주석에 "PC 전용") | **`VrHudSpace`가 자동으로 WorldSpace 변환** — 걱정했던 "패턴이 안 보임"은 대비돼 있음 |
| `VrHudSpace` | ScreenSpace→World 변환기 | 동작. 단 **`distance 1.3m` / `panelHeight 1.5m`가 임시값**이고, 코드 주석에 *"뷰어 FOV 확정 후 안전영역 기반으로 정식화해야 코너 HUD 잘림이 풀린다"* 고 명시돼 있음 |
| `VrStatsHud` | 월드 `TextMesh` | 정상 (이번 세션 신규) |
| 디버그 패널 7개 (`DevConsole`, `MoveTuningPanel`, `GlitchTuningPanel`, `LightingTuningPanel`, `PoseSeqPanel`, `PoseTunePanel`, `ScreenCenterDot`) | **`OnGUI`(IMGUI)** | **VR에서 못 씀.** IMGUI는 캔버스가 아니라 `VrHudSpace`가 변환할 수 없고, 여는 데 키보드가 필요하다 |

### 핵심 문제 — PC 화면 좌표계를 월드로 밀어내는 방식의 한계

`PatternUI`는 패널을 **화면 왼쪽 끝**(`anchorMin.x = 0`)에 붙인다. 1.3m 거리에서 화면 세로 전체가
1.5m에 매핑되면 세로 약 60°, 가로는 그 이상 — **왼쪽 끝은 시야 밖이거나 렌즈 왜곡이 심한 영역**이다.

VR UI는 **중앙 30~40°** 안에 있어야 한다. 화면 가장자리 기준 배치(왼쪽 정렬·코너 HUD)는 원리적으로 안 맞는다.

### VR UI 제약 (설계 시 전제)

1. **스크린스페이스 금지** — 양안 렌더에서 한 번만 그려져 어긋난다. 전부 월드스페이스
2. **거리·크기는 각도로** — 1m보다 가까우면 수렴-조절 충돌로 눈이 아프다. 편한 범위 **1.5~2.5m**,
   텍스트는 2m에서 최소 5cm
3. **시야 가장자리 사용 불가** — 왜곡·색수차
4. **머리 완전 고정 금지** — 큰 패널은 멀미. yaw만 따라가거나 감쇠 지연 추종
5. **커서 없음** — 중앙 시선 레티클 기본. S10e 6DoF가 있으니 레이저 포인터도 가능
6. **우리 고유 제약** — 컨트롤러가 눈먼 터치패드라 **조이스틱 위치·패턴 격자·커서가 전부 VR 화면에
   보여야 한다.** 이게 이번 UI 설계의 가장 큰 동인

### ★ 막힌 지점 — 렌즈 FOV가 미지수

**검은 테두리**가 보인다는 사용자 보고가 있다. 조사 결과:

- `androidRenderOutsideSafeArea: 1` — 노치 레터박싱은 **배제됨**
- **우리가 렌즈 프로파일을 강제 주입하고 있고, 그 FOV가 사방 40°**(한쪽 눈 80°)다.
  Cardboard급 뷰어는 보통 90~100° → **FOV를 실제보다 좁게 선언하면 그 차이만큼 검게 남는다**
- `cardboardProfileUri`가 비어 있어 **뷰어 QR을 스캔해도 우리 코드가 매번 덮어쓴다**

**UI 안전영역과 검은 테두리가 같은 미지수에 걸려 있다.** FOV를 모르면 UI를 어디까지 놓을 수 있는지
정할 수 없다. **FOV 확정이 UI 설계의 선행 조건이다.**

#### 재빌드 없이 FOV를 실측하는 법 ★

`VrTuning`이 `persistentDataPath/vr_tuning.json`을 읽는다. **adb로 JSON만 밀어넣고 앱을 재시작하면
즉시 반영**된다:

```bash
adb push vr_tuning.json /storage/emulated/0/Android/data/com.mindhexer.headset/files/vr_tuning.json
```

FOV를 40 → 50 → 55로 올려가며 검은 테두리가 줄어드는지 본다.
**줄어들면 우리 프로파일 문제, 안 줄어들면 렌즈 물리 한계.**

뷰어(엑토 프로 VR-01)에 **QR코드가 있으면 그게 정답**이다 — 그 URI를 `cardboardProfileUri`에 넣으면
우리 계산값 대신 그걸 쓴다(코드가 이미 그렇게 분기한다).

## 5. 다음 작업 (순서 있음)

1. **렌즈 FOV 확정** — QR 확인 또는 `vr_tuning.json` 실측. **이게 안 되면 아래가 전부 추측이 된다**
2. **UI 안전영역 정의** → `VrHudSpace`의 `distance`/`panelHeight` 정식화, 코너 잘림 해소
3. **VR UI 레이아웃 설계** — 패턴 격자, 조이스틱 피드백, 레티클, 상태 표시
4. **VR용 디버그 수단** — IMGUI 7개를 대체할 월드스페이스 패널 (실기 튜닝이 막혀 있다)
5. **A3 부품 조종 디버깅** — 실기에서 안 되는 원인 규명
6. **최악 시나리오 최적화 씬** — 보스 6명 + demoscene + 경비병 사망 등

### 미결 (사용자 판단 필요)
- **VR에서 `MotionFeel`의 롤·FOV 연출을 켤지.** 머리가 소유한 회전 위에 롤을 얹으면 멀미 위험이 크다.
  위치 연출(킥·딥)만 남기고 롤은 끄는 것을 기본값으로 제안했으나 미확정

## 6. 환경 메모

- **네트워크**: 노트북 핫스팟 `192.168.137.1`. S10e `.140`, S24+ `.20` (DHCP라 바뀔 수 있음)
- **eduroam은 단말 격리로 UDP가 막힌다**(캠퍼스 `10.x`). 반드시 핫스팟
- **방화벽** — 에디터 수신용. 개발 끝나면 정리할 것
  ```bash
  New-NetFirewallRule -DisplayName "MINDHEXER controller UDP 45710" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 45710 -RemoteAddress 192.168.137.0/24 -Profile Any
  ```
  `Unity 6000.5.4f1 Editor`의 인바운드 `Public/Block` 규칙은 **비활성 상태로 둬야** 한다(Block이 Allow를 이긴다)
- **컨트롤러 대상 IP**: S10e HUD의 "IP 변경" 버튼. **앱 재시작하면 `192.168.137.1`로 돌아간다**(하드코딩 기본값)
- **컨트롤러가 30Hz로 보낸다** — AR Foundation이 앱 프레임을 AR 카메라(30Hz)에 맞추기 때문
  (`ARSession.matchFrameRate`). 수신 측에서 평활로 가리고 있으나, 근본 해결은 컨트롤러 재빌드 필요
- **adb**: `C:\Program Files\Unity\Hub\Editor\6000.5.4f1\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\adb.exe`
- **빌드**: Development + Autoconnect Profiler. 패키지 `com.mindhexer.headset`

## 7. 이번 세션 신규 파일

| 파일 | 역할 |
|---|---|
| `View/Net/ControllerLink.cs` | UDP 45710 수신, v3 파싱, `touchId`별 상태기계, 통계. `[DefaultExecutionOrder(-200)]` |
| `View/Net/ControllerDriver.cs` | 원시 터치 → 게임 조작. 조이스틱·자이로 시점·해킹 매핑·패턴 격자·서보 |
| `View/Net/HandCalibration.cs` | 6DoF 위치 보정 5단(점프게이트·저역통과·데드존·커브·변화율제한) |
| `View/Input/CompositeHexInputSource.cs` | PC 소스 + 네트워크 소스 합성(에디터 튜닝용) |
| `View/Debug/VrStatsHud.cs` | 월드스페이스 fps/ms 표시 + logcat 주기 기록. **경과 시간을 함께 남긴다** — 스로틀링은 추이로만 보인다 |
| `View/Bootstrap/MouseLook.cs` | FPP에서 뜯어낸 PC 시점 |
