# ADR-0005 — VR 컨트롤러 입력 매핑 (눈먼 터치패드 → MINDHEXER)

상태: 진행 중 (A1·A2·A4 구현 완료, A3 부품 조종 미구현)
날짜: 2026-07-29
관련: ADR-0001(6DoF 트래킹), 프로토콜 v3(`shared`)

---

## 배경

컨트롤러(S10e)에서 조이스틱·패턴 판정을 **떼어냈다**. 이유는 원리적이다:

> **플레이 중엔 헤드셋을 쓰고 있어 컨트롤러 화면이 보이지 않는다.**

화면에 그리는 조이스틱 원·패턴 노드·경로선은 플레이어에게 도달하지 않는다. 시각 피드백은
전부 VR 화면(MINDHEXER)에 있어야 한다. 부수 효과로 감도·데드존 같은 튜닝값이 APK에 박히는
문제도 사라졌다 — 이제 값을 바꿔도 **폰을 다시 빌드하지 않는다**.

결과적으로 컨트롤러는 **눈먼 터치패드 + 포즈 송신기**이고, **모든 해석이 MINDHEXER 몫**이다.

---

## 확정된 매핑

| 컨트롤러 | 게임 | 비고 |
|---|---|---|
| 오른쪽 절반 터치 | Space (해킹·취소·조종해제·복귀) | 탭/홀드 판정은 `HackDriver`가 소유 |
| 왼쪽 절반 터치 | 이동(플로팅 조이스틱) + 빙의 사격 | 분기하지 않는다 — 아래 참조 |
| 오른쪽 절반 스와이프 | 패턴 그리기(`strokeDir`) | Hacking 컨텍스트 |
| 기기 자세(자이로) | 시점 | **에디터 전용 대역** — 실기에선 헤드셋이 소유 |
| 6DoF 위치 | 부품 조종 | 미구현(A3) |

### 왼쪽 절반을 분기하지 않는 이유

이동과 사격을 같은 절반에 동시에 먹인다. 상황이 알아서 갈라주기 때문이다:

- 고정 시점 빙의(터렛·CCTV) → `HackDriver`가 `ExternalMotion=true`로 본체를 얼려 **이동이 무시**된다
- 경비병 빙의(`_bodyMode`) → 총이 없어 **사격이 무시**된다

컨텍스트로 분기하면 "빙의 대상에 따라 왼손 의미가 바뀐다"가 되어 손이 헷갈린다. 분기하지
않는 편이 코드도 짧고 감각도 일관된다.

### 해킹 중 홀드-복귀를 버린 이유

`HackDriver`의 홀드-복귀 조건은 `_ctx.Current != ControlContext.Player`라 **Hacking에서도 성립**한다.
패턴을 그리려고 손가락을 대고 있는 것이 복귀로 새면 그릴 수가 없다.

**`hackHeld`를 Hacking 컨텍스트에서 채우지 않는 것**으로 해결했다 — 홀드 조건이 성립할 수 없다.
`HackDriver`는 수정하지 않았다. 취소(탭)는 살아 있다: 움직이지 않은 터치를 뗄 때만
`hackPressed`+`hackReleased`를 합성한다.

> PC에는 같은 버그가 남아 있다(패턴 중 Space 홀드로 복귀). 커밋 `aa15aa6`의 명시된 의도는
> "홀드를 빙의 중에만 인정"이므로 `== ControlContext.ViewEntry`가 맞다. VR에 영향이 없어 미수정.

## 패턴 입력 — 적응형 격자

격자는 정규화 `0..1`, 점 간격 1.0, `hitRadius 0.16`, `sensitivity 1/300`(= 300px가 1유닛).
시작점은 **좌상단 고정**(`PatternGraph.StartDot`).

### 절대 좌표가 아니라 상대(플로팅)

화면이 안 보이므로 "화면 어디를 눌렀나"는 의미가 없다. 엄지를 내려놓은 자리가 시작점이고,
**움직인 거리**로 커서가 간다. 조이스틱과 같은 원리다.

### 배율을 상수로 박지 않는다

터치 지점에서 남은 물리 공간에서 **유도**한다. 고정 상수면 화면 가장자리에서 격자가 밖으로
나가 패턴을 완성할 수 없다(팀원 구현의 실제 결함이었다 — 간격이 상수라 오른쪽·아래 가장자리에서
노드 2개가 화면 밖으로 나갔다).

시작점이 좌상단이므로 필요한 여유는 **오른쪽·아래로 `1 + hitRadius`, 왼쪽·위로 `hitRadius`**.
네 방향 제약 중 가장 빡빡한 것이 배율을 정한다. **등방**으로 잡는다 — 방향마다 다르면 대각선
획이 45도가 아니게 되어 VR에 보이는 격자와 손의 느낌이 어긋난다.

배율은 **이번 패턴의 첫 터치에서 한 번만** 계산한다. 획 도중이나 클러치마다 바뀌면 감각이 흔들린다.

S10e(2280×1080, DPI 480 → 120.7×57.2mm) 기준 오른쪽 절반 한가운데에서 약 **14.8mm/유닛**
(안전계수 0.6). 하한 10mm의 근거는 임의 상수가 아니라 **엄지 정밀도**다: 위치 재현 정밀도
약 2mm, 히트 반경 0.16유닛 → `0.16 × 배율 > 2mm`.

### 커서 스냅 — 오차 누적을 끊는다

두 지점에서 커서를 점에 붙인다:

1. **점 커밋 시**(`PatternInput.Advance`)
2. **손가락을 뗄 때**(클러치)

원래 구현은 히트 반경 안 아무 데서나 커밋하고 커서는 그 자리에 남겼다. 화면을 보고 마우스로
그릴 땐 눈으로 보정되니 드러나지 않던 문제인데, 화면이 안 보이면 **오차가 획마다 누적**되어
손 위치와 격자가 어긋난다. 붙이면 매 획마다 0으로 초기화된다.

### 클러치

델타 기반이라 손가락을 떼도 커서가 유지된다. 뗐다 다시 잡으면 이어 그려진다 → **엄지 도달
범위 문제가 공짜로 해결**된다. 해킹 중엔 움직인 터치에 `hack*`를 안 보내므로 상태도 안 깨진다.

## 30Hz 문제와 보간

컨트롤러가 **30Hz**로 보낸다. AR Foundation이 앱 프레임을 AR 카메라 프레임에 맞추기 때문
(`ARSession.matchFrameRate`). 에디터는 60fps 이상이라 그대로 먹이면 **패킷 없는 프레임의 델타가
0**이 되어 계단처럼 끊긴다.

수신 측에서 해결했다 — **총량을 보존한 채 프레임에 고르게 푼다**:

- 시점: 자세를 지수 평활(`lookSmoothTime 0.05s`)한 값의 프레임간 차이를 쓴다
- 패턴: 밀린 이동량을 시정수(`patternSmoothTime 0.04s`)로 나눠 내보낸다. 손을 뗀 뒤에도 남은
  분이 마저 나가야 획 끝이 안 잘린다

지연이 시정수만큼 생기는 대신 끊김이 사라진다. 근본 해결(`matchFrameRate` 끄기 → 60Hz)은
컨트롤러 재빌드가 필요해 다른 수정과 묶어서 한 번에 한다.

## 실기에서만 정해진 값

책상에서 추측하지 않고 기기로 잡은 것들:

- **`invertPitch = true`** — 자이로 상하가 반대였다. 기기 자세 쿼터니언의 절대 프레임은
  화면 방향·기기마다 달라 미리 맞힐 수 없다. 그래서 절대각이 아니라 **델타**로 가고
  `invertYaw`/`invertPitch`/`swapAxes` 플래그로 잡는 구조로 만들었다
- 조이스틱 반경 14mm, 격자 안전계수 0.6

## 발견한 막힘 (실기 검증됨)

| # | 내용 | 상태 |
|---|---|---|
| 1 | `Unity.exe` 인바운드 방화벽 `Public/Block`이 UDP를 막음 | 해결 — 핫스팟 서브넷 한정 UDP 45710 Allow 규칙 추가. **Block을 끄기만 하면 안 된다**(기본 인바운드가 차단이라 명시적 Allow가 필요) |
| 2 | `FirstPersonPlayer.Update`가 `kb == null`이면 통째로 return | 해결 — 안드로이드엔 키보드가 없어 이동뿐 아니라 **시점·중력·ApplyMove까지 정지**했다. 키보드·마우스를 선택으로 |
| 3 | 에디터 포커스가 빠지면 `Update`가 안 돌아 큐가 안 비워짐 | 해결 — `PlayerSettings.runInBackground = true` |
| 4 | `NetworkHexInputSource`가 VR 모드에서만 배선됨 | 해결 — `ControllerDriver`가 꽂는다. 기존 PC 소스는 버리지 않고 합성(`CompositeHexInputSource`)해 키보드·마우스도 계속 살아 있게 |
