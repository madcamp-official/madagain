# ADR-0001: 컨트롤러 6DoF 추적 채택 (VIO)

- 날짜: 2026-07-24
- 상태: 제안 (SYB 합의 대기)

## 결정

컨트롤러(S10e)의 추적을 **6DoF(회전 + 위치)** 로 한다. 위치 추적은 ARCore의 VIO(카메라 + IMU 융합)로 얻는다. 회전만의 3DoF에 머무르지 않는다.

## 이유

MINDHEXER의 물체 조종은 "폰을 실제로 움직여 물체를 그만큼 이동시키는" 공간 조작이 재미의 필수 요소로 판단된다. 회전(자이로)만으로는 물체를 기울이거나 돌릴 수는 있어도, 공간에서 밀고 당기는 감각이 나오지 않는다.

가속도계만으로는 위치를 얻을 수 없다. 위치는 가속도를 두 번 적분해야 하고, 중력 제거 잔차·바이어스 때문에 오차가 시간의 제곱으로 폭발한다. 몇 초면 붕괴한다. 절대 위치는 **카메라로 실제 세상의 특징점을 보고 자기 이동을 역산하는 VIO**로만 안정적으로 얻는다.

## 고려했던 대안

- **3DoF(자이로+터치)만** (SYB SPEC v3 방식): 단순·저발열·안정적이고 카메라 가림 문제가 없다. 그러나 위치 조작이 원천 불가라 물체 조종의 공간감을 포기해야 한다. 회전 기반 조종만으로 재미가 충분하면 이 방식이 옳다 → 그래서 **층 1로 먼저 검증**하기로 한다(아래 영향).

## 영향

- **SYB SPEC v3와 충돌**: SPEC은 "6DoF/VIO 폐기"로 적혀 있다. 이 결정은 그것을 뒤집으므로 **SYB 합의가 전제**다. 합의 전에는 "제안" 상태.
- **프로토콜 변경**: 공유 `InputPacket`에 `Position(float×3)` +12바이트 추가 → 60→72바이트. `PacketSerializer`·`NETWORK_PROTOCOL.md`·`ProtocolVersion` 동시 갱신. `shared/com.mindhexer.shared`에서만 변경(양쪽 자동 반영).
- **컨트롤러 앱 확장**: `TouchGyroCapture`에 ARCore 세션이 얹힌다. 카메라 상시 구동 = 발열·부하 증가.
- **하드웨어 제약**: 카메라 가림 방지 그립 설계 필수(소프트웨어로 해결 불가), 밝고 텍스처 있는 시연 공간, 세션 시간 제한, 두 폰 좌표계 수동 정렬.
- **완화책 — 층 구조**: 층 1(3DoF, 항상 동작) 위에 층 2(6DoF)를 얹고, 층 2가 깨지면 층 1로 graceful degradation. 층 1만으로도 물체 조종이 성립하게 먼저 만든다. 상세: [../design/기초_설계안.md](../design/기초_설계안.md) §4.
