## 0. 먼저 알아야 할 것 (작업 규칙)

- **토큰 쓰는 작업은 반드시 "승인"이라는 단어를 받고 시작한다.** 설계·측정·코드 작성 전부 포함.
  값 하나 바꾸는 것도 예외 없다. 이걸 안 지켜서 여러 번 지적받았다.
- **스크린샷을 찍어 확인하려 하지 말 것.** 사용자가 직접 눈으로 보고 알려 준다.
- **MCP for Unity는 다른 세션이 쓰고 있을 수 있다.** "코드만 짜라"는 지시가 오면 유니티를 건드리지 말고
  파일만 만든다. 컴파일 확인도 사용자가 한다.
- 사용자가 쓰는 값(복도 폭, 팔 길이 등)은 **대부분 임시값**이다. 제약 조건으로 굳혀 쓰지 말 것.

## 1. 지금까지 확정된 보스전 구조

1막 잠입(스테이지 4개) → 2막 추격. **역순으로 되돌아가며** 각 스테이지 입구의 유압프레스로
보스 머리를 찍는다. 첫 조우 1회 + 스테이지마다 1회 = **총 5회**.

- 보스 해킹은 **삭제**. 대신 보스가 좁은 입구에 머리를 박고 **끼어 있는 동안** 프레스를 해킹해 찍는다.
- 사망 연출은 **원인 무관 하나로 통일**: 암전 → 1초 → 죽인 대상 정면 클로즈업 → 치지직 → 방 리셋.
  보스의 "양팔로 카메라 감싸 찌부"는 **폐기 확정**. 그래서 `BossChase`에 잡기(catch) 판정이 없다.
- 파괴 연출은 **정면 파괴만** 남겼다. "짚는 곳 = 부서지는 곳"은 폐기. 정면 파괴는 물리 베이크로 굽는다.
- **미결**: 끼임 시간 안에 못 찍었을 때 재돌진을 허용할지 / 4회 전부 1회 성공 필수인지.

## 2. 모델 — 여기서 시간을 많이 잃었다

### 쓰는 모델은 `MegaRobot.prefab`이다

```
Assets/_Project/Prefabs/Hackables/Boss/MegaRobot.prefab
  └ nupjuk_rigged (Assets/_Project/Art/Boss/nupjuk_rigged.fbx)
```

리깅이 **제대로** 되어 있다 — 손가락 4개×3마디, 좌우 대칭, `_end` 말단까지.

### `Boss_Rigged.fbx`는 애니메이션 원본일 뿐이다

`Assets/_Project/Art/Boss/Boss_Rigged.fbx` (원본 `untitleddddd.fbx`)는 **같은 모델의 다른 버전**으로,
손가락 리깅과 텍스처가 없고 **오른팔 본이 망가져 있다**(팔꿈치→손 거리가 왼쪽의 29%).
**여기서 애니메이션만 뽑아 쓴다. 모델로 쓰지 말 것.**

> 나는 이걸 보스 모델로 착각해서 오래 헤맸다. 리그 결함을 진단하고 180도 보정 컴포넌트까지
> 만들었는데 전부 안 쓰는 파일 이야기였다. **씬에 실제로 배치된 것을 먼저 확인할 것.**

### 애니메이션 이식 방법 (이미 완료)

두 리그의 본 이름·계층이 같고 접두만 달라서 **경로 치환만으로** 옮겼다. 리타게팅 불필요.

```
클립 경로   ParentNode/Armature/Root/...
MegaRobot   nupjuk_rigged/Armature/Root/...
```

결과물:
```
Assets/_Project/Art/Boss/Anim/Boss_Walk.anim          1.88s 루프 (전체)
Assets/_Project/Art/Boss/Anim/Boss_Walk_Legs.anim     ← 실제로 쓰는 것
Assets/_Project/Art/Boss/Anim/Boss_Chop.anim          6.58s (미사용)
Assets/_Project/Art/Boss/Anim/MegaRobot_Anim.controller
```

**클립에서 뺀 것 (중요)**

| 뺀 것 | 이유 |
| --- | --- |
| 모든 `m_LocalPosition`·`m_LocalScale` (Hip 제외) | 클립이 `Boss_Rigged`의 **뼈 길이**를 담고 있어서, 재생하면 nupjuk의 올바른 뼈를 덮어썼다. 오른팔이 32.1m→16.9m로 줄었다 |
| Hip의 전진 이동 (선형 추세) | 루트 이동이 박혀 있어 ×50에서 72m씩 미끄러졌다 |
| `/Waist` 이하 전부 → `Boss_Walk_Legs.anim` | **상체 커브가 가슴 메시를 찌그러뜨렸다.** 팔·척추는 스크립트가 소유하므로 클립에서 뺐다 |

> 상체 찌그러짐은 **클립 문제였다.** IK를 다 끄고 애니메이션만 켜도 찌그러졌다.
> 원본 리깅 사이트(웹)에서는 멀쩡했다고 하니, 팀원이 조정하는 과정에서 생긴 것으로 추정된다.
> 상체 모션이 필요해지면 팀원에게 리깅 수정을 요청해야 한다.

## 3. 만든 코드

### `View/Boss/BossArmRig.cs` — 팔의 유일한 소유자

관절 규약: **쓰는 것은 어깨(`Upperarm`)·팔꿈치(`Forearm`)·손가락뿐.**
**손목(`Hand`)과 트위스트 본은 전혀 쓰지 않는다** — 매 프레임 홈 회전으로 동결.

동작 쪽 API는 이것뿐이다.
```csharp
rig.Aim(side, worldTarget, palmNormal);   // Relax까지 유지 (짚은 손은 목표가 안 바뀐다)
rig.Relax(side);
rig.Curl(side, 0~1);                      // 손가락 쥐기
rig.Reach(side);                           // 유효 팔 길이
rig.PalmPos / PalmNormal / ShoulderPos
```

**핵심 설계 두 가지**

1. **IK 말단은 손 본이 아니라 `L_Palm`/`R_Palm` 마커**다. 리그가 어떻게 생겼든 "여기가 닿는다"를
   저작이 정한다. `Hand` 자식으로 자동 생성된다.
2. **남은 자유도 하나는 팔꿈치가 가져간다** (`elbowHint`, 기본 `(1, 0.15, -0.25)`).
   2본 IK는 목표에 닿고도 "어깨→목표 축 둘레 회전" 하나가 남는데, 그걸 손바닥 정렬에 주면
   팔꿈치가 안쪽으로 오므라든다. 그래서 `alignStrength = 0`. 손바닥은 `rollOffset`으로 따로.

**겪은 함정**

- `Transform.RotateAround`를 쓰면 **position까지 쓴다.** 회전 중심을 읽은 시점과 실제 위치가
  부동소수점만큼 어긋나 그 차이가 `localPosition`에 매 프레임 누적된다(스케일 50배라 증폭).
  위팔이 어깨에서 떨어져 나가 메시가 늘어난다. → `rotation = AngleAxis(θ, n) * rotation`으로 대체.
- 편집 모드에서 `preview`가 꺼져 있으면 **아무것도 건드리지 않는다.** 매 프레임 홈으로 되돌리면
  인스펙터에서 본을 손으로 돌려도 즉시 원복돼 조사가 불가능하다. 미리보기가 꺼지는 프레임에만 1회 복원.
- 씬 저장 직전·비활성 시에도 홈으로 복원한다 — 미리보기 자세가 씬에 굳지 않게.

### `View/Boss/BossChase.cs` — 추격 이동 + 벽 짚기 (실행순서 40)

IK를 직접 하지 않는다. "어디를 짚을지"만 정해 `BossArmRig.Aim`으로 넘긴다.

**짚는 곳은 옆이 아니라 앞으로 멀리.** 복도 폭 48m에 팔이 32m라 바로 옆(14m)을 짚으면
팔꿈치가 112도 접혀 뭉개진다. 어깨~지점 거리가 팔 길이의 `reachUse`가 되도록 앞 성분을 역산해
**앞 27~29m / 옆 13~15m**를 짚는다.

**짚은 손은 월드에 고정**되고 몸이 그리로 밀려간다. 팔이 `releaseExtension` 이하로 접히면
떼고 다시 앞을 짚는다. 손등으로 짚는다(`braceWithBackOfHand`).

**겪은 버그**: 교차 우선 조건의 부호가 반대여서 왼손이 순번을 독점하고 오른손이 **한 번도 짚지 못했다**.
```csharp
if (_lastStepped == h && NeedsReplant(Other(h))) return;   // 반대 손도 대기 중이면 양보
```

**속도 (현재 값)**

| | 값 | 근거 |
| --- | --- | --- |
| `speedFar` / `speedNear` | 9 / 1.5 m/s | 플레이어 최고속도가 6(`MoveIntegrator.maxSpeed`). 가까우면 1.5로 떨어져 초당 4.5m씩 벌어진다 → 해킹할 시간 |
| `farDistance` / `nearDistance` | 150 / 60 m | |
| `animBaseSpeed` | **24** | 실측: 접지 중 발이 뒤로 밀리는 속도(×50 기준). 원본 클립 루트로 재면 38~42가 나오는데 그 차이만큼 프리셋에 발 미끄러짐이 있다 |
| `minAnimSpeed` | 0.05 | 아주 느릴 때 완전히 멈춰 보이지 않게 |
| `stepTime` / `minStepInterval` | 0.7 / 0.3 | **속도와 맞지 않으면 팔이 못 따라가 접힌다.** 한 손이 버티는 전진 거리는 4m뿐이다 |

> ⚠️ **속도와 팔 교대 주기는 서로 당긴다.** 팔을 펴둔 채로 느리게 걷게 하려면 걸음 속도를 낮춰야 한다.
> 값을 바꿀 때 이 관계를 반드시 계산해 볼 것.

**참고 — 파피플레이타임 1의 허기워기는 고무줄 AI가 아니다.** 투명 벽과 정해진 타이밍의 문으로
경로를 강제하는 **온레일 시퀀스**다. 죽는 것은 길을 잘못 들었을 때뿐이다. 우리는 길이 이미
정해져 있고 시간을 잡아먹는 것이 해킹이라 성격이 다르지만, **"속도로 잡지 않는다"는 원칙은 같다.**

### `View/Boss/BossSpineAim.cs` — 척추·머리 (실행순서 45)

**팔(50)보다 먼저 돌아야 한다.** 허리를 굽히면 어깨가 움직이는데, 팔 IK가 그 뒤에 돌아야
벽에 짚은 손이 제자리에 붙어 있다.

- **허리 굽힘**: 플레이어 Y에 맞춰 머리를 낮춘다. 게인이 아니라 **이분 탐색 14회로 각도를 직접 푼다**
  (비례 제어는 숙일수록 높이차가 줄어 목표에 영영 못 닿는다).
- **분배**: `Waist 0.5 / Spine01 0.3 / Spine02 0.2`. 한 관절에 몰면 그 자리에서 뭉개진다.
- **굽힘 축을 안 쓴다**: "플레이어 방향에 수직인 수평축" 둘레의 월드 회전 → 사선에 있으면 그쪽으로 기울며 숙인다.
- **머리 조준**: `Head` 아래 `HeadAim` 마커의 +Z를 플레이어로 향하게. 바인드 포즈에서 보스 정면을
  향하도록 자동 세팅되므로 손으로 맞출 필요 없다. 좌우·상하 한계는 `maxHeadYaw 70` / `maxHeadPitch 45`.
- 현재 `maxBendDeg = 75` (110은 너무 찌그러졌다), `headAboveTarget = 2`.

### ⚠️ 머리 찌그러짐 — **다른 세션 설계와 정면 충돌한다. 먼저 합의할 것.**

`design/보스_머리_압사_연출.md`(다른 세션 작성)가 **완전히 다른 방식**을 이미 확정해 놓았다.
나는 그 문서를 뒤늦게 발견했고, **내가 만든 코드는 그 설계와 맞지 않는다.**

| | 다른 세션 설계 (`보스_머리_압사_연출.md`) | 이번 세션 코드 (`BossHeadCrush`) |
| --- | --- | --- |
| 구조 | **2겹** — 겉껍질(구형 강판) + 속 넙죽이 머리 | **1겹** — 지금 머리 판때기를 그대로 움직임 |
| 겉껍질 | Blender Cell Fracture로 파쇄해 **터뜨림** | 파쇄 없음 |
| 납작해짐 | 속 넙죽이를 **블렌드 셰이프**로 | 판때기 **오프셋·각도 보간** |
| 눈 | 별도 눈알 + 힘줄 고어 팝아웃 | 눈알도 판때기 목록에 넣어 최종 자세에서 처리 |
| 단계 | A→B(2막), B→C(4막) **2회** | **stageCount회**(첫 조우 1 + 스테이지 N) |
| 신규 에셋 | 속 넙죽이 머리 + 눈알 **제작 필요** | 없음 |

**충돌 원인은 막 구성 변경이다.** 그 문서는 4막 기준(A→B→C 2회 압사)으로 쓰였고, 사용자가
2막 4~5회 압사로 바꾼 뒤에 갱신되지 않았다. 그리고 사용자는 이번 세션에서 **"최종 찌그러짐 위치를
내가 지정하고 단계별로 나눈다"**고 명시적으로 지시했으므로, **의도는 이번 세션 쪽에 가깝다.**

**다음 담당자가 먼저 할 일**: 사용자에게 어느 쪽으로 갈지 확인받고, 지는 쪽 문서를 폐기 표시할 것.
내 판단으로는 이번 세션 방식이 신규 에셋 0개로 끝나 훨씬 싸지만, 2겹 파쇄 쪽이 볼거리는 낫다.
**절충안**: 단계 1~N−1은 판때기 보간(싼 것), 마지막 완전 납작만 파쇄+블렌드셰이프(비싼 것)로 가는 것도
가능하다 — `BossHeadCrush.Kill()`이 이미 "최종 찌그러짐 → 텀 → 완전 납작"으로 갈라져 있어 그 자리에
파쇄 연출을 끼울 수 있다.

### 머리 찌그러짐 코드 — **아직 안 돌려봤다**

| 파일 | 역할 |
| --- | --- |
| `Editor/BossHeadRigidTool.cs` | 머리 판때기 → 강체 변환 (메뉴) |
| `View/Boss/BossHeadCrushPose.cs` | 자세 3개 애셋 (home / crush / flat) |
| `View/Boss/BossHeadCrush.cs` | 런타임 단계 보간 |
| `Editor/BossHeadCrushCaptureEditor.cs` | 인스펙터 캡처 버튼 |

**왜 강체 변환이 필요한가**: 머리 판때기는 전부 `SkinnedMeshRenderer`이고, bones가 할당된
스킨드 메시는 정점을 **본 행렬로만** 계산하고 렌더러 자신의 Transform은 무시한다.
그래서 인스펙터에서 판때기를 옮겨도 **화면상 아무 변화가 없다** — 손으로 자세를 잡는 것이 불가능하다.
머리 본도 `Head` 하나뿐이라 나눠 돌릴 수도 없다.

**실측**: Head 가중치 50% 이상인 파츠 **23개** (단일 본 5 / 여러 본 18).
여러 본에 걸친 18개는 나머지가 목 본인데 **규약상 목은 동결**이라 영향이 상수다.
따라서 **바인드 포즈에서 구우면** 형태가 유지된다. ← 이 가정을 아직 눈으로 확인하지 않았다.

**작업 순서** (사용자가 유니티에서 직접)
1. `MegaRobot.prefab`을 **프리팹 모드로 열고** 루트 선택 → `Tools ▸ 보스 ▸ 머리 판때기 강체로 변환`
   (애니메이터·IK 미리보기 끈 상태여야 함. 최대 위치 오차를 로그로 찍는다)
2. `Create ▸ MINDHEXER ▸ 보스 머리 찌그러짐 자세`로 애셋 생성
3. `BossHeadCrush` 부착 → 애셋 연결 → `[홈 캡처]`
4. 판때기를 직접 잡고 찌그러뜨린 뒤 `[최종 찌그러짐 캡처]`, 더 눌러서 `[완전 납작 캡처]`
5. **`[홈으로 복원]` 후 저장** (안 하면 찌그러진 자세가 원본이 된다)

**런타임**: `stageCount = 5`(첫 조우 1 + 스테이지 4), `Crush()`로 한 단계,
`Kill()`은 최종 찌그러짐 → `deathHold` → 완전 납작 → `OnFlattened`.
스테이지가 늘면 `stageCount`만 바꾸면 되고 자세는 다시 안 잡는다.

### 기타 손댄 것

- `View/Debug/FreeLookController.cs` — **E/Q 상하 이동** 추가(`verticalKeys`, `verticalSpeed`).
  상하는 **월드 기준**이다 — 시점 기준이면 아래를 볼 때 E가 앞으로 가버려 높이 테스트가 안 된다.
