## 3. 레일 세트 전환 (이번 세션의 본체)

### 3.1 구조를 잘못 짚었다가 고친 것

처음에 `RailCarrier` **112개를 개별 오브젝트**로 보고 "몇 덩어리로 이어져 있나"를 물었다. 틀렸다.
실제 구조는 이랬다.

```
Stage_1/RailCarrier1        ← 이게 세트 (Transform만, 스크립트 없음)
  ├ RailCarrier (00)        ← 조각. 각각 Hackable + RailCarrier + BoxCollider
  │   └ Model_Rail          ← 렌더러 96개
  └ … 16개
```

**세트 7개 × 16조각 = 112개.** 계층을 안 보고 추측한 것이 원인이다. **구조는 반드시 먼저 덤프해 볼 것.**

```
세트 7개:  Stage_1 × 3   Stage_2 × 1   Stage_3 × 3
크기 7.19 × 81.62 × 1.54  →  긴 축 = Y (세로 레일, 바닥·천장을 뚫는다)
```

### 3.2 전환 결과

각 세트 부모에 `RailSet` + `Hackable` + 조준용 `BoxCollider`(트리거)를 붙이고,
조각 16개를 `Rails/` 아래로 옮기면서 **개별 `Hackable`·`RailCarrier`·`ControlAxisGizmo`를 제거**했다.

```
해킹 대상    112개 → 7개      (조각마다 따로 해킹되던 것이 세트 단위로)
axis         (0,1,0)          긴 축 = Y
stepTarget   2.55             조각 5.10m의 절반 (사용자 지시)
range        ±20.40           레일 총 길이 81.62 × 0.5 = 가동 폭 40.81
```

> **가동 범위 해석**: "중앙에서 최대 길이의 0.5배"를 **가동 폭 = 0.5 × 총길이**(±0.25배)로 읽었다.
> 근거: 한쪽이 0.5배면 `총길이 ≥ 보이는구간 + 2×0.5×총길이` → 보이는 구간이 0이어야 해서 기하학적으로
> 불가능하다(끝까지 밀면 레일 끝이 반드시 드러난다).

**조각의 `BoxCollider`는 남겼다.** `RailSet` 주석은 "레일은 콜라이더 없음"이지만 그건 밟고 지나가는
가로 레일 전제다. 세로 기둥이라 통과되면 이상하다. 움직이는 비트리거 콜라이더라 플레이어를 밀 수 있는데,
`FirstPersonPlayer`의 밀림 감지가 `MotionFeel.OnCarried`로 넘겨 연출은 나온다. 문제되면 제거할 것.

**`glowRenderers`는 비웠다.** 자동으로 채우면 세트당 1,536개(7개면 10,752개)가 물려 하이라이트가 무거워진다.

### 3.3 ★ `Riders/` 자동 배선 — 두 가지 함정을 코드로 막았다

`RailSet.OnValidate`가 `Riders/` 직계 자식에 대해 자동 처리한다. **둘 다 증상이 원인과 안 닮아서
손으로 하면 반드시 놓친다.**

**① `RailPlatform` 자동 부착**
없으면 **발판만 미끄러져 나가고 플레이어는 허공에 남는다.** 계층으로 오브젝트는 따라가지만
CharacterController는 안 따라온다.

**② `Batching Static` 자동 해제** — 이번에 실제로 겪은 버그다.

> 정적 배칭은 Play 진입 시 메시를 **월드 좌표로 구워** 한 버퍼에 합친다. 그 뒤로는 트랜스폼을
> 움직여도 구워진 정점이 그대로 쓰인다. 결과가 아주 헷갈린다 —
> **콜라이더는 움직이는데 렌더러는 제자리에 남는다.** 즉 "밟고 올라가지는데 발판은 안 따라오는" 것처럼 보인다.

레벨 지오메트리에서 발판을 가져오면 static이 딸려 온다. **부모는 꺼져 있고 자식 렌더러에만 켜져 있어
인스펙터로는 안 보인다** — 그래서 자식까지 훑는다. 성능 손해는 없다(움직이는 물체는 애초에 배칭 대상이 아니다).

## 5. 초거대 프레스 (`f126584`)

`GiantPress.prefab` = `HydraulicPress.prefab`의 **프리팹 배리언트**(완전 복사 아님 —
`PressCrusher`·`StitchSites` 배선이 양쪽에서 따로 썩는 것을 막는다).

```
scale 4 · hackRange 99999(사거리 제한 없음) · allowHold=false(플릭 전용)
gazeBox → isTrigger    ★ 조준용인데 29.9×38.1×18.7m 물리 벽이었다
```

씬의 scale 4 인스턴스 **4개**를 `ReplacePrefabAssetOfPrefabInstance`로 교체(위치·회전·오버라이드 보존).
`Stage_2/HydraulicPress`(1.7×1.3×1.7)는 **일반 프레스**라 건드리지 않았다.

### ★ `strokeMax`를 내가 오해했다

`strokeMax`를 "보스 머리를 찍는 거리"로 보고 임시값 4를 넣었다. **틀렸다.**

```
strokeMax = 바닥까지 닿는 기구의 전체 행정      ← 사용자가 19.5로 확정
LimitT    = 보스 머리에서 멈추는 런타임 상한    ← 별개. StageEntranceFlow가 소유
```

사용자가 4개 전부 19.5로 세팅 완료. **[초거대프레스_스테이지입구_설계.md](design/초거대프레스_스테이지입구_설계.md) §1·§4가
같은 오해로 쓰여 있다 — 정정 필요**(승인 대기).

### `Model_Presser`에서 `WalkSurfaceCollider` 제거

이 컴포넌트는 Play 시작과 함께 박스를 **앵커~헤드 전체로 늘린다**. 피스톤(수평축)에서는 밟고 가는
발판이 되지만, **프레스(아래 축)에서는 세로 벽**이 되어 통로를 막았다. 편집 중엔 작은 박스라 안 보이고
Play를 누르는 순간 늘어나서 "콜라이더가 새로 생긴다"로 보인다.

### `ActuatorControlEditor` (신규)

`strokeMin`/`strokeMax`/`startExtension`이 자식 `Model_Presser`에 있어 매번 찾아 들어가야 했다.
루트 인스펙터에서 바로 편집되게 했다 — **값을 복제하지 않고 자식의 `SerializedObject`를 대신 그린다.**
값이 프리팹에 저장되는지 인스턴스 오버라이드가 되는지도 표시한다.

## 6. 마일스톤 — 다른 세션이 설계를 바꿨다

내가 만든 `MilestoneStepper`는 **스텝을 인스펙터에 손으로 넣는** 구조였다(터렛 5도, 레일 0.17 등).
지금은 **`SyncTo(maxSpeed)`가 `속도 × 간격 × noiseScale`로 자동 계산**하는 구조로 바뀌어 있다.

```
minInterval 기본 = VR 1프레임(72Hz)
stepSize    = maxSpeed × minInterval × noiseScale   ← 손으로 넣지 말 것
Awake에서 SyncTo(moveSpeed) / SyncTo(rotateSpeedDeg) 호출
```

**의도가 바뀌었다**: "딸깍딸깍 톱니 손맛"에서 **"최고 속도에서는 완전히 부드럽고 떨림만 걸러낸다"** 로.
[기초_설계안 §6.2 마일스톤](design/기초_설계안.md)은 **내 옛 설계(스텝 5도·12틱/초)로 적혀 있어 지금 코드와 안 맞는다.**
문서를 지금 코드에 맞춰 고쳐야 한다.

   안 재고 배수를 말했다.

## 8. ⚠️ 파괴와 Static의 충돌 (문서화 필요)

사용자 지적: **"보스가 Wall 빼고는 다 파괴해서 날려버릴 것"**.

§12가 정한 파괴 방식은 둘 다 **원본 트랜스폼을 움직인다**(소규모=리지드바디, 대규모=물리 베이크 후
`AnimationClip` 재생). 즉 **파괴 대상에 `Batching Static`이 켜져 있으면 Floor와 똑같이
콜라이더만 날아가고 화면은 제자리에 남는다.**

**지금 끄면 안 된다** — 이미 드로우콜이 문제인데 배칭까지 빼면 더 나빠지고, 파괴는 2·4막 setpiece라
당장 필요하지 않다. §12가 **"레벨 확정 후 굽는다"** 고 했으므로, **베이크 스크립트가 대상을 알 때
그 대상만 자동으로 끄면 된다.** 손으로 8천 개를 고를 일이 없다.

**§12에 이 함정이 안 적혀 있다.** "베이크는 물리 비용만 없앤다"는 경고는 있는데 static 얘기가 없다.
→ **문서 추가 필요**(승인 대기).

| 3 | **거리 컬링** `far` 150 + Stats `Batches` 확인 | 가장 큰 효과, 가장 싼 작업 |
| 4 | **문서 정정 3건** | §6 마일스톤(코드와 불일치) · 초거대프레스 §1·§4(`strokeMax` 오해) · §12(static 함정) |
| 5 | 실패 경로 연결 | `GameOverManager.Trigger` → `DeathSequence.Play()` / `GuardDetection.OnDetected` — 둘 다 구독자 없음 |
| 6 | S24+ 빌드 후 실측 | 이게 있어야 "돌아가는가"를 말할 수 있다 |

## 10. 이번 세션에서 배운 것 (반복하지 말 것)

- **계층을 안 보고 구조를 추측했다** — `RailCarrier` 112개를 세트로 착각. 덤프부터 할 것.
- **정적 배칭이 켜진 씬에서 `sharedMesh.vertexCount`로 정점을 세면 안 된다** — 결합 메시가 중복 집계된다.
- **렌더러 개수 ≠ 드로우콜.** 배칭을 안 재고 배수를 말하면 20배씩 틀린다.
- **에디터가 백그라운드면 `UnityStats`·`isVisible`·`[ExecuteAlways] Update`가 전부 멈춘다.**
  `frameCount`가 안 늘면 그 상황이다. MCP 측정 결과를 그대로 믿지 말 것.
- **바운즈로 레벨 구조를 판단하지 말 것**(앞 세션 교훈인데 이번에도 프리팹 크기 비교에서 같은 함정에 근접).
