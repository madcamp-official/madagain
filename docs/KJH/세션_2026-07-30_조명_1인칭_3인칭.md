## 1. 끝난 것

### 1.1 조명 — 플레이어 시점 손전등 (완료)

`GameBoot`이 **Main Camera**에 `PlayerLightRig`을 붙입니다(`[Head]`가 아닙니다 — `MotionFeel`의 착지 킥·롤에 빛이 같이 흔들려야 손전등을 들고 뛰는 감각이 납니다).

라이트는 **3개**입니다. 2개로는 안 됩니다 — 팔이 카메라에서 30cm 안쪽이라 손전등 원뿔의 최대 강도를 정면으로 받아 새하얗게 뜹니다.

| 오브젝트 | 타입 | cullingMask | PC 기본 | VR 기본 |
|---|---|---|---|---|
| `[Flashlight]` | Spot | 뷰모델 **제외** | 45°/20°, 25m, 그림자 Soft | **60°/28°**, 그림자 **없음** |
| `[Fill]` | Point | 뷰모델 **제외** | 0.6 / 4m | **1.0 / 5m** |
| `[ViewmodelLight]` | Point | 뷰모델 **만** | 2.0 / 2.5m, 좌상단 | 동일 |

- 값은 **모드별 파일**로 저장됩니다: `Poses/lightrig_pc.json` / `lightrig_vr.json`. 한 파일에 섞으면 PC에서 맞춘 값이 VR을 망가뜨립니다.
- 손전등 오프셋 기본 `(0.15, -0.10, 0)`. **0으로 두면 안 됩니다** — 빛과 눈이 같은 위치면 그림자가 물체 뒤로 완전히 숨어 손전등인데도 평평해 보입니다. 라이트는 씬 객체라 이 오프셋은 **VR 스테레오를 깨지 않습니다**.
- 전 씬(11개) 기존 조명 삭제 + 앰비언트 `Skybox` → `Flat 0.04`. **`ViewmodelStudio`만 예외로 0.212** — 라이트가 0개인 손 튜닝 씬이라 0.04면 에디터에서 아무것도 안 보입니다.
- 조절: **F2 조명 패널 맨 위 "플레이어 조명 리그"** 섹션. 새 키를 만들지 않았습니다(F1 이동 / F2 조명 / F3 포즈 / F4 포즈시퀀스 / F5 글리치 / **F6 손·거미**).

### 1.2 OneBit 셰이더 — 추가 광원 지원 (완료)

`GetAdditionalLightsCount()` 루프 추가. 이게 없으면 손전등이 손·거미에 **전혀** 안 걸려, 디렉셔널을 지운 순간 통째로 검게 죽습니다.

> ⚠️ **URP 17.5에서 Forward+ 키워드 이름이 바뀌었습니다.** `_FORWARD_PLUS` → **`_CLUSTER_LIGHT_LOOP`** (`Core.hlsl:13` 확인). 옛 이름을 쓰면 클러스터 경로에서 **조용히 라이트 0개**가 됩니다. 에러도 안 납니다.

라이트 랩은 메인과 **똑같이** 적용했습니다 — 다르게 주면 손전등 안팎에서 손의 계조가 튑니다.

### 1.3 근평면 클리핑 (완료)

**근평면 클리핑은 투영 단계에서 일어납니다.** 깊이 클리어나 렌더 순서로는 절대 못 고칩니다. 근평면을 줄이는 것 말고 방법이 없습니다.

- **PC**: 오버레이 카메라 근평면 `0.151` → **`0.01`**. 오버레이 전용이라 월드 깊이 정밀도와 무관합니다(애초에 오버레이를 만든 이유가 이것).
- **VR**: 오버레이가 **아예 없었습니다**(URP 오버레이는 XR 스테레오 미지원 → 한쪽 눈에만 렌더). `ApplyVrPath()`를 추가해 메인 카메라 근평면 **0.03** / 원평면 1000 → **400**으로 잡습니다. 깊이 정밀도는 **근/원 비율**이 지배하므로 `0.03/400`이 `0.15/1000`보다 오히려 낫습니다. 뷰모델 레이어를 메인 cullingMask에 **다시 넣습니다** — 오버레이가 없는데 레이어가 빠지면 팔이 통째로 사라집니다.

### 1.4 팔꿈치 아래만 (완료)

`BodyPartTaggerTool`에 **"팔꿈치 아래만"** 토글 추가(기본 켬). 기존 판정이 `n.Contains("arm")`이라 **`Upperarm`까지 걸렸습니다** — `forearm`을 먼저 걸러야 갈립니다. 파츠 70개 중 **11개만** 남습니다.

어깨가 없어지면 `pullBack`(카메라 뒤 어깨를 담는 장치)이 불필요해지고, 어깨가 벽에 파묻히던 문제도 원인째 사라집니다.

### 1.5 1인칭 기본 자세 · 등반 손 절차 동작 (코드 완료, 값 미확정)

`MantleRig`에 `driveIdlePose` + `idleLocalR/L` · `idleEulerR/L` · `idleGripR/L` 추가.

**전완 뼈를 직접 대입하지 않았습니다.** 팔 뼈는 `HandIK` 소유라(설계 §3) 직접 쓰면 서로 덮어씁니다. 대신 **기존 park 기구를 재사용**해 Idle에서 IK 타깃을 카메라 로컬 지점에 두고 weight 1로 둡니다. 덕분에 **기본↔등반 전환이 두 지점 사이 보간**이 되어 팝이 원리적으로 안 생깁니다.

등반 손 절차 동작도 넣었습니다.
- 손가락 **시차 감기** — 검지→중지→약지→새끼 순, 엄지는 가장 늦고 덜 감김(`thumbCurlScale`). 다섯 개가 동시에 같은 양으로 감기면 집게처럼 보입니다.
- 감길수록 **벌림이 줄어듭니다**(편 손은 벌어지고 쥔 손은 모임).
- **손목 꺾임** — 잡는 순간 살짝 꺾임(`climbWristFlexDeg` 12° / `climbWristRollDeg` 8°). 뼈를 직접 만지지 않고 **IK 목표 회전에 얹습니다**(§3).

### 1.6 거미 (부분)

- **응시 추가** — 퍼치 중 카메라를 봅니다. **완전 LookAt이 아닙니다**: 다리 끝이 팔에 고정돼 있어 몸통을 다 돌리면 다리가 꼬이고 손목 뒤를 볼 때 뒤집힙니다. `gazeMaxDeg`(55°)까지만 비틀고 넘으면 멈춥니다 — 그 "못 따라오는" 느낌이 오히려 생물처럼 보입니다.
- 크기 `0.04 → 0.13`(3.4배 = 2 × 1.7, 사용자 지시).
- `SpiderRig.body`가 비어 있어 `PlayerBodyParts` 연결. 다리 앵커 재생성.
- **다리 4개는 이미 배선돼 있었습니다**(`L_Leg1_Upper/Lower/Toe` … + `[LegAnchor_0~3]`). 설계 §6.5의 "모델에 뼈가 0개"는 **문서가 낡은 것**입니다.

### 1.7 F6 조정 패널 (완료)

`ViewmodelTuningPanel` 신규. 자동 부착. **Start에서 저장값을 자동으로 불러옵니다.**
오른손/왼손 위치·회전·손가락 · 손 뼈 축 보정 · 거미 응시·얹히는 자리 · 다리 반지름·간격 · 근평면(PC/VR). 저장 → `Poses/viewmodel_tuning.json`.

> 리그는 **Play 중에만** 존재합니다. 맞춘 값은 반드시 **저장**을 눌러야 남습니다.

### 1.8 `ViewmodelStudio` 씬 수술 (완료)

이 씬은 **`[Head]` 분리 이전의 옛 구조**였습니다. `MouseLook`이 없어 **카메라가 안 돌았고**, `MotionFeel`이 몸에 붙어 롤이 시선 축이 아니라 몸 앞 축을 돌게 되어 있었습니다(설계가 명시적으로 금지한 배치).

`GameBoot`이 정본 리그를 만들도록 맞췄습니다.
- `Main Camera`를 루트로 분리(`Viewmodel`이 자식이라 동행) → Play 때 `[Head]` 아래로 재부착
- 옛 컴포넌트 5개 제거(`CharacterController`·`FirstPersonPlayer`·`MotionFeel`·`AutoTraversal`·`MantleRig`)
- `Player` → **`[BodyMode]`** 로 개명, `PlayerBodyModeController`만 유지(파츠 참조 보존)
- `[GameBoot]` 배치 (`startPosition (0,0,-4)`, `eyeHeight 1.6`)
- 뼈·파츠 171개를 FBX 원본 자세로 복원, 루트 **스케일 2**, **회전 180°**

## 2. ★ 버그 원인 표 — 증상과 원인이 안 닮은 것들

| # | 증상 | 진짜 원인 | 조치 |
|---|---|---|---|
| 1 | 에디터에서 뷰모델 오버레이가 안 붙음 | `LateUpdate`에서만 설치 → **Play 전용**. `[ExecuteAlways]`를 붙여도 에디터 틱이 씬 뷰 리페인트에 의존해 확실하지 않다(실제로 안 돌았다) | `ViewRigEditorDriver`가 `EditorApplication.update`에서 직접 구동 |

## 3. 불변식 — 깨면 조용히 망가지는 것들

1. **`??`를 `GetComponent`에 쓰지 마십시오.** 가짜 null을 통과시킵니다. 반드시 `== null`.
2. **`OnValidate`에서 오브젝트를 만들거나 지우지 마십시오.** 조용히 실패하고 뒤에서 터집니다.
3. **저장 JSON이 있는 값은 기본값만 고쳐서는 안 됩니다.** `Awake`의 로드가 덮어씁니다. (`viewmodelcam.json`, `lightrig_*.json`, `viewmodel_tuning.json`, `pose_*.json`)
4. **루트 TRS 소유자는 하나입니다** — `PlayerBodyModeController`. 포즈 데이터·`ViewmodelMotion`·`PosePlayer`가 겹치면 안 됩니다(설계 §3).
5. **팔 뼈는 `HandIK` 소유입니다.** 자세를 주려면 **IK 타깃**을 옮기십시오. 뼈를 직접 쓰면 매 프레임 덮어씁니다.
6. **뷰모델 스킨드 메시는 `updateWhenOffscreen = true`여야 합니다.** 아니면 화면 정중앙에 있어도 컬링됩니다.
7. **IK 목표는 도달거리 안쪽**(80% 권장). 넘으면 뻗친 채 굳습니다.
8. **URP 오버레이 카메라는 VR에서 쓸 수 없습니다.** 스테레오가 깨집니다.
9. **모드별 튜닝 파일을 섞지 마십시오.** PC 값이 VR을 망가뜨립니다.
10. 이전 세션 불변식도 유효합니다: `minHeight ≤ CC.stepOffset`, `landMinSpeed > 2.0`.

## 4. 미결 — 판단이 필요한 것

### 4.1 3인칭 빙의 (이 세션의 본 주제, 감사만 끝남)

요구사항(사용자 확정):
- 빙의 중 플레이어 본체는 **해킹한 순간의 방향**으로 남는다 → **이미 됨** (`MakeShell(_rig.position, ViewYaw)`)
- **빙의 해제 순간의 방향을 기록해 경비병이 그 방향으로 남는다** → **미구현**
- 본체 자세는 사용자가 직접 만든다 + `idle` 숨쉬기 절차 실행
- CCTV 비활성 · **터렛은 빙의 대상이 아니다** → `EnterFixed`(고정 시점) 경로는 이번 범위 밖. 따라서 **VR에서 시점 소유자가 계속 `[Head]` 하나로 유지되어 구조가 안 깨집니다.**

**감사 결과 — 버그 3개**

1. **빙의할 때마다 몸이 가라앉습니다(릴레이에서 누적).** 리그 원점은 **눈높이**인데 셸은 **발+1m**에 놓고, 복귀 때 그 셸 트랜스폼을 리그 좌표로 **재사용**합니다. 셸을 "그리는 물건"과 "복귀 지점"으로 겸용한 것이 원인입니다. **복귀 좌표는 숫자로 따로 들고 있어야 합니다.**
2. **경비병 눈높이가 플레이어 것입니다.** `_eyeHeight`를 플레이어 CC에서 계산해 씁니다. 경비병이 더 크면 눈이 가슴께에 박힙니다. `ViewEntryTarget.eye`가 이미 정의돼 있고 고정 시점은 그걸 쓰는데, **몸 이동 모드만 안 씁니다.**
3. **본체(셸)가 표적이 아닙니다.** `MakeShell`이 콜라이더를 지웁니다("조준을 가로채지 않게"). 설계 §6.3은 본체를 "취약 표적이자 복귀 지점"으로 규정하는데 지금은 **순수 장식**입니다.

**릴레이(경비병→경비병)는 구조적으로 정상입니다.** `Enter()`가 먼저 `Exit()`를 부르므로 A의 메시·콜라이더가 복구되고 리그가 본체 자리로 돌아간 뒤 B로 갑니다. 본체 위치도 유지됩니다. 다만 셸이 매번 파괴·재생성되어 **숨쉬기 위상이 끊기고** 그 한 프레임 동안 본체가 없습니다.

**피격 판정은 이미 되어 있습니다** — 걱정할 필요 없습니다.
- `GuardDetection.SeesPlayer()`가 빙의 중이면 즉시 false ("경비병이 경비병을 발각하는 꼴")
- `TurretGun`이 `ViewEntryController.Current.AllowsMove`로 판정해 안 쏨
- 둘 다 **리그를 경비병 자리로 옮기는 방식**을 전제로 짜여 있습니다. 그 방식을 바꾸면 이 판정이 깨집니다.

**사용자에게 물어봤으나 답을 못 받은 것 2개**
1. 경비병 눈높이를 `ViewEntryTarget.eye`(수동 지정)로 할지, 콜라이더 높이에서 자동으로 뽑을지
2. 본체를 표적으로 만들지 (설계 문서는 전자를 전제)

**권장 구현 순서**: 가라앉음 수정 → 눈높이를 `target.eye`로 → 셸을 파괴하지 않고 재사용(숨쉬기 위상 유지) → 셸을 `PlayerBodyParts`의 3인칭 파츠 + `BodyIdleMotion`으로 교체 → 해제 시 경비병 yaw 기록.

### 4.2 값 미확정

- **1인칭 손 자세** — 사용자가 원하는 것은 매사냥 가로 자세가 **아니라** "오른쪽 아래에서 손이 들어와 손등이 보이는" 평범한 자세입니다(사진 제공). 제가 처음에 잘못 이해했습니다. 기본값을 `idleLocalR (0.02, -0.30, 0.48)` / `idleEulerR (10, -30, 0)`로 근사만 해 뒀고 **F6으로 확정해야 합니다.**
- **거미 얹히는 자리** — 손등 살짝 아래(손목 쪽). 사용자가 직접 조정하겠다고 했습니다.
- **`OneBitControl` 재조정** — 뷰모델 전용 라이트가 새로 생겨 확정값(`inWhite 0.5 / lightWrap 1`)의 전제가 깨졌습니다. 그 값은 "라이트 없는 스튜디오" 기준이었습니다.
- **VR 손전등 그림자** — `Mobile_RPAsset`이 Additional Light Shadows를 꺼 두고 있어 **VR에선 그림자가 안 나옵니다.** 켜려면 해상도 2048→512로 낮춰야 하고 Cardboard는 2배 렌더입니다. 실기 프레임을 봐야 정합니다.
- **`ViewmodelStudio` 앰비언트** — 이 씬만 0.212로 예외입니다. 리그가 Play 중에만 생기므로 에디터에서 팔을 보려면 필요합니다. 정리할지 판단 필요.

### 4.3 미조치로 남긴 것

- **`ControllerLink` 소켓 누수**(§2 #13). 사용자가 "지금 그딴거 할 시간 없음"이라 보류했습니다. 값어치 순서는 ① 어셈블리 리로드 직전 정리 훅 ② 에러 문구 개선 ③ 바인드 실패 시 재시도. `ReceiveTimeout`은 ①과 겹쳐 불필요합니다.
- **`GameBoot`의 `??` 패턴 4곳**(`MotionFeel`, `FirstPersonPlayer`, `UniversalAdditionalCameraData`). §2 #5와 같은 부류의 잠재 버그이나 지금 터지지 않습니다.
- **`HackSandbox`의 `Protag`** — 스케일 2·회전 180°·파츠 분류를 적용하지 않았습니다. `PosePlayer` 수정은 코드라 전역으로 듣지만 나머지는 씬별 값입니다. `ViewmodelStudio`에서 자세가 확정된 뒤 옮기는 편이 낫습니다.
