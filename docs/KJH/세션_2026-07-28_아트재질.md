## 3. 🔑 핵심 발견 — AI 모델의 UV가 망가져 있다

**이게 이 세션에서 가장 중요한 사실이다.**

```
tripo_part_4    UV면적 0.000018  ↔  3D표면적 0.141531   →  1 : 7,900
UV 범위는 0~0.85로 넓은데 면적은 0에 가깝다 = UV 껍질이 면적 없는 슬리버
UV1/UV2/UV3 없음 (채널 0 하나뿐)
```

**의미**: **어떤 텍스처도 붙지 않는다.** 베이크한 `Presser_Normal.png`(2048²)를 물려도 요철이 전혀 안 나타난다. 파트가 텍스처의 극히 작은 점 하나만 샘플링하기 때문. 늘어난 줄무늬로 뭉개진다.

**교훈**: UV를 판단할 때 **범위(bounds)가 아니라 면적(area)** 을 봐야 한다. 범위만 보면 정상으로 착각한다.

**선택지였던 것**
- A. 트라이플래너/절차 (UV 무시) ← **채택**
- B. Blender에서 UV 재전개 + 노멀 재베이크 (모델 3개 × 100여 파트, 비용 큼)
- C. 셰이더 절차 마스크 ← A와 함께 채택

## 4. 절차 재질 `TriplanarGrunge`

```
Assets/_Project/Shaders/TriplanarGrunge.shader
Assets/_Project/Art/Mat_FactoryGrunge.mat        ← 공유 머티리얼
```

**UV를 전혀 쓰지 않는다.** 월드 좌표 기반:
- fbm 3옥타브 그런지(명도 얼룩)
- **높이 기반 녹** (`_RustHeight` 아래로 갈수록)
- **윗면 먼지** (N.y↑) / **아랫면 캐비티** (N.y↓)
- 노이즈 기울기로 **노멀 퍼터베이션** (탄젠트·노멀맵 불필요)
- 녹·먼지 부위는 **거칠고 metallic 낮게** ← 폐공장 질감의 핵심
- 애초에 회색만 출력 → 흑백 2단계 전환 시에도 교체 불필요

패스: ForwardLit / ShadowCaster / DepthOnly 직접 작성(URP Lit 패스를 include하면 `_BaseMap`·`_Cutoff`를 요구해서).

**주의**
- 녹이 **월드 Y 절대값** 기준 → 오브젝트를 옮기면 녹 분포가 변한다. 로컬 기준이 필요하면 수정.
- **모바일 성능**: 픽셀당 fbm 4회(요철 기울기). 무거우면 `_BumpStrength = 0` → 4회가 사라진다.

현재 적용: `Model_Piston`(67), `Model_Rail`(96). **`Model_Presser`(126)는 TallCity 머티리얼 순환 배정 상태**(비교 실험 중이라 되돌리지 않음).

## 5. 흑백 아트 + 조명

상세 계획은 **[design/흑백_아트_계획.md](design/흑백_아트_계획.md)** 에 별도로 작성해뒀다. 요약만:

- **1단계(지금) = 후처리** Color Adjustments 채도 −100. 색으로 남길 것(LED·UI·이펙트)이 **아직 없으므로** 단점이 발생하지 않는다.
- **2단계 = 셰이더 교체**(`GreyLit` + 전역 `_Desaturation` 프로퍼티). **LED·UI가 처음 생길 때** 전환. 그때는 "색으로 남길 소수만 지정"이라 작업이 오히려 쉬워진다.
- **텍스처 오프라인 변환은 쓰지 않는다** — 복구 불가라 사용자 원칙에 어긋남.

**조명 원칙 (중요)**: **금속은 환경 반사에서 밝기를 얻는다.** `reflectionIntensity=0` + `skybox=null` + `ambient≈0`을 동시에 하면 직접광이 닿아도 **검게 남는다**. ambient·reflection은 **무채색으로** 만드는 것이지 **0으로 만드는 게 아니다.**

- 환경광·반사 / 조명 개별 on·off·세기·범위·각도 / 채도·대비·노출·블룸 / 절차 재질 파라미터

## 6. ▶ 다음 작업 — 프레스·피스톤 신축 애니메이션

사용자가 **파트를 3그룹으로 직접 분류해뒀다**:
> 고정부(벽·레일에 붙음) / **연결부(이동 + 스케일 변화)** / 가동부(실제 움직임)
> → `Anchor` / `Shaft` / `Head`

### 실측 (프리팹 기준, 루트 scale=11)

**Model_Presser — 세로(Y), 위에 매달린 구조**
```
Y 10.77 ┬─ Anchor  25파트   고정
Y  8.12 ┘
Y  8.32 ┬─ Shaft    4파트   늘어남   ← Anchor 바닥(8.12)과 맞물림
Y  3.21 ┘
Y  8.24 ┬─ Head    97파트   내려옴   ← Shaft 아래쪽이 Head 안에 잠겨 있음
Y  1.26 ┘
```
- **이동 축 = Y(아래)**. 현재 거의 접힌 상태(스트로크 상단). 바닥까지 여유 **1.26**.
- 텔레스코핑 구조가 이미 성립해 있다.

**Model_Piston — 가로(X)**
```
X -23.03 ~ -22.46   Anchor  1파트   (폭 0.56)
X -22.87 ~ -20.13   Shaft  23파트   (폭 2.74)
X -29.29 ~ -18.61   Head   43파트   (폭 10.67)
```
- **이동 축 = X**
- ⚠️ **Head 범위가 Anchor·Shaft를 통째로 감싼다.** 피스톤이라면 Head는 Shaft 한쪽 끝에 있어야 하는데 양쪽으로 뻗어 있다. **43개 중 일부가 반대편에 잘못 분류됐을 가능성** — 사용자 확인 필요.

### 결정해야 할 것 (사용자와 상의 중이던 지점)

**① Shaft를 어떻게 늘릴 것인가**

| 방법 | 특징 |
|---|---|
| **스케일** | 간단하나 **끝단 디테일(캡·볼트)이 같이 늘어나 뭉개짐** |
| **텔레스코핑** | 늘리지 않고 Head 안으로 잠기게. 왜곡 없음. **실제 유압프레스 방식** |

현재 구조상 **텔레스코핑이 자연스럽다** — Shaft를 Anchor에 고정하고 Head만 내리면 Shaft가 저절로 드러난다. 늘릴 필요 자체가 없을 수 있다. (이 답을 듣기 전에 세션이 끊겼다.)

**② Shaft 피벗** — 스케일 방식이면 피벗이 **Anchor 쪽 끝**에 있어야 한다. 지금 세 그룹 모두 `localPos=(0,0,0) scale=1`이라 **피벗이 프리팹 원점**이다. 스케일하면 원점 기준으로 늘어나므로 재배치 필요.

**③ 스트로크 범위** — Presser는 바닥까지 최대 1.26. 그 이상이면 지면을 뚫는다.

### 설계 문서 연결
조종 방식은 [design/기초_설계안.md](design/기초_설계안.md) §6.2에 이미 확정돼 있다:
> **유압프레스** = 아날로그 정밀(느림·묵직) + **플릭 = 끝까지 내리찍기**
> **피스톤(공압)** = 아날로그 없음, 플릭으로 **끝↔끝 돌출**만(2단)
> 구동 = PD 제어

## 7. 이 세션에서 밟은 함정 (반복 금지)

1. **`VolumeProfile.Add<T>()`만으로는 에셋에 저장되지 않는다.** `AssetDatabase.AddObjectToAsset(comp, profile)`으로 서브에셋 등록까지 해야 한다. → 이걸 빠뜨려 **후처리가 적용된 줄 알았으나 실제 컴포넌트 0개**였다. 사용자가 먼저 눈치챘다.
2. **`GameObject.Find`는 비활성 오브젝트를 못 찾는다.** 꺼둔 조명을 다시 켜는 코드가 동작하지 않았다. → `FindObjectsByType(..., FindObjectsInactive.Include)`.
3. **Play 모드에서의 씬 변경은 정지 시 되돌아간다.** 배치한 모델이 통째로 사라졌다. 씬 작업 전 Play 상태 확인 필수. (`EditorApplication.isPlaying` 체크가 전환 중엔 오탐할 수 있음 — `manage_editor stop`이 "already stopped"를 반환한 적 있다.)
4. **UV는 범위가 아니라 면적으로 판단.** (§3)
5. **환경광·반사를 0으로 만들면 금속이 검정.** 무채색 ≠ 0. (§5)
6. **`execute_code`는 CodeDom(C# 6)** — Roslyn 미설치. `UnpackPrefabInstanceMode`처럼 해석 안 되는 열거형은 **리플렉션 우회** 필요(실제 이름은 `PrefabUnpackMode`였다). `Object`는 `UnityEngine.Object`로 명시.
7. **`AssetDatabase.DeleteAsset`은 안전장치에 막힌다** → `safety_checks: false` 필요.
8. **프리팹 에셋을 지우면 씬 인스턴스가 Missing Prefab으로 깨진다** → 지우기 전에 씬 인스턴스를 언팩해 보존.

### 내가 틀렸던 판단 (사용자가 교정함)
- 프레서 파트를 좌표만 보고 "고정 몸통/포스트/크라운"으로 분류해 색칠했으나 **틀렸다.** 이름 없는 AI 파트는 좌표 추측으로 분류하면 안 된다. 결국 **사용자가 직접 분류**했다.
- "텍스처는 흑백이라 불필요"라고 단언했으나 **틀렸다.** 흑백에서 무의미한 건 **색(hue)** 뿐이고, **명도·러프니스 변화**는 폐공장 질감의 핵심이다.
