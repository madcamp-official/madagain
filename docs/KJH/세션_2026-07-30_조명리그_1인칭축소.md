## 1. 조명 — 완료

플레이어 시점 손전등. **씬의 조명을 전부 지우고** 플레이어가 빛을 들고 다닌다.

### 라이트가 3개인 이유

팔은 카메라에서 30cm 안쪽이라 손전등 원뿔의 최대 강도를 정면으로 받아 **새하얗게 뜬다.**
그래서 월드용과 뷰모델용을 **레이어로 갈랐다**(FPS 표준).

| 이름 | 타입 | cullingMask | 역할 |
|---|---|---|---|
| `[Flashlight]` | Spot | 뷰모델 **제외** | 월드만 비춤 |
| `[Fill]` | Point | 뷰모델 **제외** | 원뿔 바깥이 완전히 죽는 것 방지 |
| `[ViewmodelLight]` | Point | 뷰모델 **만** | 손·거미 전용. 스테이지와 무관하게 일정 |

부수 효과: 뷰모델 조명이 씬과 무관해져 `OneBitControl` 값의 전제였던 "라이트 없는 스튜디오" 조건이 재현된다.

### 부착 위치는 Main Camera (★ `[Head]`가 아니다)

카메라는 `MotionFeel`이 착지 킥·롤로 흔든다. **빛이 발걸음마다 같이 흔들려야** 손전등을 들고 뛰는 감각이 난다.
VR은 `vrRollScale=0`이 기본이라 사실상 정지 — 멀미 방지 측면에서 그게 맞다.

### 눈에서 비킨다

`spotOffset` 기본 `(0.15, -0.10, 0)`. **0으로 두면 그림자가 물체 뒤에 완전히 숨어 평평해 보인다.**
라이트는 씬 객체라 양 눈이 같은 결과를 보므로 **VR에서도 스테레오 불일치를 만들지 않는다.**

### PC / VR

값은 **모드별로 따로 저장**된다(`Poses/lightrig_pc.json` / `lightrig_vr.json`). 한 파일에 섞으면 PC에서 맞춘 값이 VR을 망가뜨린다.

| | PC | VR |
|---|---|---|
| 원뿔 | 45° / 20° | **60° / 28°** (좁으면 터널 시야 → 멀미) |
| 그림자 | Soft | **없음** |
| 필 | 0.6 / 4m | **1.0 / 5m** (그림자가 없어도 공간이 읽혀야) |

> ⚠️ **VR에서 손전등 그림자는 안 나온다.** `Mobile_RPAsset`이 `m_AdditionalLightShadowsSupported: 0`이다.
> 켜려면 해상도를 2048 → 512로 낮춰야 하고 Cardboard는 2배 렌더다. **실기 프레임을 보고 판단할 것.**

### 씬 조명 삭제

`_Project` 아래 **11개 씬 전부**에서 Light 제거 + 앰비언트 `Skybox` → `Flat 0.04`.
단 `ViewmodelStudio`만 **0.212로 되돌렸다** — 라이트가 0개인 손 튜닝 씬이라 0.04면 에디터에서 아무것도 안 보인다.

> 함정: `UniversalAdditionalLightData`가 `[RequireComponent(Light)]`다. **Light를 먼저 지우면 실패한다.**
> 콘솔에만 에러가 쌓이고 조용히 아무것도 안 지워진다. 데이터 컴포넌트를 먼저 지울 것.

## 2. OneBit 셰이더 — 추가 광원 지원

`GetMainLight()` 하나만 읽고 있어서, 포인트·스팟이 **완전히 무시**됐다. 디렉셔널을 지운 순간 손·거미가 통째로 검게 죽는다.

`GetAdditionalLightsCount()` 루프를 넣었다. 랩은 메인과 **똑같이** 적용한다 — 다르게 주면 손전등 안팎에서 손의 계조가 튄다.

> ★ URP 17.5에서 Forward+ 키워드가 **`_FORWARD_PLUS` → `_CLUSTER_LIGHT_LOOP`으로 바뀌었다**(`Core.hlsl:13`).
> 옛 이름을 쓰면 클러스터 경로에서 **조용히 라이트 0개**가 된다.

이 파일은 그 뒤 다른 세션이 스페큘러 맵 보조·해킹 대상 세트를 추가하며 계속 편집 중이다.

## 3. 근평면 — 완료

**근평면 클리핑은 투영 단계에서 일어난다.** 깊이 클리어나 렌더 순서로는 절대 못 고친다.

| | 이전 | 지금 |
|---|---|---|
| PC 오버레이 | 0.151 | **0.01** |
| VR 메인 | 0.15 (대책 없음) | **0.03** / 원평면 400 |

- **0.151은 Precog가 "지저분한 어깨 단면을 잘라내려고" 올린 값**이다. 전완만 쓰는 지금은 어깨가 없고, 대신 손가락이 몇 cm 앞까지 온다.
- ★ `Poses/viewmodelcam.json`이 `nearClip: 0.151`을 **못 박고 있었다.** 기본값만 고치면 아무 변화가 없다. JSON도 함께 고칠 것.
- **VR엔 오버레이가 아예 없었다**(`if (VrMode.Enabled) return;`). URP 오버레이는 XR 스테레오를 지원하지 않는다. `ApplyVrPath()`로 메인 근평면을 직접 낮추고, 뷰모델 레이어를 메인 cullingMask에 **다시 넣는다**(안 넣으면 팔이 통째로 사라진다).
- 정밀도는 근/원 **비율**이 지배한다. `0.03/400`은 `0.15/1000`보다 오히려 낫다.

## 4. 1인칭 축소 — 진행 중

**전완(팔꿈치~손)만 남기고** 절차적으로 배치한다. 어깨가 없어지면 근평면·벽 관통 문제가 원인째 사라진다.

### 이미 있던 것 (다른 세션 작업)

`PlayerBodyParts`(본 가중치로 팔/나머지 분류) · `BodyPartTaggerTool` · `PlayerBodyModeController`(1↔3인칭) ·
`SpiderRig`(퍼치·독수리식 수평 안정화) · `SpiderLegs`(다리 4개를 팔 앵커에 스냅) · `HandIK` · `FingerPoser` · `MantleRig`.

### 이 세션이 얹은 것

1. **`BodyPartTaggerTool`에 "팔꿈치 아래만" 토글** — 기존 판정이 `n.Contains("arm")`이라 **`Upperarm`도 걸렸다.** `forearm`을 먼저 걸러야 갈린다. 결과: 파츠 70개 중 **11개만** 켜짐.
2. **`MantleRig`에 1인칭 기본 자세** — `idleLocalR/L`, `idleEulerR/L`, `idleWeight`, `idleGripR/L`.
   전완 뼈를 직접 대입하지 **않았다**. 팔 뼈는 `HandIK` 소유라(설계 §3) 직접 쓰면 서로 덮어쓴다.
   대신 **기존 park 기구를 재사용**했다 — 기본↔등반 전환이 두 지점 사이 보간이 되어 팝이 원리적으로 안 생긴다.
3. **거미 카메라 응시** — `gazeAmount` / `gazeMaxDeg`(55°). 완전 LookAt은 다리가 꼬이고 몸이 뒤집힌다. 각도를 넘으면 멈추는데, 그 '못 따라오는' 느낌이 오히려 생물처럼 보인다.
4. **등반 손 절차 동작** — 다섯 손가락이 동시에 같은 양으로 감기면 집게처럼 보인다. 검지→중지→약지→새끼 **시차**, 엄지는 가장 늦게 70%. 벌림은 쥘수록 0으로. 손목은 잡는 순간 12° 꺾이고 8° 비틀린다(**IK 목표 회전에 얹는 오프셋**으로 — 뼈를 만지면 소유권이 겹친다).
5. **F6 `ViewmodelTuningPanel`** — 손 위치·회전·손가락, 거미 응시·자리, 다리 앵커, 근평면. 저장/불러오기. 자동 부착. **Start에서 저장값을 자동으로 불러온다.**

### ★ 자세 값은 아직 안 맞는다

사용자가 원하는 것은 **오른쪽 아래에서 손이 들어와 손등이 보이는** 자세다(매사냥처럼 전완을 가로로 눕히는 게 **아니다** — 이걸 한 번 잘못 이해했다).
거미는 그 **손등 살짝 아래(손목 쪽)**에 앉는다.

현재 기본값은 근사치다. `idleLocalR (0.02, -0.30, 0.48)` / `idleEulerR (10, -30, 0)`.
**F6으로 눈으로 맞춰야 한다.** 계산으로 정할 수 없다 — 리그마다 손 뼈가 보는 축이 다르다.

## 5. 이 세션이 찾은 함정 (같은 데 다시 빠지지 말 것)

| 증상 | 원인 | 조치 |
|---|---|---|
| Play에서만 몸이 100배(키 75m), 팔이 화면 밖 50m 위 | **`pose_기본포즈.json`의 `rootScale [100,100,100]`.** Precog(카타나) 데이터가 이식된 것. 그쪽은 FBX 임포트 스케일 1/100이라 맞았지만 우리 리그는 뼈 좌표가 이미 미터 단위 | `PosePlayer.applyRootTrs`를 기본 **끔**으로. 루트 TRS는 `PlayerBodyModeController` 단독 소유(§3). 뼈 회전은 그대로 씀 |
| **거미는 보이는데 팔만 안 보임** | 스킨드 메시 컬링 바운드가 뼈를 안 따라간다. IK가 손을 수십 cm 밖으로 끌고 가면 바운드가 딴 데 남아 `isVisible=false`. 실측: `R_Hand` 뷰포트 (0.76,0.10)인데 팔 파츠 바운드는 −54까지 흩어짐 | `PlayerBodyParts.Awake()`에서 `updateWhenOffscreen = true` |
| 모델이 카메라를 마주 봄(오른 어깨가 −x) | 루트 회전 0 | 루트 Y **180°** |
| 팔이 뻗친 채로 굳음 | IK 목표가 도달거리 밖 → 클램프 | 어깨에서 도달거리의 **80% 안쪽**에 목표를 둘 것. 루트 스케일 2 기준 오른팔 도달 **0.67m** |
| 시점이 안 돌아감 (`ViewmodelStudio`) | `[Head]` 분리 이전의 옛 구조라 **`MouseLook`이 없었다.** `MotionFeel`도 몸에 붙어 있어 롤이 시선 축을 안 돌았다 | 씬을 `GameBoot` 정본 리그로 교체 |
| `MissingComponentException` (조명 리그) | `GetComponent<T>() ?? AddComponent<T>()` — **`??`는 유니티가 오버로드한 `==`를 안 거쳐** 가짜 null을 통과시킨다. `OnValidate`에서의 오브젝트 생성도 금지 | 명시적 `== null` 비교. `OnValidate`는 값 반영만 |
| 라이트가 안 지워짐 | `UniversalAdditionalLightData`가 `[RequireComponent(Light)]` | 데이터 컴포넌트를 먼저 삭제 |
| UDP 45710 바인드 실패 | **Play 중 재컴파일 시 수신 스레드가 샌다.** Mono 관리 스레드는 도메인 리로드로 안 죽고 소켓을 붙든다. GC로도 안 풀림 | 지금은 **에디터 재시작**이 유일한 해법. 근본 고침은 §7 |

## 6. ★ 지금 떠 있는 컴파일 에러 — 이 세션 것이 아님

```
Assets\_Project\View\Hacking\HackDriver.cs(45,16): error CS0246:
The type or namespace name 'PossessionTransition' could not be found
```

확인한 사실:
- `View/Hacking/ViewEntry/PossessionTransition.cs`에 `namespace Game.View` / `public class PossessionTransition`로 **정상 존재한다.**
- `HackDriver.cs`도 같은 `Game.View`다.
- 즉 **소스상으로는 맞다.** 다른 세션이 이 영역(`OneBit.shader`도 동시에)을 편집 중이라 중간 상태로 보인다.

**먼저 할 일: 리프레시/재컴파일 후 에러가 남는지 확인.** 남으면 `PossessionTransition.cs` 내부에 문법 오류가 있는지 볼 것.

## 7. 남은 일

### 자세 확정 (가장 급함)
`ViewmodelStudio`에서 **Play → F6**으로 오른손 위치·회전을 사진처럼 맞추고 **저장**.
손이 뒤집혀 보이면 회전이 아니라 **축 보정**(`handEulerR`)을 만질 것.

### 값 이식
`ViewmodelStudio`에서 확정한 값을 `HackSandbox`로. 지금 옮기면 두 번 작업하게 되므로 확정 후에.
`PosePlayer` 수정은 코드라 전역으로 듣지만, **스케일 2 · 회전 180° · 파츠 분류는 씬별 값**이다.

### 조명 값 튜닝
Play에서 F2 → "플레이어 조명 리그" → **저장**. PC/VR 각각 한 번씩.

### `OneBitControl` 재조정
뷰모델 전용 라이트가 새로 생겨 확정값(`inWhite 0.5 / lightWrap 1`)의 전제가 깨졌다.

### VR 실기 확인
- 손전등 그림자를 켤지 (프레임 여유 보고)
- 근평면 0.03에서 z-fighting이 보이는지
- OneBit 디더가 양안에서 어른거리는지 (화면 좌표 기반이라 눈마다 패턴이 다르다 — 미검증)

### `ControllerLink` 소켓 누수 (선택)
정상 흐름에서는 문제없다. **Play 중 재컴파일**과 **두 에디터 동시 Play**에서만 터진다.
값어치 있는 것만: ① 어셈블리 리로드 직전 정리 훅 ② 에러 문구 개선. 재시도 로직은 두 에디터를 얼마나 자주 같이 Play하는지에 달렸다.

### 정리 대상
`GameBoot`의 `GetComponent<T>() ?? AddComponent<T>()` 4곳 — 위에서 터진 것과 같은 부류. 지금은 안 터지고 있다.
