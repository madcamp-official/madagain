## 1. 레일 세트 (커밋 `b8e8e9d`)

설계 문서: [design/레일_세트_설계.md](design/레일_세트_설계.md) — 전면 갱신됨. **먼저 읽을 것.**

핵심 수정: `riderRoot`만 옮기던 것을 **`RailSet` 루트가 직접 움직이도록** 교체.
Rails/·Riders/가 자식이라 통째로 따라가고 중첩·기즈모·조종 실이 자동으로 맞는다.

- **좌표**: `center` 삭제 → **앵커**(배치 위치) 기준, **부모 공간** 단위.
  길이 환산은 **부모 스케일**(`ParentScaleAlongAxis`)로 — 기존 툴은 자기 스케일을 써서 틀렸다.
- **플릭**: 시간 기반 + `Mech()` 곡선(smootherstep+오버슈트) = **철컥** 안착. 크립은 가감속 램프.
- **`RailPlatform`**(신규): 세트 이동 델타만큼 `CharacterController.Move`. 계층 부모 지정을 안 해
  VR 리그·AutoTraversal·MantleRig와 충돌 없음. 중첩 시 소유자 판정으로 이중 이송 방지.
- `IRunResettable`(아레나 리셋 시 앵커 복귀), `OnCellArrived`/`CurrentCell`/`AtRest` 노출.
- 에디터: 앵커 기즈모·양 끝 고스트·레일 길이/콜라이더 경고 + **그레이박스 생성 메뉴**
  (`GameObject > MINDHEXER > 레일 세트 (그레이박스)`) — 프리팹 없이 즉시 테스트.

**미결**(설계 §9): 레일 프리팹 · **경비병 NavMeshAgent 탑승**(지금은 CharacterController만) ·
오디오 훅 · 수치 튜닝 · `OnCellArrived` ↔ 아레나 클리어 배선.

## 3. 경비병 — 현재 상태

### 프리팹 (`Prefabs/Hackables/ViewEntry/Guard.prefab`)
원래 `Hackable`만 있던 미완성 프리팹에 다음을 **구워 넣었다**:
`CapsuleCollider`(h1.94/r0.35) · `GuardDetection`(6m) · `ViewEntryTarget`(경비병 프리셋:
pan180/tilt85/allowsMove=true/blocker=false) · `Camera` 눈 앵커(루트 직속 — 애니에 안 흔들림) ·
`GuardManual` 컨트롤러 · `GuardDestruction`(조각 10개 연결).

### 애니메이션
에셋 팩 `Robot1 Animator Controller`는 **상태 7개가 전부 전이를 갖는 데모용 순환 컨트롤러**라
하나를 재생하면 자동으로 다음으로 넘어갔다. → **전이 0개짜리 `Art/GuardManual.controller`를
새로 만들어 교체.** 빈 기본 상태 `None` + 클립 7개, 재생하면 그 상태에 머문다.

| # | 클립 | 실제 동작 | 길이 | 루프 |
|---|---|---|---|---|
| 0 | `Attack_Arm_1` | 공격(팔) | 1.00s | ❌ |
| 1 | `Idle_1` | 기본 대기 | 3.33s | ❌ |
| 2 | `Idle_2` | **왼쪽 보기** 대기 | 3.33s | ❌ |
| 3 | `Idle_3` | **오른쪽 보기** 대기 | 3.33s | ❌ |
| 4 | `Idle_Crazy_Robot` | **오작동** 대기 | 3.33s | ❌ |
| 5 | `Run_IP` | 뛰기(제자리) | 0.67s | ❌ |
| 6 | `Walk_IP` | 걷기(제자리) | 0.87s | ❌ |

- **전 클립이 loop=False** → 재생 후 마지막 프레임에서 멈춘다. Idle/Walk/Run은 실제 사용 시
  **loopTime을 켜야 한다**(미처리, §7 대기 항목).
- 없는 것: **조준·사격 애니**(§2.3 경비병 위협 모델에 필요), **사망 애니**.
- 프리팹 Animator는 **`ApplyRootMotion` 켜짐** — 코드로 이동시킬 때 충돌하므로 그때 꺼야 한다.

### 파괴 (커밋 `d707969`)
- **조각 10개**를 `MeshSplitter`(본 가중치 분할)로 미리 구움 →
  `Prefabs/Hackables/ViewEntry/GuardDebris/` (Head 482tri / Torso 252 / 팔·다리 각 84~173).
  원본 1698tri와 **정확히 상보적**(누락 없음). 각 조각 = MeshFilter+MeshRenderer+BoxCollider+Rigidbody.
- **`View/Entities/GuardDestruction.cs`** — 원본 숨김 → 조각 스폰 → 임펄스 → `life`(8s) 후 정리.
- **충돌 규칙**: 레이어 매트릭스 대신 **`Physics.IgnoreCollision`으로 플레이어만 무시**.
  이유 — **바닥이 `Default`(0)이고 플레이어는 GameBoot가 런타임 생성**이라 전용 레이어가 없다.
  레이어로 끊으면 잔해가 **바닥까지 통과**한다. 나중에 플레이어를 전용 레이어로 옮기면 매트릭스로 전환 가능.
- **힘 튜닝 완료**: `burst 0.4 / upBias 0.1 / spin 1.0` — 폭발이 아니라 **주저앉듯** 무너진다
  (초기값 3.5/1.6/4는 "너무 강하게 터짐"이라 낮췄다).

### 메커니즘 (설계 확정, 구현 안 됨)
**한 번이라도 해킹당하면**: ① 해킹 성공 순간 **감지 범위 영구 소멸**(`GuardDetection.Active`가

→ 경비병은 "위협 → 도구"로 바뀌는 **일방향 자원**. 순찰 AI·NavMesh·복귀 로직이 전부 불필요해진다.

**미결**: **재해킹 허용 여부**(권장: 허용 — 소프트락 방지에 유리), 고장 표현
(`Idle_Crazy_Robot` vs 애니 정지).

## 5. 빙의 = 리그 이동 (A안) — **미커밋, 컴파일은 통과**

"빙의 중 본체와 **완전히 동일한 조작**(해킹 포함)" 요구를 만족시키는 구조.
기존 코드는 **모순 상태**였다 — 경비병은 `allowsMove=true`라 본체가 안 얼었고, 카메라만 경비병
눈에 붙어 있어 **WASD를 누르면 화면은 고정된 채 본체만 걸어갔다.** 경비병을 움직이는 코드는 없었다.

### 채택안 (A) — 리그를 옮기고 셸을 남긴다
`GameBoot`가 만드는 PC 리그는 **Main Camera 오브젝트 자체**다
(FirstPersonPlayer·AutoTraversal·MantleRig·MotionFeel·HackDriver가 전부 여기). 그래서:

- 빙의 시 **리그를 통째로 경비병 자리로 순간이동**(CC 껐다 켜서 위치 씹힘 방지)
- 원래 자리에 **`[BodyShell]`**(지금은 임시 캡슐, `shellPrefab`에 본체 모델 꽂으면 대체)
- 경비병 본체: **콜라이더 끄고 메시 숨김** + 매 프레임 리그를 **yaw만** 따라감
  → **빙의를 풀면 데려간 자리에 그대로 남는다**(§6.3 "경비병을 옮겨 길 정리")
- **CCTV·터렛(`allowsMove=false`)은 기존 방식 유지** — 대상 눈에 별도 카메라 + 본체 정지
- **실 연결**: 빙의 중 실이 **셸 → 경비병**을 잇는다(리그가 이동했으므로 카메라 기준이면 길이 0)
- `HackDriver.ActiveCam`이 `viewEntry.Cam == null`(몸 이동 모드)이면 플레이어 카메라로 폴백

**(B)안(경비병에 리그 복제)을 버린 이유**: 이동 스택이 두 벌이 되어 포크 세션이 이동을 고칠 때마다
양쪽을 관리해야 하고, 경비병 루트를 눈높이로 재구성 + pitch가 모델을 기울이는 문제를 따로 풀어야 한다.

### ⚠️ 실기 검증이 안 됐다
컴파일만 통과했고 **플레이 테스트 전에 세션이 끝났다.** 다음 작업자가 확인할 것:
1. 경비병 해킹 → **WASD로 걸어지는가**, 벽에서 자동 등반이 되는가
2. 뒤돌아보면 원래 자리에 **캡슐(셸)과 실**이 보이는가
3. **Q 복귀** 시 원위치로 돌아오고 **경비병이 데려간 자리에 서 있는가**
4. CCTV 빙의([F4])가 예전처럼 동작하는가(회귀 확인)

## 9. 이 세션에서 배운 함정

- **Unity 플레이 모드 중엔 씬·프리팹 변경이 안 먹는다**(`MarkSceneDirty`가 예외). 에디터 작업 전 정지 확인.
- **`execute_code`는 CodeDom(C#6)** — `out var`·`default` 리터럴 불가, `Object`가 모호하면
  `UnityEngine.Object`로 명시. `AssetDatabase.DeleteAsset`은 안전장치에 막힌다.
- **`EditorUtility.InstanceIDToObject`는 폐기됨** → `EntityIdToObject`.
- 애셋 팩 컨트롤러는 **데모용 순환 구조**인 경우가 많다 — 수동 제어하려면 전이 없는 컨트롤러를 따로 만들 것.
