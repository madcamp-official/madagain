## 1. ★ 빙의가 몸이 아니라 카메라만 옮기고 있었다

`[Head]` 층을 넣은 뒤(→ 앞 문서 §1) 드러난 잔재다.

```csharp
// ViewEntryController.EnterBody — 고치기 전
_rig = playerCam.transform;                         // ← 카메라
var cc = _rig.GetComponent<CharacterController>();  // ← null (CC는 [PlayerBody]에 있다)
Teleport(_rig, feet + up * _eyeHeight);             // ← 카메라만 날아간다
```

주석에 *"플레이어 리그 = 카메라 오브젝트(GameBoot 구성)"* 라고 적혀 있었다. **카메라가 곧 리그였던
옛 구조의 잔재**다. 지금은 `[PlayerBody] > [Head] > Main Camera` 3층이고 CC는 맨 위에 있다.

**증상 세 개가 모두 이 하나에서 나왔다.**

| 증상 | 이유 |
|---|---|
| 회전이 이상함 | 몸은 원래 자리에서 충돌·이동을 계속하는데 카메라만 경비병 위에 떠 있었다 |
| 복귀가 이상함 | `ExitBody`도 카메라만 셸 자리로 돌렸다. 몸은 애초에 움직인 적이 없다 |
| 경비병 방향이 화면과 안 맞음 | `_rig.eulerAngles.y`로 yaw를 읽었는데 **`[PlayerBody]`는 회전하지 않는다**(항상 0) |

### 고친 것

`_rig`(=몸, CC가 붙은 트랜스폼)와 `_view`(=카메라, **yaw 전용**)를 분리했다.

```csharp
var fpp = playerCam.GetComponentInParent<FirstPersonPlayer>() ?? FirstPersonPlayer.Instance;
_rig  = fpp.transform;          // 옮길 것
_view = playerCam.transform;    // 방향을 읽을 것
float ViewYaw => _view.eulerAngles.y;
```

### 실측 (왕복 검증)

```
[빙의 전]  몸=(0.00,1.68,-6.00)   경비병 발밑=(6.09,0.00,-5.01)
[Enter]    몸=(6.09,1.60,-5.01)   기대와 일치        ✅
           Shell=(0.00,1.08,-6.00) 원래 자리          ✅
           Shell yaw=40 (시선 40)                     ✅
[빙의 중]  경비병 yaw=40 (시선 따라감)                 ✅
           부채꼴=꺼짐 / 감지=False                    ✅
[Exit]     몸=(0.00,1.08,-6.00) 셸 자리로 복귀        ✅
           카메라 로컬=(0,0,0) 어긋남 없음             ✅
```

> **교훈**: `[PlayerBody]`는 `FirstPersonPlayer`가 `rotation = identity`로 고정한다.
> **yaw는 항상 시선(카메라)에서 읽어야 한다.** `ViewmodelMotion`의 스웨이도 같은 이유로
> 영영 안 걸리고 있었다(앞 문서 §1).

## 2. 빙의 진입·해제 연출

**신규**: `View/Hacking/PossessionTransition.cs` · `Shaders/PossessionFrame.shader`

### 시퀀스

| | 진입 | 해제 |
|---|---|---|
| ① | FOV 확대 + 대상 쪽 짧은 돌리(가속) | FOV 축소 + **노이즈 급격히 폭증** |
| ② | **도중에 딱 암전**(완주하지 않는다) | 도중에 딱 암전 |
| ③ | 0.5초 검정 — **여기서 실제 전환** | 0.5초 검정 — 여기서 `Exit` |
| ④ | 암전 풀림 → 대상 시점 | 본체 시점. 노이즈 **강한 상태로 시작** |
| ⑤ | 흰 테두리가 화면 가장자리→안쪽 **스프링** | 노이즈 빠르게 소멸 + 테두리가 **화면 밖으로 스프링** |
| ⑥ | 노이즈 강 → 약(상시 미세 노이즈로) | — |

빙의 중에는 흰 테두리 + 아주 약한 가로선 노이즈가 **계속** 떠 있다.

### ★ 암전이 기능이다

실제 리그 순간이동을 **암전 중에** 실행하므로 순간이동이 화면에 안 보인다. 연출을 얹은 게 아니라
**연출이 순간이동을 가려 준다.** 그래서 `onSwap` 콜백의 호출 시점이 이 클래스의 핵심 계약이다.

```csharp
transition.BeginEnter(cam, targetPos, onSwap: () => {
    viewEntry.Enter(vet, cam);            // ← 암전 중
    SetPlayerFrozen(!vet.allowsMove);
});
```

`HackDriver`는 `Enter`/`Exit`를 **직접 부르지 않는다.** 연출 동안은 무조건 얼려 두고(안 얼리면
눈 감고 0.5초 걸어간다) 전환 후에 경비병만 풀어 준다.

### FOV·카메라 위치를 직접 쓰지 않는다

`MotionFeel`에 **오프셋 입구**를 냈다. 직접 `camera.fieldOfView`를 쓰면 `MotionFeel`이 매 프레임
덮어써서 **조용히 무효**가 된다(카메라 소유권 사고와 같은 종류).

```csharp
[System.NonSerialized] public float   ExternalFovOffset;   // 쓰는 쪽이 0으로 되돌릴 책임
[System.NonSerialized] public Vector3 ExternalPosOffset;
```

`ExternalPosOffset`은 `_appliedPos`에 **함께 담았다** — 되돌리기가 같은 값을 빼야 누적되지 않는다.
따로 더하면 카메라가 계속 밀려난다.

### 값 (전부 인스펙터)

```
suckTime 0.18   blackoutTime 0.5
frameInset 22px   frameThickness 6px
frameSpring: frequency 11, damping 0.55   ← damping<1이라 살짝 넘어갔다 정착(스프링)
noiseBurst 0.85 → noiseIdle 0.08   noiseSettleTime 0.5 / noiseRiseTime 0.18 / noiseFadeTime 0.3
zoomFovDelta +14
```

**`zoomFovDelta` 부호가 미확정이다.** "FOV 확대"를 *시야가 넓어짐 + 전진 돌리*(돌리 줌 = 현기증)로
읽었다. 반대로 느껴지면 **부호만 뒤집으면 되고 해제는 자동으로 반대**가 된다.

스프링은 **기존 `PdApproach`를 그대로 재사용**했다(새로 만든 것 없음).

## 3. 경비병 — 해킹당하면 영구 고장

**신규**: `View/Hacking/GuardBreakdown.cs`

`everHacked`가 true가 되면 되돌리지 않는다.

```
① 순찰 정지          ← 먼저. 새 회전(BeginTurn)이 시작될 길을 막는다
② 다리 IK 종료        ← GuardTurnStep.ShutDown()
③ 감지 소멸          ← GuardDetection.Active = false (판정 + 부채꼴을 동시에)
④ Idle_Crazy_Robot 무한 반복  ← 맨 마지막. 이제 뼈는 Animator가 온전히 소유
```

> **★ 터렛과 반대다.** 터렛은 총구만 돌린 것이라 **손을 떼면 다시 나를 쏜다.** 경비병은 거미가
> 몸속 기어를 헤집은 것이라 **한 번이면 끝**이다. → **경비병은 처리하면 끝, 터렛은 계속 붙잡고 관리.**

`Active` 하나가 판정과 표시를 **동시에** 끈다. 따로 끄면 언젠가 한쪽만 꺼져 *"안 보이는데 걸리는"*
사고가 난다.

**실측**: `Broken=True` / `Active=False` / 부채꼴 렌더러 꺼짐 / `Patrol.enabled=False` /
재생 클립 `Idle_Crazy_Robot` `isLooping=True` / `normalizedTime = 3.28`(3바퀴 넘게 = 무한 반복 확인).

### 발 들림 버그 — `HandIK.weight = 0`은 복원이 아니라 포기

해킹당한 경비병이 **한쪽 발을 든 채 굳었다.**

```csharp
// HandIK
if (weight <= 0f || ...) return;            // 안 쓸 뿐, 써 놓은 뼈 회전을 되돌리지 않는다
if (weight < 1f) { Slerp(원래자세, ...) }   // 복원은 0<weight<1 구간에서만
```

게다가 `GuardTurnStep`이 만드는 다리 IK는 **별도 `HandIK` 컴포넌트**(`[GuardLegIK_L/R]`)라
`GuardTurnStep`을 꺼도 **계속 살아 있다.** 회전 도중(발이 들린 순간) 해킹당하면 그대로 굳는다.

**고친 것** — `GuardTurnStep.ShutDown()` 신규: weight 0 + **컴포넌트·홀더 오브젝트까지 비활성화**해
되살아날 경로 자체를 없앤다. 그리고 `GuardBreakdown`을 `[DefaultExecutionOrder(100)]` + `LateUpdate`로
옮겼다 — `GuardTurnStep`이 `-10`으로 LateUpdate에서 IK를 굴리므로, `Update`에서 정리하면 **그 프레임에
이미 시작된 작업을 되돌리지 못한다.**

⚠️ **실측 미완.** `weight`가 1로 되돌아간 정확한 경로는 확정하지 못했다(MCP가 다른 세션에 점유돼
추가 측정 불가). 다만 이 수정은 경로를 특정하지 않고도 *"고장 이후에는 어떤 것도 다리를 붙들 수 없다"* 를
보장한다. **MCP가 풀리면 회전 도중 해킹 시나리오로 재현 확인할 것.**

### `Idle_Crazy_Robot`은 고장 표현으로 약하다

발 높이 변화가 **0.14~0.25m뿐**(정상 대기와 거의 같다). "고장났다"가 눈에 안 들어올 수 있다.
약하면 `anim.speed`를 낮추거나(느릿한 경련) 클립을 바꾸는 편이 낫다.

## 5. 터렛 사격 규칙 — 정정된 최종형

앞 문서 §3에 적힌 것에서 한 번 더 뒤집혔다. **이게 최종이다.**

| 상태 | 쏘는 대상 |
|---|---|
| 조종 중 **아님** | **플레이어만** (경비병은 아군) |
| **조종 중** | **경비병만** (플레이어 안 쏨) |

- 기준은 `everHacked`가 **아니라 `captureState == Captured`** 다.
  **한 번 해킹했다고 영구히 안 쏘지 않는다 — 손을 떼면 다시 나를 쏜다.**
- **빙의당한 경비병은 어느 모드에서도 안 쏜다.** 콜라이더로는 구분이 안 되고 실체는 "내 몸"이다.
- 감지 범위 표시(빨간 원기둥 → 지금은 흑백 노이즈 띠)는 **조종 중일 때만 꺼진다**(위협이 아닐 때만).
- 중간에 "무차별(해킹 전후 동일)"로 정했다가 되돌렸다. **위 표가 최종이다.**

`HackDriver.ForceReturnToBody(reason)` 신규 — 바깥 사정으로 빙의가 끊길 때의 **유일한 진입점**.
복귀는 `Exit` + 얼림 해제 + 컨텍스트 복귀 **세 개가 한 세트**라 하나만 부르면 플레이어가 얼어붙거나
ViewEntry 컨텍스트에 갇힌다. 현재 호출자는 없다(압사 구현 시 쓸 자리).

## 6. 이번 턴에 새로 겪은 함정

### 6-1. UI `Image` 재질에는 `_MainTex`가 반드시 필요

없으면 매 프레임 `Material '...' doesn't have a texture property '_MainTex'` 경고가 쏟아진다.
CanvasRenderer가 스프라이트 텍스처를 그 이름으로 밀어넣기 때문이다. **쓰지 않아도 선언만** 해 두면 된다.

### 6-2. `Busy`에 정착 상태를 포함하면 안 된다

`PossessionTransition.Busy = phase != Idle`이면 빙의하는 순간 `Held`에서 `Busy`가 **영구 true**가 되어
`BeginExit`가 계속 거부된다 → **영영 복귀 불가.** 실측에서 `BeginExit` 호출이 무시되는 걸로 드러났다.

### 6-3. 연출은 dt에 상한을 걸어야 한다

한 프레임이 통째로 길어지면(컴파일·로딩) 그 한 프레임에 흡입 0.18초와 암전 0.5초가 동시에 소비돼
**암전이 안 보이고 순간이동이 노출된다.** 실측 중 실제로 한 프레임에 두 단계를 건너뛰는 것을 봤다.
→ `Mathf.Min(Time.unscaledDeltaTime, 0.05f)`

### 6-4. Unity 애셋 DB가 특정 파일만 컴파일에서 빼먹을 수 있다

`ViewEntry/PossessionTransition.cs`가 임포트는 되는데(`MonoScript` 로드 OK, `GetAssemblyNameFromScriptPath`도
`Game.View.dll`) **컴파일 대상에 안 들어갔다.** `CS0246`만 반복되고 그 파일 자체의 에러는 없었다.

시도해서 **실패**한 것: `ImportAsset(ForceUpdate)` · `AssetDatabase.Refresh(ForceSynchronousImport)` ·
`.meta` 삭제 후 재발급 · `CompilationPipeline.RequestScriptCompilation()`.

**해결**: 파일을 다른 폴더로 옮겼다(`ViewEntry/` → `View/Hacking/`). 즉시 해결.
원인 미확정 — 다른 세션의 동시 점유와 관련 가능. **같은 증상이면 위치 이동을 먼저 시도할 것.**

### 6-5. 에디터가 백그라운드면 Play가 거의 안 틱한다

`Application.runInBackground = true`를 **매 측정 앞에** 넣어야 프레임이 돈다. 이걸 모르면
"코드가 안 도는 것"으로 오진한다 — 이번 세션에 두 번 오진했다. `frameCount`가 안 늘어나면 이것이다.

   - §6.3의 빙의 테두리: **파란 실 → 흰 선 + 검은 가로 노이즈**(파란 실은 구버전).
     조종 실(손↔대상)의 파랑은 **그대로 유지** — 빙의와 조종을 색이 아니라 **형태**로 구분한다.
   - §6.3에 **해킹당한 경비병 영구 무력화** 추가.
   - §7 색 언어: "위험 = 빨강" → 흑백 노이즈. ⚠️ 흑백 맵에 흑백 노이즈라 **배경에 묻힐 위험**이
     실재한다 — 실기에서 안 읽히면 테두리만 살리는 보정이 필요하다.
6. **미구현 (설계는 있으나 코드 없음)**
   - **경비병의 공격 수단이 없다.** 발각해도 아무 일이 안 일어난다 — `GuardDetection.OnDetected`
     이벤트와 로그만 낸다. §6.4의 "발각 → 방 리셋"은 **리셋 시스템 자체가 없어** 배선 못 했다.
     리셋이 생기면 그 이벤트 한 곳만 구독하면 된다.
   - **압사(CrushZone)** — 사용자가 명시적으로 뒤로 미뤘다. `ForceReturnToBody`가 그 자리에 미리 있다.
7. **VR 미완**
   - **`PossessionTransition`은 PC 전용이다.** 암전·테두리가 ScreenSpace-Overlay Canvas라
     **VR 양안에서 렌더되지 않는다.** `VrHudSpace`(월드 패널) 경로로 옮겨야 한다.
     FOV·돌리는 이미 `VrMode.Enabled` 게이트로 건너뛴다.
   - `ViewEntryController.Exit`에 `Camera.main`을 넘기는 경로 — 고정 시점 빙의 중엔 플레이어 카메라를
     끄므로 **`Camera.main`이 null**이 된다. 고정 시점 대상이 CCTV뿐이고 보류라 지금은 실행되지
     않는다. **로봇팔(3인칭)을 만들 때 되살아난다.**
